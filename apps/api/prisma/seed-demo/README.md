# Демо-данные для локальной базы

Одна команда (из корня репозитория):

```bash
npm run seed:demo --workspace apps/api
```

Нужны `DATABASE_URL` и (для картинок) `S3_ENDPOINT`, `S3_BUCKET_MEDIA`,
`S3_BUCKET_DOCUMENTS`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` — те же,
что у API; скрипт читает `apps/api/.env`. Бакеты в MinIO создаются сами.
Без `S3_*` всё, кроме картинок и документов, всё равно создаётся.
Перед запуском в базе должны быть справочники (переводы, штаты, практики,
планы) — на Mac они уже есть. Скрипт отказывается работать, если
`DATABASE_URL` похож на боевой.

Повторный запуск ничего не дублирует (id строк выводятся из ключей,
запись с `skipDuplicates`). Видео-карточки (рилсы) по умолчанию не создаются:
без библиотеки Bunny они не проигрываются. Чтобы добавить заглушки:
`DEMO_SEED_VIDEO_STUBS=1 npm run seed:demo --workspace apps/api`.

## Что получается

1. **Мир** (`src/modules/demo/demo-seed.ts`, тот же код, что у демо-режима):
   14 адвокатов (лицензии, штаты, практики, языки, цены, отзывы, подписки),
   12 клиентов, помощник адвоката, кейсы во всех стадиях, ставки и
   предложения, чаты с сообщениями, подписки, задачи, уведомления.
2. **Контент** (`seed-demo/content.ts`, тексты в `texts.ts`):
   - 21 пост: карточка LawBid (с практикой), Instagram (фото и карусели
     до 9 фото), Threads (только текст), новости, посты с PDF; заголовок
     ровно 120 и текст ровно 2200 символов для проверки обрезки; RU и EN;
     один пост с выключенными комментариями; места.
   - Комментарии и ответы автора, лайки комментариев, лайки, сохранения,
     репосты у ВСЕХ постов (в том числе у старых); счётчики пересчитаны.
   - Аватары всем, у кого их нет; фото в 4 отзывах и в 6 кейсах.
   - 4 активных продвижения (2 поста, 2 открытых кейса).
   - Уведомления «лайк / комментарий / ответ».

Картинки генерируются в коде (градиенты, ~70 КБ), PDF тоже, ничего не
скачивается. Файлы кладутся в `demo/...` в тех же бакетах, с вариантами
`_w320` и `_w1080`, как у настоящих загрузок.
