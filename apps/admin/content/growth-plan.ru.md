# План роста

Это инструкция для владельца: **что включать, когда людей становится больше**. Всё написано по документам проекта (`docs/perf/GROWTH_LADDER_2026-10-23.md`, `LOAD_SPEED_AUDIT_6`, `SCALE_LIMITS_AUDIT`, `docs/runbooks/*`, `infra/`). Если в документах чего-то нет, здесь так и сказано: «в документах не указано».

Главное правило: **пока нет сигнала, ничего не включаем.** Лишние деньги, потраченные заранее, — тоже ущерб. Все переключатели ниже выключены и ничего не стоят, пока вы их не включите.

> «DAU» значит «сколько разных людей заходят за один день». Цены — примерные добавки к счёту AWS в месяц (список цен США, ±30 %). Это оценка из документов, не счёт.

## Как пользоваться этой страницей

У каждого пункта один и тот же порядок:

- **Что это** — простыми словами.
- **Когда включать** — какой сигнал или какая цифра говорит, что пора.
- **Где включать** — точное место: строка в файле настроек, ключ в админке или раздел консоли AWS.
- **Что зарегистрировать / куда вставить** — если нужен сторонний сервис, ключ или файл.
- **Цена в месяц.**
- **Как проверить** и **как откатить.**
- **Статус** — одно из двух: «код готов, только включить» или «код ещё не написан — попросить разработчика, ориентировочно N дней».

### Где смотреть сигналы

1. Админка → **Система → Здоровье системы** (`/system-health`). Там лампочки: серверы, база, Redis, очереди, бэкапы, расходы.
2. Письма-тревоги на адрес из `alert_emails`. Имя тревоги начинается с `lawbid-prod-`, например `lawbid-prod-db-cpu`.
3. Консоль AWS → **CloudWatch → Alarms** (список всех тревог и их история) и **CloudWatch → Metrics → LawBid/Runtime** (задержка серверов, память).
4. Админка → **Система → Экономика** (`/economy`): доход и расходы на сторонние сервисы. Размер серверов, базы и Redis — **Система → Масштаб** (`/scale`), там же кнопки «Увеличить».

### Как менять файл настроек (tfvars)

Почти все переключатели роста — это строки в файле `terraform.tfvars` в папке `infra/envs/prod` на вашем Mac. Образец: `infra/envs/prod/launch.tfvars.example`. Порядок всегда один (из `docs/runbooks/DEPLOY_PROD.md`, «Повторные terraform apply»):

1. Открыть Terminal. `cd ~/Desktop/LawBid/infra/envs/prod`
2. Войти в AWS и подготовить Terraform: `eval "$(aws configure export-credentials --format env)" && terraform init -backend-config=backend.hcl`
3. Подставить текущие версии образов: `../../../scripts/deploy/current-tag.sh`
4. Добавить или изменить строку в `terraform.tfvars` (примеры ниже).
5. **Только посмотреть, что изменится:** `terraform plan -out=plan.bin`, затем `../../../scripts/deploy/plan-guard.sh plan.bin`. Эта проверка падает, если Terraform хочет удалить базу, секреты, ключи шифрования, Redis или хранилища. В плане должно быть **0 to destroy**.
6. Если всё ожидаемо: `terraform apply plan.bin`.
7. Если что-то непонятно — не применять, написать разработчику.

Все переключатели роста собраны в одной строке `growth = { ... }`. Пустая строка (или её отсутствие) = всё как сейчас, ничего не меняется и ничего не стоит. Можно включать по одному ключу:

```
growth = { rds_read_replicas = 1 }
```

Откат почти везде одинаковый: вернуть значение, `plan`, `apply`.

Второе место для настроек без разработчика — админка → **Система → Настройки** (`/config`, ключи вида `security.…`, `client.…`). Они вступают в силу сразу, обновлять приложение не нужно (кроме отдельно отмеченных).

## Сейчас (запуск)

Размер запуска по `launch.tfvars.example`: примерно **$150–170 в месяц** за AWS. Один API-сервер и один фоновый (`min_tasks = 1`), дальше сами добавляются по нагрузке. Из документов: «Включение серверов по нагрузке (процессор 60 %, запросы на сервер, очередь фоновых задач)» уже работает без вас.

Что уже защищает вас без действий: перезапуск упавшего, рост и сжатие числа серверов, защита от «толпы» на одном ключе кэша, одна запись в 10 секунд вместо записи на каждый просмотр профиля, замер задержки сервера с тревогой, ежемесячный бюджет AWS с письмами.

### Проверить один раз перед запуском

Каждый пункт — из `docs/runbooks/OWNER_TODO_2026-10-22.md` и других инструкций. Это не рост, но без них рост будет дорого стоить.

1. **Лимит серверов AWS.** Консоль AWS → **Service Quotas → AWS services → AWS Fargate → Fargate On-Demand vCPU quota → Request increase.** У нового аккаунта лимит 6 vCPU, а потолок в `launch.tfvars.example` — 35 vCPU (50 API × 0,5 + 20 фоновых × 0,5). Без увеличения серверы не добавятся в час наплыва людей. Подробности: `docs/runbooks/ecs-capacity.md`.
2. **Бюджет.** Строка `monthly_budget_usd = 350` в `terraform.tfvars`. Письма придут при 50 %, 80 % и 100 %. При 100 % система сама держит сервер на минимуме, то есть слишком низкий бюджет сам тормозит рост. Выключатель: админка → Здоровье системы → «Минимум сервера, когда бюджет AWS исчерпан». Инструкция: `docs/runbooks/cost.md`.
3. **База: Multi-AZ и бэкапы.** Консоль AWS → **RDS → Databases → lawbid-prod-postgres → Modify → Multi-AZ**. Terraform на живой базе это не переключает. Цена: примерно ×2 к цене базы. Шаги и проверка: `docs/runbooks/DEPLOY_PROD.md`, «Надёжность».
4. **Проверка восстановления из бэкапа** раз в квартал: `scripts/ops/restore-drill.sh`, инструкция `docs/runbooks/restore-drill.md`.
5. **Stripe.** Dashboard → Developers → Webhooks → наш endpoint → «Add events»: `customer.subscription.pending_update_applied`, `customer.subscription.pending_update_expired`, `payment_intent.succeeded`. Без них докупка мест и оплата на нашей странице не подтверждаются.
6. **Налог с продаж.** Пока вы продаёте в одном штате — можно не включать. Как только появится обязанность (порог продаж в другом штате, покупатели из ЕС): Stripe Dashboard → Settings → Tax → Get started, затем админка → Настройки → `billing.stripe_tax_enabled` → Вкл. Все шаги: `docs/runbooks/STRIPE_TAX.md`.
7. **Защита от «ботов, которые просят SMS на дорогие номера» (App Check).** Сервер сейчас в режиме `monitor` (только записывает). Порядок из `docs/runbooks/APP_CHECK.md`: зарегистрировать приложения в Firebase Console → App Check, выпустить приложение, через неделю посмотреть журнал, затем админка → Настройки → `security.app_check.mode` = `enforce`. Откат — вернуть `monitor`, обновление приложения не нужно.
8. **Ссылка на App Store.** После регистрации приложения в App Store Connect скопировать числовой Apple ID и вставить ссылку в админке → Настройки → `store_url_ios` (и `store_url_android`). Только `https`. Без неё экран «обновите приложение» на iPhone не ведёт в магазин.
9. **Журнал канарейки.** Консоль AWS → **CloudWatch → Log groups →** группа, начинающаяся с `/aws/lambda/cwsyn-` → Actions → Edit retention → 30 дней (у неё случайное имя, Terraform это не умеет). Источник: `docs/perf/SCALE_LIMITS_AUDIT_2026-10-23.md`, пункт 13.
10. **Если среда (окружение) уже была создана раньше этих правок:** две группы журналов RDS нужно один раз «импортировать» в Terraform (команда `terraform import` в `SCALE_LIMITS_AUDIT`, пункт 9). Если в плане нет ошибок про `aws_cloudwatch_log_group.rds` — делать ничего не нужно.

### Звонки через TURN: что сейчас и что приходит на почту

> **С 2026-10-24 свои серверы TURN удалены.** Звонки 1 на 1 идут через Cloudflare TURN, групповые через Cloudflare SFU. Тревоги `…-turn-primary-*` больше не приходят; вместо них `lawbid-prod-turn-provider-failed` (Cloudflare не выдаёт доступ) и звонковая SLO-тревога: смотреть админка → Состояние системы → Cloudflare TURN / SFU, `docs/runbooks/TURN.md`. Текст ниже описывает старую схему со своими серверами (на случай возврата).

- **Что это.** Большинство звонков идут напрямую между телефонами. Через наш сервер TURN идут только те, что напрямую не соединились (строгий NAT, мобильные операторы, офисный Wi-Fi). Серверов два, в разных зонах.
- **Сейчас.** Каждый сервер `t4g.small`, лимит ≈ 500 «выделений» на сервер (это ≈ 250 звонков через TURN одновременно на сервер, ≈ 500 на оба). Лимит считается из размера сервера: маленький сервер имеет малый постоянный сетевой предел, и видео через него задохнулось бы раньше лимита.
- **Тревоги по звонкам** приходят на тот же адрес из `alert_emails`, что и остальные. Имена: `lawbid-prod-turn-primary-network` и `…-second-network` (трафик выше 70 % предела 10 минут), `…-cpu` (процессор выше 70 %), `…-cpu-credits` (кончается запас процессора), `…-allocations` (занято больше 70 % мест), а также старые `…-health`, `…-system-status`, `…-instance-status`, `…-turn-traffic`.
- **Что делать, когда письмо пришло.** Один раз в час пик, потом «OK» — ничего. Письмо повторяется несколько дней или приходит вместе с ростом числа звонков — подняться на ступень выше (лестница ниже): строка `turn_instance_type` в `terraform.tfvars`, затем `apply` **по шагам: сначала второй сервер, потом первый** (`docs/runbooks/TURN.md`, «Смена размера»), иначе оба перезапустятся одновременно и звонки через TURN на пару минут пропадут. Если звонков не больше, а трафик растёт — смотрите `docs/runbooks/TURN.md`, «Трафик» (возможно злоупотребление).

Не включайте `ARM64` «на глаз»: сначала должен быть собран образ под `arm64`, иначе серверы не запустятся.

## Когда людей около 100 тысяч (DAU)

**Один-два API-сервера, одна база, один Redis — это запас до 10 тысяч DAU.** До этого момента ничего не трогаем, только следим, что тревога про задержку сервера молчит.

### Сигналы, что пора (любой один)

1. Тревога `lawbid-prod-db-cpu`: «процессор базы выше 85 % больше 15 минут». Приходит письмом.
2. Тревога `lawbid-prod-api-event-loop-lag` (и `…-worker-event-loop-lag`): «сервер отвечает с опозданием: задержка выше 250 мс 10 минут подряд».
3. Тревоги `lawbid-prod-api-p95` или `lawbid-prod-db-slow` повторяются каждый день в часы пик.

### 1. База на ступень выше

- **Что это.** Тот же сервер базы, но мощнее. Данные не пропадают.
- **Когда.** Сработал сигнал 1 или 3.
- **Где.** Админка → **Система → Масштаб** (`/scale`) → раздел «База данных и Redis» → кнопка **«Увеличить до …»** возле базы → подтвердить. Это работает без разработчика. Кнопка «Больше некуда» — значит, самый большой доступный размер уже стоит.
- **Регистрироваться / вставлять:** ничего.
- **Цена.** ≈ +$50–100 в месяц за ступень.
- **Проверить.** Через 15–30 минут в Здоровье системы лампочка базы зелёная, а тревога `db-cpu` не приходит повторно сутки.
- **Откат.** В документах кнопки «Уменьшить» нет. Размер можно вернуть в консоли AWS → RDS → Modify; перед этим лучше написать разработчику.
- **Статус.** Код готов, только включить.

### Звонки через TURN: сервер сети побольше

- **Что это.** Те же два сервера TURN, но на машинах с настоящей «сетевой» мощностью без кредитов процессора.
- **Когда.** Любая тревога `lawbid-prod-turn-…-network`, `…-cpu`, `…-cpu-credits` или `…-allocations` приходит регулярно в часы пик (при ≈ 100 тыс. DAU это обычно так).
- **Где.** `terraform.tfvars`: `turn_instance_type = "c6gn.large"` (или `c7gn.large`); лимит `turn_total_quota` сам станет ≈ 2000 на сервер (≈ 1000 звонков через TURN на сервер). Промежуточная ступень: `t4g.medium` (1000) и `t4g.large` (2000) дешевле, но с кредитами процессора. `plan`, затем `apply` **по шагам**: сначала второй сервер (`-target` в `docs/runbooks/TURN.md`, «Смена размера»), через 5 минут весь `apply`.
- **Регистрироваться / вставлять:** ничего.
- **Цена.** ≈ +$35–40 за сервер в месяц против `t4g.small` (≈ $12 → ≈ $45–52; цены приблизительные).
- **Проверить.** Через 10 минут нет писем `…-health`; звонок по мобильной сети идёт; в CloudWatch → метрика `LawBid/TURN → Allocations` у новых серверов появилась.
- **Откат.** Вернуть прежнее значение `turn_instance_type`, `apply` по шагам.
- **Статус.** Код готов, только включить.

### 2. Больше API-серверов и потолок расходов

- **Что это.** Число серверов растёт само. Вы задаёте потолок, выше которого оно не пойдёт.
- **Когда.** Тревога `lawbid-prod-api-cpu` не гаснет, а число серверов стоит на максимуме больше часа.
- **Где.** Реальный потолок считается автоматически от дохода (админка → Экономика, правило «расходы не больше `economy.max_spend_percent` % дохода за 30 дней, но не меньше `economy.min_threshold_usd` долларов»). Ручной режим: Настройки → `economy.ceiling_mode` = `manual`, числа `economy.manual_api_max` и `economy.manual_worker_max`. Жёсткий потолок — строки `api_max_tasks` и `worker_max_tasks` в `terraform.tfvars` (в `launch.tfvars.example` сейчас 50 и 20).
- **Цена.** Один API-сервер на запуске (0,5 vCPU) ≈ $14 в месяц; сервер с 1 vCPU ≈ $36 (`cost-plan-2026-10-20.md` и `GROWTH_LADDER`, цифры расходятся, см. в конце страницы). На Spot добавочные серверы дешевле примерно на 60 %.
- **Проверить.** Здоровье системы → число серверов API выросло, тревога `api-cpu` погасла.
- **Откат.** Вернуть число в `terraform.tfvars` или в Настройках.
- **Статус.** Код готов, только включить. Не забудьте квоту Fargate (см. «Сейчас», пункт 1).

### 3. Отдельный Redis только для кэша

- **Что это.** Сейчас один Redis держит всё: очереди, сокеты, кэш. Когда память почти заполнена, он отказывает **во всех** записях сразу. Идея: кэш уезжает в отдельный дешёвый Redis, где старое выбрасывается само.
- **Когда.** Тревога `lawbid-prod-redis-memory` (память выше 80 %) или память главного Redis держится выше ~60 %.
- **Где (инфраструктура).** `terraform.tfvars`: `redis_cache_node = true` (по желанию `redis_cache_node_type = "cache.t4g.micro"`), затем `plan` → `apply`. Terraform создаст узел и секрет `lawbid-prod-cache/REDIS_URL` и передаст его серверам как `REDIS_CACHE_URL`.
- **Цена.** ≈ +$12 в месяц.
- **Статус: код ещё не написан — попросить разработчика, срок в документах не указан (попросить оценить).** В `docs/runbooks/redis.md` прямо сказано: «App change (not done yet)». По коду приложения (проверено поиском): переменную `REDIS_CACHE_URL` он нигде не читает. Если включить только строку в tfvars, вы заплатите $12, а пользы не будет. **Сначала разработчик, потом строка.** (В `GROWTH_LADDER` этот шаг описан как «включить в tfvars»; это не учитывает, что приложение ещё не подключено.)
- **Проверить после кода.** В CloudWatch → Metrics → ElastiCache оба узла показывают память; на главном она перестала расти.
- **Откат.** `redis_cache_node = false`.

### 4. Регуляторы в админке (бесплатно)

Все — админка → **Система → Настройки**, действуют сразу:

- `security.anonymous_rate_limit_per_minute` (по умолчанию 100; не меньше 100). Поднимите, если много людей приходят с одного адреса мобильного оператора или офиса и им отвечает «слишком часто».
- `realtime.max_sockets_per_user` (по умолчанию 10 на сервер).
- `client.*` (повторы запросов, задержка переподключения, как часто телефон шлёт события, сколько видео подгружать наперёд `client.video_prefetch_ahead` 0–6 и др.). **Работают только в сборках приложения, где этот код есть** (первая сборка для магазинов должна его включать). Они нужны, чтобы разгрузить сервер после аварии, когда телефоны подключаются все сразу.
- `storage.retention_post_view_events_days` (730 по умолчанию), `storage.retention_user_activity_days` (400), `storage.retention_app_events_days` (90): сколько дней хранить большие журналы. 0 = хранить всегда.

## Когда людей около 1 миллиона (DAU; пик ≈ 400 запросов в секунду)

### Сигналы (любой один)

1. Тревога `lawbid-prod-db-connections`: «соединений с базой больше 80 % от допустимых».
2. `api-p95` (ответы медленнее нормы), хотя серверов достаточно и `api-cpu` молчит.
3. `db-cpu` приходит снова, хотя базу уже увеличили.

### 5. Копия базы для чтения (реплика) и «диспетчер соединений» (RDS Proxy)

- **Что это.** Реплика — вторая база, которая только читает. Поиск и публичные профили перестают толкаться с записью на главной. RDS Proxy — «диспетчер»: тысячи соединений от серверов делят несколько сотен настоящих соединений с базой; при аварии базы приложение переподключается за секунды.
- **Когда.** Сработал сигнал 1 (реплика — для сигналов 2–3).
- **Где.**
  1. `terraform.tfvars`: `growth = { rds_read_replicas = 1, db_proxy_enabled = true, db_proxy_secret_arn = "<адрес секрета с логином приложения>" }`. Адрес секрета (ARN): консоль AWS → **Secrets Manager** → секрет с логином и паролем роли приложения (`{username, password}`) → скопировать «Secret ARN». Если такого секрета нет, попросить разработчика. Без прокси — только `growth = { rds_read_replicas = 1 }`.
  2. `terraform plan`, `plan-guard`, `terraform apply`. Реплика создаётся ещё ≈ 30 минут сама.
  3. Адрес реплики: `terraform output growth_replica_endpoints` (прокси: `growth_db_proxy_endpoint`).
  4. Консоль AWS → **Secrets Manager → Store a new secret → Other type of secret → Plaintext**. Имя `DATABASE_REPLICA_URL`, значение — та же строка подключения, что у `DATABASE_URL`, но с адресом реплики. Строку не вставляйте в чаты и письма.
  5. В `terraform.tfvars` добавить имя в `extra_secrets = ["DATABASE_REPLICA_URL"]` (только **после** того, как значение создано, иначе серверы не запустятся). `apply`, затем выкатить заново через GitHub → Actions → Deploy. Новые серверы подхватят секрет. Поиск начнёт читать с реплики сам, **без новой версии кода**.
- **Регистрироваться:** ничего, это всё внутри AWS.
- **Цена.** Реплика ≈ +$200 (того же размера, что главная база; если главная в Multi-AZ, реплика такая же по размеру). RDS Proxy ≈ +$25 (2 процессора) … +$90.
- **Проверить.** Консоль AWS → RDS → у реплики статус `Available`; CloudWatch → метрика `ReplicaLag` небольшая; через сутки нагрузка (CPU) главной базы ниже. В журнале приложения нет сообщений о падении на главную базу.
- **Откат.** Убрать `DATABASE_REPLICA_URL` из `extra_secrets` (или `DB_REPLICA_ENABLED=false`) и выкатить; затем `rds_read_replicas = 0`, `plan`, `apply`. Если реплика недоступна больше 15 секунд, приложение само читает с главной базы.
- **Осторожно.** Proxy у Prisma частично «прикалывает» соединения, поэтому выигрыш в числе соединений есть, но не безграничный. Включать прокси только когда сработал сигнал 1.
- **Статус.** Код готов, только включить.

### Звонки через TURN: Cloudflare вместо своих серверов (сделано 2026-10-24)

- **Что это.** Вместо своих серверов TURN звонки 1 на 1 идут через управляемый Cloudflare Realtime TURN: платится только за трафик (первые 1000 ГБ в месяц бесплатно, дальше $0.05 за ГБ, цена на странице Cloudflare может меняться), масштабируется сам, серверов на AWS нет.
- **Где.** Админка → Интеграции → `cloudflare_turn` (keyId и apiToken из Cloudflare Dashboard → Realtime → TURN). Ключи вставлять только в админку, не в чаты. Кнопка «Видеозвонок» появляется, как только ключи есть.
- **Если Cloudflare не ответил.** Сервер пробует ещё раз через 0,3 секунды; не вышло, звонок идёт на STUN (может не соединиться за сложной сетью) и ставится счётчик, 5 сбоев за 5 минут шлют письмо `lawbid-prod-turn-provider-failed`.
- **Групповые звонки** (3+ человека): Cloudflare SFU (`calls.video_provider = cloudflare`, ключи `cloudflare_sfu`).
- **Проверить.** Админка → Состояние системы → строки «Звонки: Cloudflare TURN» и «Групповые звонки: Cloudflare SFU» зелёные; звонок по мобильной сети идёт; у Cloudflare на панели виден трафик.
- **Откат.** Вернуть свой сервер: `turn_enabled = true`, `docs/runbooks/TURN.md`, «Bringing our own coturn back».
- **Статус.** Готово: код, проверки, тревоги.

### 6. Видеозвонки: сервер побольше

- **Что это.** Свой сервер групповых звонков (3+ человека), создаётся, только если вы включили `livekit_enabled = true`. Сейчас он один (EC2 `c7g.medium`).
- **Когда включать вообще.** Когда приложение со сборкой звонков вышло. Строка `livekit_enabled = true` в `terraform.tfvars`, `apply`, затем **две** A-записи в Namecheap → Advanced DNS: хосты `livekit` и `livekit-turn` на адрес `livekit_public_ip` (команда `terraform output -json stack | jq .livekit_public_ip`). Через 2–5 минут сертификат выпускается сам. Подробно: `docs/runbooks/LIVEKIT.md`.
- **Когда расти.** Тревога `lawbid-prod-livekit-cpu` (процессор выше 70 % полчаса) приходит регулярно. Тревога `…-livekit-egress` (за сутки ушло больше 50 ГБ) значит большой счёт за трафик.
- **Где (вертикально).** `terraform.tfvars`: `livekit_instance_type = "c7g.large"` (≈ $52 вместо $26) или `c7g.xlarge`; `apply` пересоздаёт сервер, ~1 минута без звонков. Адрес сохраняется.
- **Цена.** Включение: ≈ +$32 в месяц без трафика. Трафик $0,09 за ГБ (первые 100 ГБ в месяц на весь аккаунт бесплатно). Пример из документа: группа из 4 человек на час ≈ 8 ГБ ≈ $0,75; 100 таких часов ≈ $75.
- **Проверить.** `curl -I https://livekit.<ваш-домен>` отвечает (любой код, но без ошибки TLS); групповой звонок из приложения идёт.
- **Откат.** `livekit_instance_type` назад или `livekit_enabled = false`.
- **Статус.** Один сервер: код готов, только включить. **Несколько серверов: код ещё не написан — попросить разработчика, ориентировочно полдня** (`LIVEKIT.md`, «Как расти»: второй сервер в другой зоне, по адресу на сервер, DNS или балансировщик). Сейчас `growth.livekit_nodes > 1` Terraform сам отклоняет. По лестнице роста это нужно при ≈ 100 млн, но если тревога CPU приходит регулярно — раньше.

## Когда людей около 10 миллионов (DAU; пик ≈ 4 000 запросов в секунду)

Весь этот этап по документам ≈ **+$1 000–2 500 в месяц** (без экономии на Bunny).

### Сигналы

1. `api-cpu` не гаснет, число серверов API стоит на максимуме (`api_max_tasks`) больше часа.
2. `redis-cpu` или `redis-memory` (память выше 80 %).
3. `db-slow`: самый тяжёлый запрос базы дольше 100 мс (обычно это поиск).
4. `db-cpu` не помогает даже после реплик: база упирается в чтение лент (≈ 23 запроса на одну ленту).

### 8. Больше серверов, Redis побольше, больше реплик

- **Серверы.** `api_max_tasks` с 20 до 60 (или больше) в `terraform.tfvars`; квота Fargate выше (см. «Сейчас», пункт 1). Один сервер ≈ $36. ≈ 5 минут. Код готов, только включить.
- **Redis побольше.** Админка → Масштаб → «Увеличить» у Redis, либо `redis_node_type = "cache.r7g.xlarge"` в tfvars. ≈ +$150–300. Применять в окне обслуживания (`apply_immediately = false`). Код готов, только включить.
- **Ещё реплики.** `growth = { rds_read_replicas = 2 }` (или 3, максимум 5). ≈ +$200 за каждую. Код готов, только включить. Проверить и откатить — как в пункте 5.

### 9. Поисковый движок OpenSearch

- **Что это.** Отдельная система для поиска (сейчас поиск идёт внутри базы и стоит около 38 мс процессора базы на каждый новый запрос).
- **Когда.** Сигнал `db-slow` из-за поиска.
- **Где.** `growth = { opensearch_enabled = true, opensearch_instance_type = "m6g.large.search", opensearch_instance_count = 3 }`. Адрес: `terraform output growth_opensearch_endpoint`.
- **Цена.** ≈ +$280 в месяц (по `GROWTH_LADDER`).
- **Статус.**
  - Сам движок создаётся Terraform: **код готов, только включить.**
  - **Подключение приложения (провайдер поиска OpenSearch) — код ещё не написан — попросить разработчика, ориентировочно 1–2 недели.** Место подключения (`SEARCH_PROVIDER`) в коде есть, но есть только провайдер на базе данных. Включайте движок **после** того, как разработчик закончит провайдер, иначе будете платить за пустой сервер.
- **Откат.** `opensearch_enabled = false` (после переключения приложения назад на поиск в базе).

### 10. Картинки через Bunny вместо CloudFront

- **Что это.** Сторонняя сеть доставки картинок. По документам: CloudFront ≈ $0,085/ГБ, Bunny ≈ $0,005–0,01/ГБ, то есть в 8–17 раз дешевле. Экономия при 10 млн DAU «несколько тысяч долларов в месяц» (считается по реальному трафику).
- **Где зарегистрироваться.** bunny.net → зарегистрироваться → **CDN → Add Pull Zone**. Адрес источника (origin), который нужно указать в Pull Zone, в документах **не описан**: уточните у разработчика, прежде чем создавать зону.
- **Где включить.** `growth = { cdn_images_provider = "bunny", cdn_images_base_url = "https://<ваша-зона>" }` (без слэша в конце). Затем `plan`, `apply`, выкатка заново (адрес картинок — переменная окружения `MEDIA_CDN_BASE_URL`).
- **Ключи.** Отдельный Bunny Read-Only API key для подписи ссылок на видео вставляется в админке → **Безопасность → Ключи и сервисы → Bunny** (это другой ключ, не для картинок).
- **Цена.** Платите Bunny по трафику; точной цифры за месяц в документах нет (считать в калькуляторе на bunny.net).
- **Проверить.** Откройте любую картинку профиля в приложении или сайте, адрес должен начинаться с вашей зоны.
- **Откат.** `cdn_images_provider = "cloudfront"`, `apply`, выкатка.
- **Статус.** Код готов, только включить. ≈ 30 минут.

## Что не удалось проверить по документам
