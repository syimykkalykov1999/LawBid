## Что это и зачем

TURN помогает дозвониться, когда телефоны не видят друг друга напрямую (мобильная сеть, офисный Wi-Fi). Без него часть звонков не соединится.

Cloudflare — **главный** путь для всех звонков: как только ключи сохранены, звонки 1 на 1 идут через Cloudflare TURN, а групповые — через Cloudflare SFU (если сохранены и его ключи, см. инструкцию «Cloudflare: групповые видеозвонки (SFU)»). Ничего больше включать не нужно. Наш собственный путь (свой TURN-сервер и прямое соединение телефонов) — только **запасной**: он включается сам, если Cloudflare начал сбоить, и выключается сам, когда Cloudflare снова работает.

## Что понадобится

- Аккаунт Cloudflare с двухфакторной защитой (см. инструкцию «Cloudflare: аккаунт и защита входа»).
- Доступ к админке с правом владельца.

## Шаги

1. Откройте [dash.cloudflare.com](https://dash.cloudflare.com) и войдите.
2. В левом меню нажмите **Realtime**.
3. В блоке **TURN Server** нажмите **Create**.
4. В поле имени впишите `lawbid-calls` и снова нажмите **Create**.
5. Cloudflare покажет **Key ID** (в документации он назван «TURN Token ID») и **API Token**. Токен виден только один раз.
6. Скопируйте оба значения в менеджер паролей, пока страница открыта.
7. Необязательно, для учёта трафика: найдите **Account ID** (см. инструкцию «Cloudflare: аккаунт и защита входа»).

> Название пункта меню в панели Cloudflare иногда меняется (**Realtime** → **TURN Server** или **TURN Keys**). Если не нашли, нажмите **Search** и впишите TURN. (Не удалось проверить: точные подписи кнопок в панели; документация даёт только ссылку на раздел, подписи взяты из примера Cloudflare и из сообщений пользователей.)

## Куда вставить в нашей админке

1. «Ключи и сервисы» → карточка **Cloudflare TURN (in-app calls)**.
2. Поле «TURN key ID» → вставьте Key ID.
3. Поле «TURN key API token» → вставьте API Token.
4. Нажмите «Добавить ключи» → «Сохранить» (потребуется код 2FA) → «Проверить» → «Включить».

## Переключатель «через кого идут звонки» (calls.transport)

«Ключи и сервисы» → карточка **«Связь для звонков»** (в ней же, в свёрнутых разделах, ключи Cloudflare TURN, Cloudflare SFU, своего TURN и LiveKit). Переключатель из трёх положений (это настройка `calls.transport`):

- **Авто** (`auto`, стоит по умолчанию, рекомендуем) — звонки идут через Cloudflare. Если Cloudflare за 2 минуты 5 раз не ответил, **новые** звонки сами переходят на свою связь. Раз в минуту система проверяет Cloudflare и, как только он ответил, новые звонки сами возвращаются на него. Если Cloudflare сломался **посреди** разговора, разговор не обрывается: групповой звонок сам переходит на свою связь (пауза 1–2 секунды), а звонок 1 на 1 сам берёт свой TURN-сервер. Надпись «Переподключение…» появляется, только если пауза дольше 3 секунд.
- **Вкл** (`cloudflare`) — только Cloudflare, даже если он сбоит. Нужно редко, например чтобы проверить сам Cloudflare. Без ключей Cloudflare это положение не сохранится.
- **Выкл** (`own`) — Cloudflare не используется, все звонки идут через свою связь. Например, если счёт Cloudflare неожиданно вырос. Сами звонки этим не выключаются (отдельного выключателя всех звонков нет).

В карточке две строки с точкой: **Cloudflare** и **Своя связь (coturn + LiveKit)**. Зелёная — несёт звонки сейчас, серая — в запасе, жёлтая — последняя проверка не прошла. Строка «Сейчас звонки идут через: …» говорит, кто несёт звонки. Кнопка **«Проверить»** делает настоящую пробу обоих путей (как телефон перед звонком) и показывает ✓ со временем ответа или ✗ с причиной.

Сколько сбоев и за какое время переключают звонки: `calls.transport_fail_limit` (5) и `calls.transport_fail_window_sec` (120 секунд). Менять обычно не нужно.

Какой путь работает сейчас, видно и в карточке «Связь для звонков», и в Система → «Состояние системы», строки «Звонки: Cloudflare TURN» и «Групповые звонки: Cloudflare SFU»: там написано «Сейчас звонки идут через Cloudflare» или «Сейчас НОВЫЕ звонки идут через наш запасной путь». Пока работает запасной путь, точка жёлтая.

## Что проверить после ввода ключей

1. **Звонок 1 на 1.** Позвоните с двух телефонов в разных сетях (один на Wi-Fi, второй на мобильном интернете). Звонок соединился, слышно обоих. В «Состоянии системы» строка Cloudflare TURN зелёная и пишет «Сейчас звонки идут через Cloudflare».
2. **Групповой звонок на троих.** Начните групповой звонок с видео из группового чата, позовите ещё двоих. Все трое видят и слышат друг друга. Строка «Групповые звонки: Cloudflare SFU» зелёная (если ключи SFU сохранены).
3. **Сломайте ключ и почините.** В «Ключи и сервисы» → Cloudflare TURN замените API-токен на неверный (сохраните настоящий в менеджере паролей!) и сохраните. Позвоните 1 на 1 несколько раз: звонки всё равно соединяются — через наш запасной TURN (если он задан в «Ключи и сервисы» → TURN). Через 5 неудачных попыток в «Состоянии системы» появится «Сейчас НОВЫЕ звонки идут через наш запасной путь». Верните настоящий токен и сохраните. Примерно через 1–2 минуты строка снова напишет «через Cloudflare», и новые звонки пойдут через Cloudflare. Ничего перезапускать не нужно.

4. **Отключить ключ Cloudflare во время звонка — разговор продолжается.** Начните групповой видеозвонок на троих и звонок 1 на 1 (на других телефонах). Во время разговора в Cloudflare (Realtime → SFU и TURN) отключите или удалите ключ — или в нашей карточке «Связь для звонков» замените App Secret / API-токен на неверный. Разговоры продолжаются: в группе возможна пауза 1–2 секунды, «Переподключение…» не появляется (или появляется ненадолго, если пауза дольше 3 секунд). Звонок 1 на 1 переходит на свой TURN сам (он должен быть задан в карточке). В карточке «Связь для звонков» после «Проверить» у Cloudflare ✗, а строка говорит «через свою связь» после нескольких сбоев. Верните ключ: новые звонки снова пойдут через Cloudflare примерно через минуту, а уже идущие звонки остаются на своей связи до конца.

## Как проверить

- На карточке после «Проверить» появится зелёная отметка.
- На странице «Запуск» (группа «Звонки») строка «Звонки: ключи Cloudflare TURN и проверка» станет зелёной.
- Позвоните с двух телефонов в разных сетях: один на Wi-Fi, второй на мобильном интернете.
- Пройдите три шага из раздела «Что проверить после ввода ключей».

## Частые ошибки

- Токен не скопировали сразу: повторно его не показать. Удалите ключ в Cloudflare и создайте новый.
- Перепутали Key ID и API Token: проверка покажет ошибку авторизации.
- Боитесь большого счёта: до 1000 ГБ в месяц платить не нужно. Расходы смотрите на странице «Расходы» в админке.
