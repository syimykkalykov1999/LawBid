## Что это и зачем

Все сообщения шифруются одним ключом. Чем больше сообщений под одним ключом, тем слабее защита, поэтому ключ меняют раз в год (новый ключ получает имя `kid`, старые остаются только для чтения). Заодно приложение теперь прячет ключи из переменных окружения и шифрует имена файлов в чатах и «Личные данные» дел. А соединение приложения с базой можно сделать проверяемым: сервер не просто шифрует, но и убеждается, что говорит с настоящей базой.

## Что понадобится

- Доступ к AWS (Secrets Manager) и к Terraform на вашем компьютере.
- Код 2FA для админки.

## Шаги: новый ключ сообщений (раз в год или когда плитка «Ключи сообщений» стала красной)

1. Сгенерируйте ключ в терминале: `openssl rand -base64 32`. Скопируйте результат (не отправляйте его никому).
2. Откройте [console.aws.amazon.com/secretsmanager](https://console.aws.amazon.com/secretsmanager/), найдите секрет **MESSAGE_ENC_KEYS** и нажмите **Retrieve secret value**, затем **Edit**.
3. Добавьте новый ключ через запятую после старого: `m1:СТАРЫЙ,m2:НОВЫЙ`. Старый не удаляйте.
4. В секрете **MESSAGE_ENC_ACTIVE_KID** (или в переменной окружения сервиса) впишите `m2`.
5. Перезапустите сервис: в AWS откройте **ECS**, выберите сервис и нажмите **Update service** с галочкой **Force new deployment**.
6. Через несколько минут откройте админку: **Система → Здоровье системы → Ключи сообщений**. Фоновая задача сама перешифрует старые сообщения новым ключом.
7. Когда проход закончен и ошибок нет, плитка покажет, какой старый ключ можно убрать. Только после этого удалите его из секрета. Если плитка пишет про ошибки, ключ не удаляйте.

## Шаги: проверенное шифрование до базы (когда будете готовы)

1. Соберите образ PgBouncer заново: GitHub → **Actions** → **Build PgBouncer** → **Run workflow**. В образ теперь встроен сертификат AWS для RDS.
2. В файле `terraform.tfvars` продакшена поставьте новый тег образа в `pgbouncer_image`, примените (`terraform apply`) и убедитесь, что всё работает.
3. Затем впишите `pgbouncer_db_tls_mode = "verify-full"` и примените ещё раз. Если пул не поднялся, верните `"require"` и примените: это откат.
4. По желанию впишите `pgbouncer_client_tls_private_ca = true` и примените: Terraform создаст собственный центр сертификации, и приложение будет проверять пул.

## Куда вставить в нашей админке

Ничего вставлять не нужно. Три новых переключателя в разделе **Настройки** уже стоят в безопасных значениях: «Шифровать имена файлов и личные данные» (включено), «Шифровать текст в журнале дел» (выключено, включайте только понимая условие про хранение ключей 5 лет), «Показывать текст в пуш-уведомлении» (включено, для адвокатов рекомендуется выключить).

## Как проверить

В **Здоровье системы** плитка «Ключи сообщений» зелёная, активный ключ новый. После `verify-full` в логах PgBouncer (CloudWatch) нет ошибок TLS, а приложение открывает чаты.

## Частые ошибки

- Нельзя убирать старый ключ, пока плитка не показала, что он больше не нужен: сообщения под ним перестанут читаться.
- Новый ключ должен быть случайным (команда выше). Слова и фразы приложение при старте отвергнет с понятным сообщением. Временный выход: переменная `KEY_STRENGTH_CHECK=off`, но лучше заменить ключ.
- Если сборка образа PgBouncer остановилась на проверке хэша сертификата RDS, AWS обновил файл: проверьте новый хэш по адресу из комментария в `infra/pgbouncer/Dockerfile`.
