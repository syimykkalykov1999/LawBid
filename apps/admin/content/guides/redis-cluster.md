## Что это и зачем

Redis - быстрая память, где живут очереди задач, кэш, лимиты, коды входа и сессии. Сейчас это одна группа (главный узел и запасной). Автомасштаб поднимает её размер по ступеням, но у самого большого узла есть предел по памяти и по одному процессорному ядру. Когда пришло письмо «Redis под большой нагрузкой, но уже на потолке» и размер уже `cache.r7g.xlarge` или больше - следующий шаг **кластер**: данные делятся между несколькими узлами (шардами).

Раньше это делать не нужно: кластер дороже и сложнее. Код приложения к кластеру готов, переключатель выключен. Кластер строится **рядом** со старым Redis, старый остаётся и служит для отката.

## Что понадобится

- Решение владельца, что потолок действительно достигнут (письма повторяются, размер максимальный).
- Mac с Terraform, свежий `git pull`, копия `terraform.tfvars` в Secrets Manager `lawbid-prod/terraform-tfvars`.
- Ночное окно по США, когда нет выкладки.
- Админка (код 2FA): страницы **Масштаб** и **Здоровье системы**.

## Шаги

1. **Подготовка.** Убедитесь, что на проде стоит версия с поддержкой кластера и тест `redis-cluster-scan.spec.ts` зелёный в CI. В tfvars `redis_cluster_mode = "off"`.
2. **Построить кластер рядом.** В `terraform.tfvars` прода поставьте `redis_cluster_mode = "standby"`. Размер: `redis_cluster_shards` (по умолчанию 2), `redis_cluster_replicas_per_shard` (1), `redis_cluster_node_type` (пусто = как сейчас). Сделайте план и проверьте, что создаются только группа `…-redis-cl`, группа параметров `…-redis7-cluster` и секрет `…/REDIS_CLUSTER_URL`. Нажмите **Run** на сохранённом плане. Старый Redis и приложение не меняются. Загрузите обновлённый tfvars в Secrets Manager. Ждите 15-30 минут.
3. **Проверить кластер.** Консоль AWS → **ElastiCache** → группа `…-redis-cl`: статус `available`, режим кластера включён, шардов столько, сколько в tfvars.
4. **Окно переключения.** Очереди в Redis - не данные, перенести их нельзя, поэтому: на **Масштаб** поставьте тяжёлые задачи на паузу; дождитесь, пока на **Здоровье системы** очереди покажут 0 не меньше 5 минут подряд. Что не успело, потеряется только как задание (источник правды - база). Кэши, лимиты, коды входа и сессии админов начнут с нуля: вас попросит войти заново, коды в полёте надо запросить снова.
5. **Переключить.** `redis_cluster_mode = "on"`, план, **Run**. Terraform сам подставит новый адрес и флаг кластера в API и воркер, серверы плавно обновятся, сокеты переподключатся.
6. **Проверить первые 15 минут.** `/health` зелёный, **Здоровье системы** без красного, пуши и чаты доходят, воркер забирает задачи, в логах нет ошибок `CROSSSLOT` или `MOVED`. Снимите паузу тяжёлых задач.
7. **Откат** (пока старая группа жива): `redis_cluster_mode = "standby"`, план, **Run**. Приложение вернётся на старый Redis. Очереди и кэши снова с нуля.
8. **Через неделю без проблем.** Старая группа ещё нужна LiveKit; удаляйте её только после переноса LiveKit. Автомасштаб Redis при кластере отключается сам.

Менять размер кластера потом: ElastiCache → группа → изменить число шардов или тип узла, онлайн, данные переезжают сами. Не делать во время выкладки.

## Как проверить

- На **Здоровье системы** строка Redis зелёная, очереди двигаются (воркер забирает задачи).
- На **Масштаб** карточка Redis показывает кластерный режим (автомасштаб неактивен).
- В ElastiCache группа `…-redis-cl` в статусе `available`.

## Частые ошибки

- Переключились днём или во время выкладки: пользователи увидят сбой чатов и звонков на минуты. Только ночью по США и вне деплоя.
- Не дождались пустых очередей: часть заданий (пуши, вебхуки) потеряется; Stripe повторит вебхуки сам, пуши - нет.
- В логах `CROSSSLOT`: команда с ключами из разных шардов. Откат по шагу 7, напишите Claude «CROSSSLOT» со строкой лога.
- Сокеты между серверами не доходят: у API и воркера должен быть одинаковый флаг кластера; Terraform ставит оба сразу, руками не трогать.
- Кластерную группу нельзя превратить обратно в обычную: откат всегда на старую группу, поэтому не удаляйте её раньше времени.
