## Что это и зачем

База данных (где лежат все записи) и Redis (быстрая память для очередей, кэша и кодов) стоят на серверах определённого размера. Чем больше размер, тем дороже. Две маленькие программы в AWS (Lambda) каждые 5 минут смотрят нагрузку:

- стало тяжело (процессор долго выше 70 %, кончается память или соединения) - размер поднимается **на одну ступень**, вам приходит письмо «База увеличена: A → B» или «Redis увеличен: A → B»;
- ночью в 03:30 по Чикаго, если 72 часа подряд было спокойно, размер опускается на ступень - письмо «уменьшена / уменьшен» с суммой экономии.

Смена размера базы - около минуты паузы (переключение на запасную копию). Смена Redis - секунды, адрес не меняется. Автоматика не работает во время выкладки новой версии и у базы требует включённого Multi-AZ (запасной копии).

Карточки с текущим размером, ступенью и режимом - на странице **Масштаб**. Кнопки «Увеличить» там же.

## Что понадобится

- Обычно ничего: только читать письма.
- Для ручных действий: Mac с AWS CLI и входом в AWS, свежий `git pull`.
- Для смены потолка: правка `terraform.tfvars` прода и «ставь на AWS» (инструкция aws-terraform-apply).

## Шаги

**Письма и что они значат**

1. «База увеличена» / «Redis увеличен» / «уменьшена» / «уменьшен» - ничего делать не надо. Если рост повторяется каждый день - просто нагрузка растёт, это нормально.
2. «База под большой нагрузкой, но уже на потолке» (то же про Redis) - решение за вами: поднять потолок (ниже) и бюджет `monthly_budget_usd`, либо оставить как есть. Для Redis на самом большом размере следующий шаг - кластер (инструкция redis-cluster).
3. «Автомасштабирование стоит на паузе» - у базы нет Multi-AZ или есть реплики чтения; у Redis нет реплики. Пока причина не уйдёт, размер меняется только руками.
4. «В Redis много соединений» - размер не менялся. Напишите Claude «соединения Redis».
5. «ПРОБНЫЙ РЕЖИМ, ничего не изменено» - стоит режим dry-run: письмо показывает, что программа сделала бы.
6. Тревога `lawbid-prod-db-autoscale-errors` или `lawbid-prod-redis-autoscale-errors` - сломалась сама программа, база и Redis остались как были. Напишите Claude «автомасштаб базы» или «автомасштаб Redis».

**Выключить или перевести в пробный режим**

7. Проще всего в админке: **Расходы** → положения автомасштаба «Выкл / Вкл = только письма / Авто». Это тот же переключатель `mode`.
8. Из терминала (действует в течение 5 минут):
   `aws ssm put-parameter --region us-east-1 --name /lawbid-prod/db-autoscale/mode --type String --overwrite --value off`
   и для Redis
   `aws ssm put-parameter --region us-east-1 --name /lawbid-prod/redis-autoscale/mode --type String --overwrite --value off`
   Значения: `on`, `dry-run`, `off`. «Ставь на AWS» это значение не трогает.

**Задать размер руками**

9. Сначала выключите автомасштаб (шаг 7 или 8), иначе он через 72 часа вернёт размер «по нагрузке».
10. Нажмите «Увеличить» на странице **Масштаб** или выполните, например для базы:
    `aws lambda invoke --region us-east-1 --function-name lawbid-prod-db-autoscale --cli-binary-format raw-in-base64-out --payload '{"action":"force","class":"db.t4g.medium"}' /dev/stdout`
    Для Redis имя функции `lawbid-prod-redis-autoscale`, размер вида `cache.t4g.medium`. Допустимы только размеры из лесенки.

**Потолок и пол**

11. В `terraform.tfvars` прода: `db_autoscale_max_class`, `db_autoscale_min_class`, `redis_autoscale_max_class`, `redis_autoscale_min_class`. Потом «ставь на AWS». Перед поднятием потолка проверьте бюджет: дорогие ступени задевают `monthly_budget_usd`.
12. Есть второй, **денежный** потолок: база не дороже 35 % допустимого расхода месяца, Redis не дороже 15 %. Включается и выключается на **Расходы** → «Потолок размера базы и Redis по деньгам». Поднять выше потолка из Terraform он не может.

## Как проверить

На странице **Масштаб** карточки базы и Redis показывают текущий размер, ступень и режим; после смены размера значение меняется в течение нескольких минут. Письмо приходит на почту владельца. Что программа видит прямо сейчас: `--payload '{"action":"status"}'` в команде из шага 10.

## Частые ошибки

- Поменяли размер руками, не выключив автомасштаб: ночью он вернёт размер обратно.
- База «висит» дольше 3 минут после смены: консоль RDS → **Events**. Не запускайте второе изменение, пока статус не `available`. Для Redis - консоль ElastiCache, ждать до 5 минут.
- «Качели» вверх-вниз каждые несколько дней: поднимите `min_class` на ступень выше текущей или задайте `down_window_h = 120` в `*_autoscale_tuning`.
- Хотите только рост без уменьшения: поставьте `min_class` равным текущему размеру.
- `redis_node_type` в tfvars после запуска ничего не меняет: его Terraform не применяет.
