## Что это и зачем

У LawBid есть публичные страницы, которые видят Google, Bing и ИИ-помощники: страницы штатов и практик, карточки адвокатов, карта сайта. Они собираются заново каждую ночь. Раздел **Admin → Продвижение: SEO и сторы** управляет тем, как именно они собираются и что можно показывать поисковикам. Пока вы ничего не нажали, всё работает как раньше.

Второе назначение раздела: список дел, которые система сделать за вас не может (подтвердить сайт в Google, завести страницы в магазинах приложений, ответить людям на форумах). Каждое дело отмечается галочкой «Сделано».

## Что понадобится

- Вход в **Admin** как владелец (или как админ, которому вы включили «Продвижение: SEO и сторы» с правом «управлять»).
- Для пробного запуска кнопкой: подключённое GitHub-приложение (**Admin → Ключи и сервисы**). Без него кнопка покажет команду для вставки в терминал.
- Для шагов в Google и Bing: аккаунт Google, доступ к DNS домена lawbid.dev.

## Шаги

1. Откройте **Admin → Контент и модерация → Продвижение: SEO и сторы**.
2. Нажмите **Пробный запуск (dry run)**. Ничего не публикуется: в GitHub Actions в запуске **SEO pages** будет план и цифры. Если приложение GitHub не подключено, скопируйте показанную команду `gh workflow run seo-deploy.yml -f dry_run=true`, либо откройте **GitHub → Actions → SEO pages → Run workflow** и поставьте галку **dry_run**.
3. Включайте тумблеры по одному, в порядке, который написан на странице: сначала «Публиковать только изменённое», потом «Карта сайта из нескольких файлов», затем «Пустить ИИ-поиск» и «Файл llms.txt». «Закрыть слабые страницы» и лимит новых страниц в сутки включайте, когда тексты страниц стали длиннее.
4. После «Карты сайта из нескольких файлов» один раз заново отправьте карту сайта: в **Google Search Console → Sitemaps** введите `sitemap.xml` и нажмите **Submit**; в **Bing Webmaster Tools → Sitemaps** сделайте то же самое.
5. Пройдите по **Чек-листу каналов** сверху вниз. Для Google: **Add property → Domain**, добавьте запись TXT в DNS, затем **Sitemaps**. Для Bing: **Add site → Import from Google Search Console**. Каждое выполненное дело отметьте галочкой.
6. Изменения тумблеров подхватываются при следующей сборке (она идёт каждую ночь). Чтобы увидеть результат сразу, запустите workflow **SEO pages** вручную без галки **dry_run**.

## Как проверить

- В блоке **Состояние** страницы видны дата последней сборки и число страниц: опубликовано, открыто для поиска, закрыто (noindex). Цифры обновляются раз в 10 минут. Пока файла `seo-manifest.json` нет, вместо цифр будет пояснение: он появляется после первой сборки с тумблером «Публиковать только изменённое» или с лимитом новых страниц в сутки.
- Откройте `https://lawbid.dev/sitemap.xml` в браузере: при включённой «Карте сайта из нескольких файлов» там список файлов, а не страницы.
- Откройте `https://lawbid.dev/robots.txt`: при «Пустить ИИ-поиск» там перечислены боты Google, Bing, OpenAI и Anthropic.
- В **Google Search Console → Sitemaps** статус **Success**, число найденных страниц растёт не быстрее лимита в сутки.

## Если что-то пошло не так

- Тумблер нажат, но на сайте ничего не изменилось: сборка идёт ночью. Запустите **SEO pages** вручную.
- В **Состоянии** написано, что сайт не открылся: цифры подтянутся позже, это не влияет на сами страницы.
- После «Закрыть слабые страницы» почти всё стало noindex: так и задумано, пока тексты короче порога (страница штата или практики от 300 слов). Выключите тумблер, тексты расширьте, включите снова.
- Нужно срочно всё откатить: выключите тумблер. При следующей сборке страницы вернутся к прежнему виду. Для немедленного эффекта запустите **SEO pages** вручную.
- Тумблер «не трогали»: значит действует переменная GitHub с таким же именем (**Settings → Secrets and variables → Actions → Variables**), а если её нет, выключено. Как только вы нажмёте тумблер, он главнее переменной.
