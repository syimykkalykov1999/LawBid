## Что это и зачем

Боты пытаются подобрать пароли и коды из СМС, узнать, какие номера у нас зарегистрированы, и украсть сессии. Пакет «защита входа» (октябрь 2026) закрывает эти дыры так, что честные люди ничего не замечают: одинаковые ответы для известных и неизвестных номеров, одна сессия-победитель при обновлении входа, предупреждения о входе с нового устройства или из новой страны, кнопка «Это не я», запрет одноразовых почтовых адресов при регистрации, учёт неверных кодов на пару «номер + адрес» (чужие ошибки не блокируют владельца номера). Всё это уже работает. Несколько защит, которым нужно обновлённое приложение, выключены настройкой — ниже сказано, когда их включать.

Термины: «App Check» — подтверждение от Google, что запрос пришёл из нашего настоящего приложения, а не от бота; «Turnstile» — такая же проверка для сайта от Cloudflare; «challenge» — требование такого подтверждения после нескольких неверных попыток.

## Что понадобится

- Вход в админку под владельцем, код 2FA для настроек.
- Для тревоги — Claude и Terraform (одно применение).
- Для «новой страны» — чтобы API стоял за CloudFront или Cloudflare (они передают страну запроса).

## Шаги

1. **Тревога в AWS.** Claude применяет Terraform: добавлена метрика `AuthFailures` и тревога `…-auth-failure-rate` (300 ошибок входа за 5 минут). Пока `terraform apply` не сделан, тревоги нет.
2. **Страна входа.** Предупреждения «вход из новой страны» работают только если до API доходит страна запроса: CloudFront → **Behaviors → Origin request policy** `AllViewerAndCloudFrontHeaders-2022-06` (или своя с заголовком `CloudFront-Viewer-Country`), либо Cloudflare (`CF-IPCountry`). Если API за одним балансировщиком без CloudFront — страны нет, ничего не срабатывает и ничего не ломается. После настройки включите `security.new_country_alert_enabled` в **Система → Настройки**.
3. **Настройки, которые уже включены и обычно не трогают:** `security.otp_legacy_purpose_fallback` (выключить, когда все версии приложения просят код с назначением `reauth`/`link` — тогда код «для входа» перестанет подходить для смены данных) и `security.signup_block_disposable_email` (выключить, только если блокировка мешает честным людям).
4. **Настройки, которые включать после обновления приложения:** `security.auth_challenge_after_failures` — поставить 3-5 после того, как приложение и сайт шлют токен App Check / Turnstile на вход; после стольких неверных попыток за 15 минут следующая требует подтверждения. `security.app_check.replay_protection` — включать вместе с `security.app_check.mode = enforce`, когда приложение шлёт одноразовые токены; каждый токен принимается один раз.
5. **Что должно уметь приложение** (следующий шаг для программистов): просить код для смены данных с `purpose: reauth | link` и брать одноразовый токен App Check на трёх маршрутах входа. Сервер к этому готов.

### Когда сработала тревога `auth-failure-rate`

1. Это подбор паролей или кодов. Включите `security.auth_challenge_after_failures` (3-5) в **Настройках** — боты без приложения упрутся в проверку.
2. Проверьте `security.app_check.mode`: при `enforce` бот без настоящего приложения отсекается совсем.
3. Посмотрите журнал: строки `metric: auth_failure`, поле `kind` — `password`, `otp_verify` или `reset_confirm` — покажет, что именно подбирают.
4. Через полчаса тревога должна сама вернуться в норму. Если нет — напишите Claude с выдержкой из журнала.

## Как проверить

- В **Система → Настройки** ключи `security.*` стоят в нужных значениях; изменения записаны в **Система → Журнал**.
- Тревога видна в AWS CloudWatch → Alarms как `…-auth-failure-rate` в состоянии OK.
- Войдите тестовым пользователем с нового устройства — придёт предупреждение; нажмите в приложении «Это не я» — все сессии аккаунта закроются, в журнале строка `wasnt_me`.
- Попробуйте зарегистрироваться с одноразовой почты (например, домен из публичных списков временных ящиков) — регистрация откажет, существующие аккаунты входят как раньше.
- В **Система → Здоровье системы** ничего не покраснело; коды входа честным людям продолжают приходить.

## Частые ошибки

- Включили `auth_challenge_after_failures` до того, как приложение шлёт токен App Check / Turnstile: честные люди после трёх опечаток в пароле не смогут войти. Сначала приложение, потом настройка.
- Выключили `otp_legacy_purpose_fallback` при старых версиях приложения: смена телефона или почты в них перестанет работать. Подождите, пока старые версии уйдут.
- Включили `new_country_alert_enabled`, а страна до API не доходит: просто ничего не происходит, вреда нет.
- Код входа на уже зарегистрированный номер «не приходит»: так задумано — приложение узнаёт «войдите по паролю» отдельным запросом, а СМС не тратится, чтобы не выдавать, кто у нас есть.
- Пользователь пишет, что в СМС нет строки `@lawbid.dev #код` на сайте с Android: привязка к домену добавляется только когда нет хеша приложения; для сайта её не будет, пока в Twilio нет отдельного отправителя.
- Тревога после 300 ошибок — это много для честных людей, но мало для бота: не поднимайте порог, лучше включите проверку.
