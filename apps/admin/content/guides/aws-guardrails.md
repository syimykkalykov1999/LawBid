## Что это и зачем

«Ограждения» - это набор проверок и замков вокруг нашего облака AWS. Они не меняют работу приложения, а следят, чтобы никто (включая нас самих по ошибке) не сделал опасного: не выключил журнал действий, не открыл хранилище наружу, не создал лишний ключ доступа. Четыре части:

- **AWS Config** - служба, которая раз в сутки сверяет настройки облака с 11 правилами (у root-пользователя есть 2FA, у хранилищ запрещён публичный доступ, база зашифрована, журнал CloudTrail включён и т. п.). Нарушение приходит письмом. Платная, поэтому по умолчанию выключена.
- **Аварийная роль (break-glass)** - запасной «ключ от всего» на один час, который можно взять только с кодом 2FA, и о каждом использовании приходит тревога. Бесплатно, выключена.
- **Athena по журналу CloudTrail** - готовые запросы «кто удалил», «кто входил в консоль», «действия root». Включена, стоит доли цента за запрос.
- **Аномалии расходов** - AWS сам замечает необычный рост счёта и присылает письмо в тот же день. Включено, бесплатно.

Пятая часть (SCP, правила на уровне организации) требует отдельной AWS Organization и пока не применяется.

## Что понадобится

- Mac с Terraform и входом в AWS (проверка: `aws sts get-caller-identity`).
- Свежий проект: `git pull`. Папка `infra/envs/prod`.
- Для аварийной роли: включённое 2FA (MFA) на вашем пользователе IAM.
- Код 2FA админки не нужен: всё делается в терминале и консоли AWS.

## Шаги

1. В Terminal перейдите в `infra/envs/prod` и выполните `terraform plan`. В списке должны появиться только: Athena, Glue, корзина результатов, подписка `*-cost-anomalies-sns`, правки политик SNS и ключа KMS. Если plan хочет что-то удалить или заменить - остановитесь и напишите Claude.
2. Выполните apply. Если AWS пришлёт письмо с просьбой подтвердить подписку - подтвердите.
3. **Config (по желанию, платно).** В `terraform.tfvars` поставьте `config_enabled = true`, снова plan и apply. Если prod и staging живут в одном аккаунте AWS, включайте Config только в одном из них. Потом откройте консоль AWS → **Config** → **Rules**: должно быть 11 правил. Часть сначала покажет NON_COMPLIANT - это честный список того, что ещё не наведено в порядок, а не поломка.
4. **Аварийная роль.** Убедитесь, что на вашем пользователе IAM включено MFA. Впишите его ARN (адрес пользователя, виден в IAM → Users → ваш пользователь) в `break_glass_principal_arns`, поставьте `break_glass_enabled = true`, apply. Один раз проверьте вход в роль (см. инструкцию «Аварийный вход в AWS (break-glass), когда обычный вход сломался») и что тревога о входе пришла письмом.
5. **Athena.** Консоль AWS → **Athena** → workgroup с окончанием `-security` → вкладка **Saved queries**. Там пять готовых запросов. Запускать их имеет смысл при расследовании: «кто удалил», «кто входил», «действия root».
6. Организацию и SCP делайте только когда решите заводить AWS Organization (отдельная инструкция по org-accounts).

## Как проверить

- Письмо от AWS Cost Anomaly Detection приходит само, когда счёт необычно растёт; проверить подписку можно в консоли **Billing → Cost Anomaly Detection**.
- При включённом Config: **Config → Rules** показывает 11 правил, и каждое нарушение приходит письмом с темой `lawbid-prod-...`.
- В админке на **Здоровье системы** ничего не меняется: это облачные проверки, они приходят на почту. В «Расходах» через месяц появится строка AWS Config на $1-4.

## Частые ошибки

- Включили Config и в prod, и в staging в одном аккаунте: рекордер может быть только один на регион, apply упадёт. Включите в одном.
- Поставили `break_glass_enabled = true` без MFA на пользователе: роль не даст войти (она требует код не старше 15 минут).
- Запросы Athena не работают: роли нужны права на чтение корзины CloudTrail и `kms:Decrypt`. Напишите Claude «Athena не читает CloudTrail».
- Если позже включите region-lock SCP, добавьте все регионы, которые реально использует приложение (копии в us-west-2), иначе копирование бэкапов остановится.
