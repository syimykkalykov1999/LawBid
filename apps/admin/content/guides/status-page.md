## Что это и зачем

Страница статуса — отдельный простой сайт, где любой человек видит: приложение, чаты, звонки, платежи, уведомления работают или нет. Главное её свойство — она **не зависит от нашего сервера**: лежит в хранилище AWS (S3) и раздаётся через CloudFront, поэтому открывается, даже когда сервер упал. Рабочий сервер каждую минуту кладёт туда свежий файл с состоянием. Если файл перестал обновляться (упало всё), страница сама пишет «данные могут быть устаревшими».

Когда что-то сломалось или идут плановые работы, вы можете вывесить на страницу своё сообщение: админка → **Система → «Страница статуса»**. Любое изменение публикуется сразу.

Выключено по умолчанию. Для включения нужны два шага: включить в Terraform (Claude) и добавить одну запись DNS (вы).

## Что понадобится

- Claude с Mac и доступом к AWS (Terraform).
- Доступ в Namecheap (сейчас) или Cloudflare (после переезда DNS).
- Вход в админку под владельцем для сообщений о сбоях.

## Шаги

1. **Terraform.** Claude добавляет в `infra/envs/prod/terraform.tfvars`: `status_page_enabled = true`, `status_host = "status.lawbid.dev"`, `status_create_certificate = true`. Затем запрашивает сертификат: `terraform apply -target=module.stack.module.status_page.aws_acm_certificate.status` и называет вам запись для подтверждения (из вывода `status_page_validation_records`).
2. **DNS для сертификата.** Добавьте записанную Claude запись CNAME у регистратора (Host без хвоста `.lawbid.dev.`, Value целиком). Сертификат подтверждается сам за 5-30 минут.
3. **Полный `terraform apply`** (Claude). Создаются хранилище, CloudFront и права фоновому обработчику записывать один файл `status.json`. В конце Claude назовёт адрес вида `dxxxx.cloudfront.net` (вывод `status_page_dns_target`). Хотите проверить заранее без домена — оставьте `status_host` пустым: страница откроется прямо по этому адресу.
4. **Запись `status`.** Сейчас (Namecheap): **Advanced DNS → Add record** → `CNAME Record`, Host `status`, Value — адрес CloudFront. Позже (Cloudflare): **DNS → Add record** → CNAME, Name `status`, Target тот же адрес, облачко **серое (DNS only)**, как у остальных записей. Оранжевое не включать: сертификат CloudFront проверяется напрямую. Если зона будет в Route 53, запись создаст сам Terraform.
5. Через минуту после `apply` фоновый обработчик начнёт класть свежий файл, и страница покажет живые данные.

### Сообщение о сбое или работах

1. Админка → **Система → «Страница статуса»**: выберите компонент (приложение, чаты, звонки, платежи, уведомления), тип (`degraded` — работает частично, `outage` — не работает, `maint` — плановые работы), заголовок и текст на русском и английском. Нужен свежий код 2FA, действие пишется в журнал.
2. Когда починили — нажмите **Закрыть** у инцидента. Страница обновится сразу. На один компонент может быть только один открытый инцидент.

## Как проверить

- `https://status.lawbid.dev` открывается с замочком и показывает пять компонентов зелёными; время обновления — не старше минуты.
- Создайте тестовый инцидент типа `maint` в **Система → «Страница статуса»** — через полминуты он виден на странице; закройте его — исчез.
- В админке **Система → Здоровье системы** и на странице статуса состояние совпадает: одна красная проверка на «Здоровье системы» даёт «частично» на странице; «не работает» появляется только когда сторож открыл инцидент (две плохие проверки подряд).
- Остановка фонового обработчика: через 6 минут страница сама покажет «данные могут быть устаревшими».

## Частые ошибки

- Страница открывается, но висит «нет данных»: прошло меньше минуты после `apply`, или фоновый обработчик не получил права на запись — Claude проверит `terraform apply`.
- В Cloudflare включили оранжевое облачко: сертификат CloudFront не проходит, страница не открывается. Переключите на серое (DNS only).
- Открыли второй инцидент на тот же компонент — система откажет: закройте первый.
- Ждёте, что страница покажет внутренние детали сбоя: нет, наружу уходят только пять общих статусов. Это задумано.
- Страница показывает «устарело», хотя приложение работает: лёг только фоновый обработчик, а не всё. Смотрите «Здоровье системы».
- Для полностью независимой внешней проверки (когда упал и обработчик) можно позже добавить сторонний бесплатный «пингер» (Upptime, UptimeRobot); для текущего решения он не обязателен.
