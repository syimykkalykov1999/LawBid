## Что это и зачем

При каждой выкладке задача миграций меняет устройство базы (новые таблицы, столбцы, индексы). Сейчас она делает это под главным пользователем базы. У него права почти на всё: создавать пользователей базы, менять их пароли, удалить базу целиком. AWS прямо советует не давать главного пользователя программам.

Переключатель «Миграции базы под узкой ролью» переводит эти изменения на отдельную роль `lawbid_migrator`. Она может менять таблицы приложения и больше ничего: не создаёт пользователей, не меняет пароли, не может удалить базу. Пароль роли система создаёт сама и хранит в AWS, вводить его не нужно.

Если что-то не готово, выкладка не ломается: миграции этого раза идут как раньше, а в журнале выкладки появляется предупреждение. Следующий раз система пробует снова.

Честно: роль видит все данные таблиц, которыми владеет (так устроена база PostgreSQL). Это закрыто тем, что роль работает только внутри задачи миграций.

## Шаги

1. Откройте «Масштаб» (или «Расходы»), строка «Миграции базы под узкой ролью (lawbid_migrator)».
2. Нажмите **Вкл**.
3. Через 2–5 минут откроется план. В нём меняется только задача миграций и её право читать один секрет. Ничего не удаляется, сайт и приложение не перезапускаются.
4. Нажмите «Подтвердить кодом 2FA и применить» и введите код.
5. Всё. Дальше система сама один раз передаёт таблицы новой роли (меньше минуты) и с этого момента делает миграции под ней.

## Как проверить

- У пункта статус «Готово».
- Ссылка «Журнал в GitHub» у пункта: в шаге «Migrate now» есть строка `migrator role: ready, migrations run as lawbid_migrator`.
- Если там написано `FALLBACK`, ничего не сломано, миграции просто прошли по-старому. Пришлите эту строку Claude.
- Откат: та же строка → **Выкл** → код 2FA. Миграции снова идут по-старому, ничего не удаляется.
