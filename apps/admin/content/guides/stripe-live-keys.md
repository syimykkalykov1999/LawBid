## Что это и зачем

Пока в админке стоит тестовый ключ (`sk_test_`), настоящие деньги не принимаются. Для запуска нужен боевой ключ, подпись вебхуков и (для оплат клиент → адвокат) Connect.

## Что понадобится

- Аккаунт Stripe с вашей почтой. Включите двухфакторный вход (лучше ключ доступа passkey).
- Данные компании: название, адрес, EIN, сайт, банковский счёт для выплат, документы владельца.
- Доступ к нашей админке владельца (2FA).

## Шаги

1. Откройте [dashboard.stripe.com](https://dashboard.stripe.com/register) и создайте аккаунт, если его нет.
2. Откройте [проверку бизнеса](https://dashboard.stripe.com/account/onboarding) и заполните данные о компании, продукте и владельцах. Пока бизнес не проверен, боевой режим не включается. Страну регистрации после активации сменить нельзя.
3. Откройте страницу [API keys](https://dashboard.stripe.com/apikeys). Переключитесь из **sandbox** в **live mode**.
4. Секретный ключ. Нажмите **Create secret key**, введите код из письма или SMS, в поле **Key name** напишите `lawbid-prod`, нажмите **Create**. Скопируйте ключ `sk_live_xxx` сразу: потом его не показать. Либо нажмите **Reveal live key** у стандартного ключа, если он ещё не раскрывался. Наша админка принимает и ограниченный ключ `rk_live_xxx`.
5. Публичный ключ **Publishable key** (`pk_live_xxx`) виден на той же странице, его можно скопировать сразу.
6. Вебхук. Откройте [Webhooks](https://dashboard.stripe.com/webhooks) (раздел Workbench) → **Create an event destination**. В вопросе об источнике выберите **Your account**. Формат данных: **Snapshot**. Выберите события, которые перечислены в разделе «Вебхук» документации по оплате (минимум `invoice.paid`, `payment_intent.succeeded`, события подписок). Далее выберите тип места назначения **Webhook endpoint** и вставьте **Endpoint URL**: `https://api.lawbid.dev/api/v1/webhooks/stripe`. На странице вебхука нажмите **Reveal secret** и скопируйте `whsec_xxx`.
7. Второй вебхук для оплат клиент → адвокат (Connect). Снова **Create an event destination**, но источник **Connected accounts**. Адрес: `https://api.lawbid.dev/api/v1/webhooks/stripe/connect`. Скопируйте его секрет `whsec_xxx`.
8. Включите Connect: в Dashboard найдите **Connect** и пройдите **Get started** для платформы (Express-аккаунты для адвокатов).

## Куда вставить в нашей админке

1. **Безопасность** → **Ключи и сервисы** → карточка **Stripe**.
2. **Secret key**: ключ из шага 4. **Publishable key (our card page)**: из шага 5 (нужен нашей странице оплаты). **Webhook signing secret**: из шага 6. **Connect webhook signing secret**: из шага 7.
3. Поля с ID цен заполняются по инструкции «Stripe - цены подписок».
4. Нажмите **Добавить ключи** → **Сохранить** (код 2FA) → **Проверить** → **Включить**. Боевой ключ сервер принимает только на AWS.

## Как проверить

1. «Проверить» в карточке вернёт успех (сервер читает баланс Stripe).
2. В **Система** → **Запуск** пункт «Платежи: боевой ключ Stripe и цены» станет жёлтым (ключ есть, цен не 3) и зелёным, когда будут все три цены.
3. В Stripe у вебхука во вкладке **Event deliveries** должны быть доставки со статусом `Delivered`.

## Частые ошибки

- Ключ `sk_test_`: «Запуск» красный с текстом «Стоит тестовый ключ». Нужен live.
- «Invalid signature» в журнале: вставили секрет не от того вебхука или не от live-режима. У тестового и боевого режима секреты разные.
- Адрес вебхука с перенаправлением (3xx) Stripe считает ошибкой. Адрес должен отвечать сразу.
- Не отправляйте ключи в чат и не кладите в git. Stripe просит хранить их в хранилище секретов.
- (не удалось проверить: точный список событий, на которые должен подписаться вебхук - он определяется кодом сервера; уточните у разработчика перед созданием)
