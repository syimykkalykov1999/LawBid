## Что это и зачем

Переписка адвоката с клиентом — самое ценное и самое чувствительное, что есть в LawBid. Пакет «защита админки» делает так, чтобы никто (включая вас) не мог прочитать приватное незаметно, чтобы журнал действий админов нельзя было подделать, и чтобы в админку нельзя было войти с чужого адреса. Всё работает как раньше, пока вы не включите.

Термины: «журнал аудита» — список всех действий админов (кто, что, когда); «цепочка хешей» — каждая запись хранит отпечаток предыдущей, поэтому удалить или подменить строку незаметно нельзя; «IP allowlist» — список интернет-адресов, с которых разрешён вход в админку.

## Что понадобится

- Вход под владельцем, приложение-аутентификатор для кодов 2FA.
- Для копии журнала в облако — Claude и Terraform (вы подтверждаете `apply`).
- Ваш текущий интернет-адрес (его показывает любой сайт «what is my IP»), если включаете список адресов.

## Шаги

1. **Чтение приватного.** Ничего включать не нужно, это уже работает. Единственное место — **Модерация → «Приватные чаты и файлы»**. Любое чтение требует код причины (жалоба, непосредственный вред, юридический запрос, техпроблема с согласия) и пояснение от 10 символов. Текст одного сообщения или файл открываются только по свежему коду 2FA (не старше `admin.private_stepup_seconds`, по умолчанию 120 секунд). Запись в журнал делается до показа; если записать не удалось, ничего не показывается (ошибка `AUDIT_UNAVAILABLE`). Второй админ не нужен.
2. **Политика приватного контента.** **Система → Право и жалобы → «Тексты и контакты»** → поле «Приватный контент: политика» (en и ru). Тексты по умолчанию уже есть; покажите их юристу перед публикацией.
3. **Месячный отчёт о чтениях.** Внизу страницы «Приватные чаты и файлы» и письмом 1-го числа в 07:15 UTC. Выключатель `admin.access_report_enabled` в **Настройках**.
4. **Копия журнала в облако** (делаете вы с Claude). В Terraform (папка `infra/envs/prod`) поставить `audit_logs_enabled = true` и `admin_audit_export_enabled = true`. Для копии, которую никто не перепишет, нужен S3 Object Lock (`audit_logs_object_lock = true`): он включается только при создании бакета, и с ним перестаёт доставляться журнал доступа к документам — решите до создания. Затем `terraform plan`, посмотреть, `terraform apply`, выкатить API. Переключатель в приложении — `admin.audit_export_enabled`.
5. **Список разрешённых адресов.** В **Настройках** впишите адреса в `admin.ip_allowlist` (вида `203.0.113.7` или диапазон `203.0.113.0/24`; для IPv6 только точные адреса), затем включите `admin.ip_allowlist_enabled`. Система не даст включить, если вашего текущего адреса нет в списке. Запрещённый адрес получает `ADMIN_IP_NOT_ALLOWED`, в журнал пишется `admin.ip_denied`.
6. **Оповещение о новом устройстве или адресе.** Включено по умолчанию (`admin.login_alert_enabled`): при входе админа с незнакомого браузера или адреса владельцу приходит письмо. Письма идут через вашу почту SES; если почта не настроена, вход всё равно проходит.
7. **Лимит одновременных сессий.** `admin.max_concurrent_sessions` (0 = без лимита). Например, 2: третий вход закрывает самую старую сессию.

## Как проверить

- Откройте любой приватный чат в «Приватные чаты и файлы»: без причины и пояснения система не пустит; в **Система → Журнал** появилась строка с причиной.
- Проверка цепочки журнала: попросите Claude вызвать `GET /admin/audit-log/verify-chain` (только владелец). Ночная выгрузка тоже проверяет и пишет в лог `audit_log hash chain is BROKEN`, если цепочка сломана.
- Копия журнала: на следующее утро после включения в бакете появилась папка `admin-audit/ГГГГ/ММ/ДД/`.
- Список адресов: войдите с телефона через мобильный интернет (другой адрес) — должны получить отказ `ADMIN_IP_NOT_ALLOWED`.
- На **Система → Здоровье системы** всё зелёное; защита не влияет на пользователей.

## Частые ошибки

- **Заперли себя списком адресов.** Способ A (быстрее): AWS Console → **ECS** → кластер → сервис `api` → **Update service** → новая ревизия Task definition с переменной `ADMIN_IP_ALLOWLIST_BYPASS` = `1`; дождаться, пока задачи станут healthy; войти, исправить список или выключить `admin.ip_allowlist_enabled`; **обязательно убрать переменную** и перевыкатить. Способ B: через базу (делает Claude) выполнить `UPDATE app_config SET value = 'false'::jsonb WHERE key = 'admin.ip_allowlist_enabled';`, подождать 1-2 минуты (настройки кэшируются), потом записать это вручную в инцидентный журнал — в журнал аудита такое изменение не попадает.
- Домашний интернет меняет адрес: впишите диапазон провайдера или временно выключите список. Лучше — постоянный адрес или VPN с фиксированным выходом.
- Ошибка 503 `AUDIT_UNAVAILABLE` на денежных страницах, ключах, админах, выгрузках: журнал не пишется (база недоступна). Это защита: действие не выполняется, пока журнал не заработает. Смотрите «Здоровье системы».
- Старые строки журнала (до 28 октября 2026) без отпечатка — это нормально, цепочка начинается с первой новой строки.
- Включили Object Lock на уже созданный бакет: не получится, он включается только при создании. Без него политика бакета всё равно запрещает удаление, а версионирование хранит историю.
