## Что это и зачем

Наши серверы стоят в закрытой сети. Когда им нужно в интернет (к Twilio, Stripe, Cloudflare, Bunny, Firebase) или к другим службам AWS, трафик идёт через одну «дверь» - NAT. AWS берёт за неё примерно $33 в месяц плюс $0,045 за каждый гигабайт. Если за сутки через дверь прошло больше 20 ГБ (≈ $0,9), приходит письмо `lawbid-prod-nat-bytes-0`. Приложение при этом работает, это сигнал про деньги.

**Эндпоинт** - отдельная «дверь» только к одной службе AWS (например, к хранилищу образов или к журналам). Он стоит ≈ $7,3 в месяц, но каждый гигабайт через него дешевле на $0,035. Выгоден, только если через него идёт больше ≈ 210 ГБ в месяц. Трафик к внешним сервисам (Twilio, Stripe, Cloudflare, Bunny) через эндпоинт идти не может: NAT для них нужен всегда.

С 2026-10-25 эндпоинты решает автоматика: маленькая программа раз в час смотрит трафик NAT, при больше 20 ГБ в сутки создаёт эндпоинты и пишет письмо, после 7 спокойных суток удаляет их и тоже пишет.

## Что понадобится

- Почта владельца.
- Для измерений: Mac с AWS CLI и входом в AWS.
- Для ручных переключений: админка (код 2FA), страница **Настройки**.

## Шаги

**Пришло письмо о трафике**

1. Посмотрите, сколько именно: консоль AWS → **CloudWatch** → метрики `AWS/NATGateway`, сумма `BytesOutToDestination` и `BytesInFromDestination` за день. Или из терминала команда из runbook с вашим идентификатором NAT (nat-…):
   `aws cloudwatch get-metric-statistics --namespace AWS/NATGateway --metric-name BytesOutToDestination --dimensions Name=NatGatewayId,Value=nat-XXXXXXXX --start-time $(date -u -v-7d +%FT%TZ) --end-time $(date -u +%FT%TZ) --period 86400 --statistics Sum --output table`
2. Кто качает: **Cost Explorer** → фильтр Usage type `NatGateway-Bytes`. Если один сервис AWS даёт больше 210 ГБ в месяц - эндпоинт окупится (автоматика его и создаст). Если трафик к Twilio/Stripe/Cloudflare/Bunny - эндпоинт не поможет; напишите Claude «NAT много трафика», будем искать лишние скачивания.
3. Если письма мешают: `nat_traffic_alarm_gb_per_day = 0` в tfvars выключает тревогу (удалить строку - вернётся 20).

**Управление эндпоинтами**

4. Главный выбор - в админке **Настройки**, ключ `scale.endpoints.mode`: `auto` (по умолчанию, решает трафик), `on` (всегда включены), `off` (никогда, созданные удаляются). Ключ `scale.endpoints.ceiling` - сколько эндпоинтов разрешено держать (0-4). Применяется в течение часа.
5. Аварийный выключатель лежит в AWS **Systems Manager → Parameter Store**, ключи `/<имя стека>/endpoints-autoscale/mode` (`on`, `dry-run`, `off`) и `ceiling`.
6. Если программа сломается три раза за три часа, придёт тревога `...-endpoints-autoscale-errors`. Напишите Claude.

**Вторая зона (принятый риск)**

7. Сейчас NAT, эндпоинты и по одному серверу API стоят в одной зоне AWS (экономия ≈ $62 в месяц). Если зона упадёт, уже работающие серверы отвечают, а новые не смогут запуститься. Мы это приняли, пока людей мало.
8. Когда пользователей станет много, включите одной правкой tfvars: `nat_per_az = true`, `interface_endpoint_azs = 2`, `api_min_tasks = 2` (≈ +$80 в месяц). `terraform plan` (должны быть только новые ресурсы, не удаления) и apply, ≈ 10 минут, без простоя. То же делается аварийно при падении зоны.

## Как проверить

- Письмо `nat-bytes` после действий больше не приходит, или приходит реже.
- Строка NAT в **Расходы** (и в Cost Explorer по сервису «EC2-Other») перестаёт расти.
- Созданные автоматикой эндпоинты видны в консоли **VPC → Endpoints** с меткой `ManagedBy=...-endpoints-autoscale`; о каждом изменении приходит письмо.
- Тревога `nat-port-alloc` (кончились порты) после второй зоны или эндпоинтов больше не срабатывает.

## Частые ошибки

- Включили эндпоинты «на всякий случай» при малом трафике: 4 эндпоинта ≈ $29 в месяц окупаются только от ≈ 840 ГБ. Оставьте `auto`.
- Ждёте эффекта от эндпоинта на трафике к Twilio или Stripe: его не будет, они вне AWS.
- Эндпоинт, заведённый в Terraform (`interface_endpoints`), автоматика не трогает - управляйте им только через tfvars.
- Ручной выбор в **Настройки** применяется в течение часа, не мгновенно.
