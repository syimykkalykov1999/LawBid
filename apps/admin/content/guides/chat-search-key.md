## Что это и зачем

Тексты чатов хранятся зашифрованными, поэтому прежний поиск по словам ничего не находил. Теперь каждое слово сообщения хранится как «отпечаток», посчитанный секретным ключом `SEARCH_INDEX_KEY`: сами слова в базе не лежат, а поиск снова находит сообщения. Пока ключа нет, поиск в чатах находит только имена и названия дел.

## Что понадобится

- Доступ к AWS и Terraform на вашем компьютере (папка `infra/envs/prod`).
- Код 2FA для админки.

## Шаги

1. В терминале в папке `infra/envs/prod` выполните `terraform apply -target=module.stack.module.secrets` и подтвердите `yes`. Создастся пустой секрет **SEARCH_INDEX_KEY**; сервисы не перезапускаются.
2. В корне проекта выполните `bash scripts/deploy/prod-secrets.sh`. Скрипт положит случайный ключ только в пустые секреты, остальные не тронет (напишет «уже есть, не трогаю»).
3. Снова в `infra/envs/prod`: `terraform apply` как обычно. Сервисы перезапустятся уже с ключом.
4. Новые сообщения ищутся сразу. Старые проиндексирует задача сама: админка → **Настройки** → «Индексация старых сообщений». По умолчанию **auto** — работает ночью, пока не закончит, потом спит. **on** — каждые 5 минут, **off** — стоп. Потолок нагрузки — «Сколько сообщений индексация обрабатывает за один запуск».
5. Проверьте: в приложении откройте поиск в списке чатов и введите слово из старого сообщения.

## Если что-то пошло не так

- После шага 3 сервис не стартует — значит, шаг 2 не выполнен: запустите `prod-secrets.sh` и нажмите в **ECS** у сервиса **Update service** с галочкой **Force new deployment**.
- Сменить ключ можно (новое значение в секрете и перезапуск): новые сообщения пойдут с новым ключом, старые задача переиндексирует сама; до конца прохода их по словам не найти. Потеря ключа данные не портит — нужна только переиндексация.
- «Пауза тяжёлых задач» тоже останавливает индексацию, это нормально.
