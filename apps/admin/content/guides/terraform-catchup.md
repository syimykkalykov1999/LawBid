## Что это и зачем

Terraform это описание сервера в виде файлов: какие тревоги есть, какие права у приложения, сколько соединений с базой. Код приложения и это описание живут в одном репозитории и должны совпадать. Бывает, что код ушёл вперёд (в репозитории уже лежат новые тревоги и права), а на сервере их ещё нет. Тогда новая версия приложения может не получить нужные права, а две тревоги (`cron-job-failing` и `migrate-failed`) не будут приходить.

Скрипт `tf-catchup.sh` «подтягивает» сервер до кода тремя командами. Он сам ничего не применяет: сначала считает план (список того, что изменится), проверяет его на опасные удаления и показывает русскую сводку. Применяется только ровно тот план, который вы прочитали, и только после вашего слова `ДА`.

Делать это нужно **до** выкладки кода (Deploy → Approve), один раз, когда Claude сказал, что сервер отстал. Это родная сестра инструкции «Terraform plan и apply через наши скрипты»: там общий порядок, здесь короткий путь для «догнать код».

## Что понадобится

- Mac с установленными Terraform и AWS CLI и доступ к аккаунту AWS (вход через `aws login`, откроется браузер).
- Свежий код проекта (скрипт сам проверит и попросит `git pull`).
- 20-40 минут, окно Терминала не закрывать.

## Шаги

1. Откройте Terminal и войдите в AWS. Откроется браузер, войдите в аккаунт:
   `aws login`
2. Посчитайте план. Ничего не меняется, займёт 2-10 минут (первый запуск дольше: скачиваются провайдеры):
   `cd /Users/sima/Desktop/LawBid && git pull && bash scripts/dev/tf-catchup.sh plan`
3. Прочитайте русскую сводку в конце: сколько ресурсов добавится, изменится, заменится, удалится.
   - Зелёное **«Опасных удалений и замен нет»**: можно дальше.
   - Красный **СТОП**: ничего не применяйте, скопируйте вывод и пришлите Claude. Скрипт такой план и сам не примет.
   - Жёлтые строки это удаление старых тревог: безвредно, в тревоге нет данных.
4. Примените ровно этот план. Скрипт ещё раз спросит, напечатайте `ДА` и нажмите Enter:
   `bash scripts/dev/tf-catchup.sh apply`
5. Дождитесь слов об успешном завершении. Секреты и файл плана скрипт удалит сам.
6. Дальше обычная выкладка кода: GitHub → **Actions** → **Deploy** → **Review deployments** → **Approve and deploy** (инструкция «Выкатить последнюю версию (main) на боевой сервер»).

## Как проверить

- В выводе apply нет слова `Error`, а в конце написано, сколько добавлено и изменено (числа совпадают со сводкой плана).
- В AWS Console → **CloudWatch → Alarms** появились тревоги `lawbid-prod-cron-job-failing` и `lawbid-prod-migrate-failed` (состояние OK или «Insufficient data»).
- После следующей выкладки на **Система → Запуск** строка «Запущена последняя версия (main)» зелёная, а в **Здоровье системы** нет жёлтых строк про права или тревоги.
- Ночная проверка «Terraform drift» в GitHub (Actions) больше не открывает issue «Terraform drift on prod».

## Частые ошибки

- «Вы не вошли в AWS» или «Вход в AWS истёк» (в том числе `ExpiredToken` посреди плана): `aws login --remote`, войдите по ссылке, повторите команду. Вход живёт около 15 минут, но скрипт сам его обновляет во время работы.
- «Terraform init не прошёл» со словом `symlink`: удалите папку `~/.lawbid-tf-catchup/plugin-cache` и запустите план снова.
- «У вас старая версия кода»: `cd /Users/sima/Desktop/LawBid && git pull` и снова `plan`.
- «За это время на сервере сменилась версия кода»: пока вы читали план, прошла выкладка. Посчитайте `plan` заново, это безопасно.
- Ошибка посреди `apply`: ничего не запускайте руками. Terraform запомнил, что успел. Пришлите вывод Claude, он подготовит безопасный следующий план.
- Хотите «откатить» Terraform старым apply: так не делают, в обратном плане легко оказываются удаления. Если плохо пошла выкладка кода, это не Terraform, а инструкция про откат («Вернуть боевой сервер на последнюю хорошую версию»).
