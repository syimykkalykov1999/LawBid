## Что это и зачем

Три закона США касаются каждого приложения с регистрацией: COPPA (нельзя собирать данные детей до 13, мы ставим планку 18+), TCPA (нельзя слать рекламные СМС без явного согласия и после слова STOP) и CAN-SPAM плюс правила Gmail/Yahoo (у рассылки должен быть почтовый адрес, кнопка отписки и низкая доля жалоб). Сервер уже умеет всё нужное, но **по умолчанию выключено**: приложение работает как раньше. Эта инструкция — что включить и где.

Термины: «вебхук» — адрес, на который внешний сервис (Twilio, Amazon) сам присылает события; «стоп-лист» — список номеров и адресов, которым больше ничего не отправляем; «SNS-тема» — почтовый ящик событий внутри AWS.

## Что понадобится

- Вход в админку под владельцем и код 2FA.
- Доступ в Twilio Console и в AWS Console.
- Решение по внешнему виду приложения: добавлять ли галочку «Мне есть 18 лет» и экран согласия на СМС (внешний вид заморожен, это ваше решение).
- Юрист для трёх текстов: заявление COPPA, текст согласия на СМС, политика удаления аккаунтов несовершеннолетних.

## Шаги

### Возраст 18+

1. В **Система → Настройки** ключ `compliance.age_gate.mode`: `off` (как сейчас), `record` (только записывать подтверждение возраста, никого не блокировать), `enforce` (без подтверждения аккаунт не создаётся).
2. Режим `enforce` включать **нельзя**, пока в приложении нет галочки «Мне есть 18 лет» на экране регистрации — иначе никто не сможет зарегистрироваться. Сначала решение о галочке, потом режим.
3. Дата рождения младше 18 уже сейчас не даёт создать аккаунт, независимо от режима.
4. Несовершеннолетние, которых заметили позже: в админке раздел проверки несовершеннолетних показывает помеченные аккаунты. «Пометить» блокирует аккаунт и кладёт телефон и почту в стоп-листы; «Снять пометку» возвращает; «Удалить» (код 2FA) обезличивает сразу. Если на аккаунте заморозка по запросу госоргана, удаление откладывается.
5. Текст для Privacy Policy (на согласование юристу) есть в runbook: «LawBid is intended for people who are 18 or older…».

### Рекламные СМС

1. Коды входа — служебные сообщения, согласие на них не нужно и стоп-лист на них не действует. Всё остальное идёт только при включённом `compliance.sms.marketing_enabled` (по умолчанию выключен), при записанном согласии человека, если номер не в стоп-листе и не в «тихие часы» (с 21:00 до 8:00 по местному времени получателя).
2. **Twilio Console** → ваш Messaging Service (или номер) → поле «A message comes in» → впишите `https://api.lawbid.dev/api/v1/webhooks/twilio/sms`, метод POST. Подпись Twilio проверяется ключом из **Ключи и сервисы**; без ключей адрес отвечает 404.
3. После этого STOP (и quit, end, cancel, unsubscribe, revoke, opt out) сразу кладёт номер в стоп-лист; START снимает; HELP по умолчанию отвечает сам Twilio. Свой текст HELP: включите `compliance.sms.reply_to_help` и впишите `compliance.sms.help_text`.
4. Старый стоп-лист из Twilio: Console → **Messaging → Opt-out Management** → экспорт, затем попросите Claude загрузить его через `POST /admin/compliance/sms/opt-outs/import` (код 2FA).
5. Важно: после STOP оператор блокирует этому номеру и коды входа, пока человек не напишет START. Для таких людей остаётся вход по почте.

### Письма

1. Рассылки «Привлечения» уже содержат почтовый адрес из Outreach → Settings, ссылку отписки и заголовки отписки в один клик. Уведомления получают подвал с адресом из `compliance.email.footer_address` (если пусто — адрес из Outreach → Settings).
2. Недоставленные письма и жалобы «спам»: AWS Console → **SNS → Create topic** (Standard), имя `ses-events`, тот же регион, что у SES.
3. **SES → Verified identities** → ваш домен → **Notifications → Feedback notifications**: для Bounce и Complaint выберите эту тему.
4. **Сначала** в **Настройках** впишите `compliance.sns.topic_arns` = ARN темы (длинная строка `arn:aws:sns:...`, её показывает SNS). **Потом** SNS → тема → **Create subscription**: Protocol `HTTPS`, Endpoint `https://api.lawbid.dev/api/v1/webhooks/ses`. Подписка подтвердится сама. Порядок важен.
5. Один раз проверьте DNS домена отправителя: SPF, DKIM и DMARC настроены (ставились при первом запуске). Доля жалоб должна быть ниже 0,3 %.

## Как проверить

- **Настройки**: `compliance.sns.topic_arns` заполнен, в SNS подписка в статусе Confirmed.
- Отправьте с тестового номера слово STOP на номер Twilio: в админке номер появился в стоп-листе; затем START — исчез.
- В **Система → Здоровье системы** ничего не покраснело; коды входа продолжают приходить.
- Жалоба или постоянная недоставка попадает в список `email_suppressions` и в стоп-лист рассылки, лид становится «не беспокоить».

## Частые ошибки

- Включили `enforce` без галочки в приложении — регистрация остановилась. Верните `off` или `record`.
- Создали подписку SNS раньше, чем вписали ARN в настройку: сервер отклонит чужую тему. Удалите подписку, впишите ARN, создайте снова.
- Вебхук Twilio отвечает 404: не заполнены ключи Twilio в **Ключи и сервисы**.
- Человек пожаловался, что не приходит код входа после STOP — это блокировка оператора, не наша. Пусть напишет START или войдёт по почте.
- Временные сбои доставки (ящик полон) в стоп-лист не попадают — это нормально.
