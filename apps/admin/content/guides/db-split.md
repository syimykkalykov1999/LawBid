## Что это и зачем

Вся база сейчас лежит на одном сервере. Внутри она заранее разложена на 256 «ящиков» (логических частей), и у каждой записи есть номер ящика. Пока ящики стоят на одном сервере, разницы не видно. Когда сервер перестанет справляться, часть ящиков можно перевезти на второй сервер: приложение само поймёт, где какой ящик лежит.

Переезд одного ящика идёт так: копируем данные, догоняем новые изменения, на несколько секунд останавливаем запись в этот ящик, сверяем количество строк и контрольные суммы, переключаем маршрут. Старая копия хранится 7 дней, всё это время переезд можно отменить без потерь. Пользователи переезда не замечают, кроме паузы в секунды на одном ящике.

Когда это нужно: процессор основной базы выше 60 процентов несколько дней подряд даже после копии для чтения и пулера, или одна таблица больше 500 ГБ. Раньше не надо: второй сервер стоит денег каждый месяц.

## Что понадобится

- Решение владельца и помощь Claude: второй сервер базы создаётся в AWS и стоит денег.
- Второй сервер RDS PostgreSQL 16 того же класса, что основной (и Multi-AZ, если основной Multi-AZ). Логическая репликация не нужна, перезагрузка базы не нужна.
- Адрес второго сервера в секрете `DATABASE_URL_SHARDS` (Claude подготовит, вы подтверждаете apply), после чего перевыкладка приложения.
- Миграции (структура таблиц), применённые ко второму серверу: `DATABASE_URL=<адрес db1> npx prisma migrate deploy` в папке `apps/api`. Повторять после каждого релиза с миграцией, до выкладки этого релиза.
- Код 2FA из приложения-аутентификатора. Второй админ не нужен.

## Шаги

1. Включите подсказку: **Настройки** → переключатель `scale.db_split_enabled` в положение «Вкл». На странице **Масштаб** появится карточка «Разделить базу» с пошаговой проверкой готовности.
2. Нажмите на карточке **Проверить**. Она проверяет три вещи: второй сервер записан в `DATABASE_URL_SHARDS`, до него можно достучаться, миграции на нём применены. Красные пункты показывают, чего не хватает; напишите Claude, что именно.
3. По желанию те же проверки можно сделать командами из Терминала (ничего не меняют, безопасны в любое время):
   `npm run shard:move --workspace apps/api -- readiness db1` (готов ли второй сервер),
   `npm run shard:move --workspace apps/api -- split-plan db1` (какие ящики поедут, сколько строк, сколько времени),
   `npm run shard:move --workspace apps/api -- plan 200 db1` (сухой прогон одного ящика).
4. Когда всё зелёное, откройте **Система → Здоровье системы** → карточка «Разделить базу на два сервера» → **Показать план**. Прочитайте: сколько ящиков, строк и примерное время.
5. Нажмите **Разделить базу** и введите код 2FA. Переезд запустился и идёт в фоне; на карточке виден прогресс по каждому ящику. Окно можно закрыть.
6. Если переезд остановился (ошибка сети, перезапуск), на карточке появится **Продолжить**: он продолжит с сохранённого шага.
7. Передумали или что-то не так: **Откатить** (код 2FA). До переключения копия просто удаляется. После переключения новые записи сначала возвращаются на старый сервер, потом маршрут переключается назад. Откат доступен 7 дней, пока не удалены старые строки.

## Как проверить

- На **Здоровье системы** карточка «Разделить базу на два сервера» показывает переезд со статусом «готово», а в обзоре у второго сервера появились ящики.
- Приложение работает: вход, список кейсов, чат открываются как раньше.
- В журнале за ночь нет записей `cross_family_orphans` (ночная проверка «осиротевших» записей) и ошибок `55P03` дольше минуты.
- Через 7 дней старые строки удалятся сами, карточка покажет «очистка выполнена».

## Частые ошибки

- Нажали «Разделить базу» без «Проверить»: кнопка откажется, если второй сервер не готов. Это защита, а не поломка.
- Пропустили миграции на втором сервере после релиза: приложение выдаст ошибку о неизвестной колонке. Применить `npx prisma migrate deploy` на db1 и повторить.
- План говорит о «старых случайных id» (демо-данные): их нужно убрать до переезда, инструмент такие ящики не повезёт. Напишите Claude.
- Запись отклоняется словами «frozen for a move» дольше минуты: переезд оборвался в момент заморозки. Нажмите **Продолжить** или **Откатить**.
- Бэкапы у каждого сервера свои; после восстановления одного сервера из копии попросите Claude запустить проверку `orphans`.
