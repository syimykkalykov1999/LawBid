## 1. Общая логика

```
Адвокат регистрируется → онбординг (файл 1) → статус unverified
   │
   ▼
Заявка на верификацию: лицензии по штатам + документ личности + селфи
   │
   ▼
Автопроверки (если включены флагами) + ручная проверка админом-верификатором
   │
   ├─ approved  → verified: доступ к вкладке «Кейсы», выбор практик, старт триала (файл 6)
   ├─ needs_more_info → адвокат догружает, заявка возвращается в очередь
   └─ rejected  → адвокат видит причину и может подать новую заявку
```

**Что даёт статус verified:**
- Синяя галочка у имени (по правилам раздела 6.3).
- Доступ к выбору практик и вкладке «Кейсы» (просмотр кейсов только в штатах с подтверждённой лицензией и по выбранным практикам).
- Возможность запустить 7-дневный триал (карта обязательна, файл 6).
- Отправка бидов только при активной подписке или триале (файл 4).

**Что доступно unverified/pending:** Лента, Поиск, редактирование профиля, публикация постов (решение по постам см. раздел 6.4), экран статуса верификации. Вкладка «Кейсы» показывает экран «Пройдите верификацию».

## 2. Верификация адвоката

### 2.1 Что подаёт адвокат
| Блок | Что нужно | Обязательно |
|---|---|---|
| Лицензии | Для каждого штата: штат, номер лицензии (bar number), фото/скан подтверждающего документа (bar card, certificate of good standing или скриншот/PDF профиля адвоката на сайте State Bar), срок действия (если указан) | минимум 1 штат |
| Документ личности | Один из: driver license, passport, state ID. Лицевая сторона (и обратная для driver license и state ID) | да |
| Селфи | Фото лица с камеры, лицо целиком, хорошее освещение | да |

- Имя и фамилия в профиле должны совпадать с именем в документе личности и в записи о лицензии. Расхождения (например, девичья фамилия) допускаются, если адвокат прикладывает пояснение (поле «Комментарий для проверяющего», до 500 символов).
- Адвокат может подать лицензии сразу в нескольких штатах в одной заявке. Позже добавить ещё штат можно новой заявкой (документ личности и селфи повторно не требуются, если адвокат уже `verified`).

### 2.2 Требования к файлам
- Форматы: JPEG, PNG, HEIC (конвертируется на сервере в JPEG), PDF (только для лицензий).
- Размер: до 10 МБ на файл, до 3 файлов на один документ.
- Селфи и документ личности: можно снять камерой в приложении; загрузка из галереи для документа личности разрешена, для селфи только камера.
- Загрузка через **pre-signed URL** в приватный S3 (срок действия ссылки 5 минут), после загрузки клиент вызывает подтверждение. Сервер проверяет реальный MIME (magic bytes), размер и запускает антивирус-скан (`scan_status`). Файл со статусом `infected` или `failed` не может быть прикреплён к заявке.
- Публичного доступа к документам нет. Просматривать их может только роль `verifier` (и `super_admin`) через короткоживущие подписанные ссылки (срок 5 минут). **Каждый просмотр документа пишется в `audit_log`.**
- Клиентское приложение показывает превью только что загруженного файла, после отправки заявки документы в приложении не отображаются.

### 2.3 Статусы и переходы

`verification_requests.status` (enum из файла 2):

| Из | В | Кто | Условие |
|---|---|---|---|
| — | `draft` | адвокат | создаёт заявку, заполняет шаги |
| `draft` | `submitted` | адвокат | выполнены все обязательные поля и файлы (`clean`) |
| `submitted` | `in_review` | система/верификатор | заявка взята в работу (1 верификатор на заявку, блокировка) |
| `in_review` | `needs_more_info` | верификатор | нужно догрузить или уточнить, указывается сообщение адвокату |
| `needs_more_info` | `submitted` | адвокат | адвокат ответил/догрузил |
| `in_review` | `approved` | верификатор | подтверждена личность и минимум одна лицензия |
| `in_review` | `rejected` | верификатор | указана причина |

Ограничения:
- У адвоката одновременно только одна заявка в статусах `draft/submitted/in_review/needs_more_info` (иначе `VERIFICATION_ALREADY_PENDING`).
- После `rejected` новая заявка возможна не чаще 5 раз за 30 дней (параметр в `app_config`).
- Синхронизация со статусом профиля (`attorney_profiles.verification_status`): `draft` → `unverified`; `submitted/in_review/needs_more_info` → `pending`; `approved` → `verified`; `rejected` → `rejected`.
- При `approved` каждая лицензия проверяется отдельно: верификатор для каждой указывает `verified` или `rejected` (`attorney_licenses.license_status`). Заявка может быть одобрена частично (например, 1 из 2 штатов): одобренные штаты становятся доступны, отклонённые получают причину.

### 2.4 Автоматические проверки

Все автопроверки записываются в `verification_checks` и **только помогают верификатору**, окончательное решение всегда принимает человек.

| Проверка | Провайдер (интерфейс) | Включается флагом | По умолчанию |
|---|---|---|---|
| Поиск адвоката в базе State Bar по номеру и имени (`bar_lookup`) | `BarLookupProvider` с адаптерами по штатам, где есть публичная база; для остальных штатов адаптера нет, и проверка идёт вручную | `auto_bar_check` | выключена |
| Проверка документа личности (`id_check`) | `IdVerificationProvider`: `stripe_identity` или `persona` | `stripe_identity`, `persona_verification` | выключены |
| Сравнение лица на селфи с фото документа (`face_match`) | тот же `IdVerificationProvider` | те же флаги | выключены |

- Пока платные сервисы выключены, работает режим `manual` (провайдер `manual`): верификатор сам сравнивает документ, селфи и данные лицензии.
- Включение флага в админке (файл 6) переключает проверку на автоматическую **без релиза приложения и без переписывания кода**: за это отвечают интерфейсы и адаптеры, реализации подключаются через DI по значению флага.
- Результат `bar_lookup`: найден/не найден, статус лицензии (active/inactive), имя, дата допуска, ссылка на источник. Результат сохраняется в `attorney_licenses.auto_check_result`.
- Если автопроверка недоступна (ошибка провайдера, штат без адаптера), заявка идёт на ручную проверку, ошибка не блокирует адвоката.

### 2.5 Что делает верификатор (админ-часть, минимально необходимая)
Верификатор работает в админ-панели (оболочка и вход в файле 6). Для верификации нужны:
1. **Очередь заявок:** список со статусами `submitted` и `needs_more_info`, сортировка по давности, фильтр по штату.
2. **Карточка заявки:** профиль адвоката, лицензии (штат, номер, срок, результат автопроверки), документ личности, селфи, история заявок этого адвоката.
3. **Действия:** «Взять в работу», «Подтвердить лицензию» / «Отклонить лицензию» (для каждой), «Одобрить заявку», «Запросить информацию» (текст сообщения), «Отклонить» (причина из списка + комментарий).
4. **Коды причин отказа** (константы + i18n-ключи `verification.reject.<code>`): `license_not_found`, `license_inactive`, `name_mismatch`, `document_unreadable`, `document_expired`, `selfie_mismatch`, `suspected_fraud`, `incomplete_submission`, `other`.
5. Все действия пишутся в `audit_log` (кто, что, когда, до/после).

Дополнительные админ-действия над уже верифицированным адвокатом (доступны `verifier` и `super_admin`):
- **Пере-проверка лицензии** (`recheck`): повторно запускает `bar_lookup` или ставит в очередь на ручную проверку.
- **Приостановка** (`suspend`) с причиной: `verification_status = suspended`. Профиль скрывается из Поиска, кейсы и новые биды недоступны, активные биды переводятся в `withdrawn`, уже принятые кейсы остаются. **Восстановление** (`restore`) возвращает статус `verified`.

### 2.6 Срок действия и повторная проверка
- Если у лицензии указан `expires_at`, ночная джоба переводит её в `expired` в день окончания; за 30 и 7 дней до окончания адвокату приходит уведомление `verification_update` с просьбой обновить данные.
- Кейсы для адвоката определяются только лицензиями со `license_status = 'verified'`, поэтому истёкший или отклонённый штат перестаёт быть доступен автоматически (запрос из файла 2, раздел 5.4, не меняется).
- Если у адвоката не осталось ни одной лицензии в статусе `verified`, профиль переводится в `unverified` и приходит уведомление; нужно подать новую заявку.
- Обновление срока действия лицензии адвокат отправляет новой заявкой (только блок лицензии).

### 2.7 Уведомления по верификации (тип `verification_update`)
Push и запись в «Уведомлениях» при: заявка принята в работу, нужна информация (с текстом), одобрена (полностью или частично), отклонена (с причиной), приближается окончание срока лицензии, лицензия истекла, аккаунт приостановлен или восстановлен. Тексты через i18n-ключи `notif.verification.*`.

## 3. Выбор практик и штатов адвокатом

### 3.1 Штаты
- Штаты определяются лицензиями (`attorney_licenses`). Отдельного выбора штатов, не подтверждённых лицензией, нет.
- Для отображения в профиле и подбора кейсов используются только штаты с `license_status = 'verified'`.
- Пока лицензия в статусе `pending`, штат показывается в редакторе с пометкой «На проверке» и не влияет на видимость кейсов.

### 3.2 Практики
- Доступны **только после `verified`**. До этого экран «Практики» показывает «Доступно после верификации».
- Справочник: дерево из файла 2 (42 категории, специализации). Экран «Мои практики»:
  - поиск по названию;
  - категории списком с раскрытием; в каждой категории кнопка «Выбрать все»;
  - специализации с чекбоксами; выбранные показываются вверху чипами;
  - кнопка «Сохранить».
- Сохранение: `PUT /attorneys/me/practice-areas` с полным списком `practice_area_ids` (замена набора), транзакционно. Сервер отклоняет неактивные и не листовые записи (`is_active = false`, категории).
- Изменения практик вступают в силу сразу (лента «Кейсы» пересобирается), дополнительной проверки не требуется. Изменение пишется в `audit_log`.
- Минимум 1 практика для доступа к списку кейсов: без практик вкладка «Кейсы» показывает призыв выбрать практики.
- Практики в публичном профиле показываются чипами: название специализации; категории с несколькими выбранными специализациями группируются (тап открывает полный список).

### 3.3 Последовательность после одобрения
`approved` → push и экран поздравления → шаг «Выберите практики» (можно пропустить, но «Кейсы» будут пустыми с подсказкой) → шаг «Запустить 7-дневный триал» (файл 6).

## 4. Профиль адвоката (публичный)

### 4.1 Поля (редактируемые самим адвокатом)
| Поле | Правила |
|---|---|
| Фото | квадрат, обрезка в приложении, до 5 МБ, сжатие до 1024 px, формат JPEG/PNG/HEIC; обязательно (деловое фото) |
| Имя, фамилия | 1-50 символов; после верификации изменение имени отправляет профиль на повторную проверку (`pending`), чтобы имя совпадало с документами |
| @username | 3-30 символов, латиница, цифры, `_` и `.`, не начинается и не заканчивается на `.`/`_`, без двух `.` подряд, уникален без учёта регистра, зарезервированные слова запрещены (`admin`, `lawbid`, `support`, `moderator`, `help`, `official` и т.п., список в `app_config`); смена не чаще 1 раза в 30 дней |
| Био | до 300 символов |
| Фирма | до 80 символов, необязательно |
| Языки общения | из списка ISO 639-1, мультивыбор |

Лицензии, штаты и практики редактируются через блоки разделов 2 и 3.

### 4.2 Публичный экран (чужой профиль и свой)
Сверху вниз:
1. Шапка: фото, `@username` + синяя галочка (по правилу 6.3), счётчики **Посты / Подписчики / Подписки**.
2. Карточка рейтинга (золотая): имя и фамилия, звёзды, число отзывов, рейтинг числом. Тап открывает вкладку «Отзывы». Если отзывов нет: пустые звёзды, подпись «Новый — без отзывов», вместо числа прочерк.
3. Чип «Attorney», био.
4. Строки чипов: фирма; практики; штаты лицензий (горизонтальная прокрутка).
5. Кнопки: у своего профиля «Редактировать» и «Поделиться»; у чужого «Подписаться»/«Вы подписаны» и «Поделиться». Кнопки «Написать» нет: чат открывается только из кейса.
6. Вкладки: **Посты** (сетка/список постов адвоката, детали файл 5) и **Отзывы**.
- «Поделиться» формирует ссылку `lawbid.app/lawyer/:username` (deep link из файла 1).
- Кейсы адвоката в публичном профиле **не показываются** (адвокатская тайна), они видны только ему в «Моё».
- Профиль приостановленного (`suspended`) или неверифицированного адвоката из Поиска и рекомендаций скрыт; прямая ссылка на профиль `unverified` показывает профиль без синей галочки, `suspended`: экран «Профиль недоступен».

### 4.3 API профиля адвоката
| Метод | Путь | Описание |
|---|---|---|
| GET | `/attorneys/me/profile` | полный собственный профиль + статус верификации |
| PATCH | `/attorneys/me/profile` | изменить био, фирму, языки, имя, username |
| GET | `/attorneys/username-available?u=` | проверка доступности (rate limit) |
| GET | `/attorneys/:username` | публичный профиль (лицензии только `verified`, счётчики, рейтинг) |
| GET | `/practice-areas` | дерево практик (с i18n), кэш ETag |
| GET | `/attorneys/me/practice-areas` | выбранные практики |
| PUT | `/attorneys/me/practice-areas` | заменить набор практик |

## 5. Профиль клиента (закрытый)

- Профиль клиента **не виден никому**, кроме самого клиента. Запрос чужого профиля клиента возвращает `404`. В Поиске и рекомендациях клиентов нет, подписываться на них нельзя.
- Экран профиля клиента: фото, имя и фамилия, штат. Счётчиков подписчиков нет. Вкладка **«Мои кейсы»**: сетка карточек с иконкой замка и подписью «Видно только вам» (данные из файла 4, здесь только каркас вкладки и пустое состояние «У вас пока нет кейсов»).
- Кнопка «Редактировать»: имя, фамилия, фото, штат, предпочитаемые языки общения, предпочтительный способ связи и заметка о времени (поля из файла 1, шаг 3A).
- Телефон и email клиента меняются только через повторную аутентификацию и код на новый контакт (файл 1, раздел 11); экран «Мои контакты» в настройках показывает подтверждённые контакты и статус.
- Что видит адвокат: до принятия бида ничего из личных данных клиента; после принятия бида и при активной подписке: имя, телефон, email, предпочтительный способ связи (правила выдачи в файле 4).
- API: `GET /users/me/profile`, `PATCH /users/me/profile` (клиент), `PATCH /users/me/contact-preferences`.

## 6. Правила отображения статуса адвоката

### 6.1 Статусы для пользователей
| verification_status | Значок в профиле | В Поиске | «Кейсы» доступны |
|---|---|---|---|
| unverified | нет | да, без галочки | нет |
| pending | нет | да, без галочки | нет |
| rejected | нет | да, без галочки | нет |
| verified | синяя галочка | да | да (по практикам и штатам) |
| suspended | нет | скрыт | нет |

### 6.2 Публичность данных о лицензиях
Публично показываются только штаты подтверждённых лицензий. **Номера лицензий (bar number) публично не показываются** (только верификатору и самому адвокату), файлы документов недоступны никому, кроме верификатора.

### 6.3 Синяя галочка
Ставится, если у адвоката `verification_status = 'verified'` и есть минимум одна лицензия `verified`. Снимается автоматически при потере статуса.

### 6.4 Посты неверифицированных
Публиковать посты в Ленту может только адвокат со статусом `verified` (посты от лица неподтверждённого юриста вводят людей в заблуждение). До верификации кнопка «Пост в ленту» в «+» показывает экран «Пройдите верификацию».

## 7. Отзывы

### 7.1 Кто и когда может оставить отзыв
- Только клиент, чей бид принят, и только после того, как кейс перешёл в статус `closed` (файл 4).
- Один отзыв на один кейс (UQ `case_id`). Отзыв привязан к адвокату, чей бид был принят.
- В `POST /cases/:id/review` сервер проверяет: автор является клиентом кейса, кейс `closed`, есть принятый бид, отзыва ещё нет.

### 7.2 Содержание
- Оценка от 1 до 5 (обязательно), текст до 1000 символов (необязательно).
- Отправка отзыва идемпотентна (`Idempotency-Key`).
- Клиент может отредактировать свой отзыв в течение 14 дней после публикации (`reviews.edited_at`, пометка «Изменено»). После этого срока отзыв неизменяем. Удалить отзыв клиент не может, чтобы нельзя было «стереть» плохую оценку после давления; скрыть/удалить может только модератор (файл 6).
- Адвокат не может удалять или править отзывы. Он может **пожаловаться** на отзыв (`POST /reviews/:id/report`, причины из `report_reason`), жалоба уходит в очередь модерации (файл 6).

### 7.3 Уведомления
- При закрытии кейса клиенту приходит уведомление `review_requested` «Оцените работу адвоката» с действием «Оставить отзыв». Если отзыв не оставлен, через 7 дней приходит одно напоминание того же типа.
- Адвокату при новом отзыве приходит уведомление `review_received`.
- Новые значения `review_requested` и `review_received` добавляются в enum `notification_type` миграцией этапа 3.1 (раздел 10).

### 7.4 Отображение
- Вкладка «Отзывы» в профиле адвоката: сверху сводка (средняя оценка, число отзывов, распределение по звёздам 5→1), ниже список отзывов от новых к старым (cursor-пагинация).
- Карточка отзыва: имя клиента в формате **«Имя + первая буква фамилии»** (например «Anna K.»), звёзды, дата, текст, пометка «Изменено» при необходимости. Аватар клиента не показывается (приватность клиентов).
- Средняя оценка: округление до одного знака (4.5), звёзды с половинками.

### 7.5 Расчёт рейтинга
- `rating_avg` и `rating_count` в `attorney_profiles` пересчитываются **в той же транзакции**, что и создание/редактирование/скрытие/удаление отзыва (учитываются только отзывы `published`).
- Формула: простое среднее по опубликованным отзывам, без взвешивания.
- Ночная джоба сверяет счётчики с реальными данными и исправляет расхождения.

### 7.6 API отзывов
