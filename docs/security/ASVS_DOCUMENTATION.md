## 1. Input rules and business limits

- **Validation.** Every route takes a class-validator DTO; the global `ValidationPipe` runs with `whitelist` + `forbidNonWhitelisted` + `transform` (`apps/api/src/app.setup.ts`), so unknown fields are refused (mass assignment) and types are coerced once. JSON only; NUL characters are refused (`hasNulChar`).
- **Body size.** JSON body limits per route family (`useBodyParsers`, `app.setup.ts`): the general limit, the contacts sync (`CONTACTS_BODY_LIMIT` = 1 MB) and the admin bulk paths (`ADMIN_BULK_PATHS`).
- **Rate limits.** Global per-IP throttler (`apps/api/src/throttler`); per-flow limits in the services (sign-in per identifier / IP / identifier+IP, OTP per identifier and per day, password reset, refresh per chain per hour, phone status, admin step-up 5 per 15 min, admin recovery 5–10 per hour). Anonymous and admin per-minute ceilings are settings (`security.anonymous_rate_limit_per_minute`, `security.admin_rate_limit_per_minute`).
- **Text limits.** Owner-editable text lengths (`apps/api/src/common/app-settings/text-limits.ts`, `@MaxTextChars`).
- **Business limits.** Every threshold the owner can change is an admin setting (`apps/api/src/common/app-settings/app-settings.defaults.ts`, labels in the admin «Настройки»); the security ones are listed in [section 11](#11-security-and-sign-in-settings).
- **Money.** Payments, refunds and ledgers run in transactions with idempotency keys; automatic money movement is off by default (owner rule).
- **CSV exports** neutralise spreadsheet formulas with one helper (`apps/api/src/common/csv/csv-cell.ts`, OWASP CSV Injection).

## 2. Files

- **Types.** Photos `jpeg, png, heic, webp, gif`; documents `pdf, doc, docx, xls, xlsx, ppt, pptx, odt, ods, odp, rtf, txt, csv`; video `mp4, mov, webm` (`apps/api/src/modules/files/upload-limits.ts`). SVG is never accepted as an image.
- **Sizes and places.** Per upload place (`post, reel, case, chat, task, review, avatar, verification, client_badge, support`) in the admin setting `uploads.limits`.
- **Checks.** Declared type against magic bytes (`files/magic-bytes.ts`); pixel-flood guard (sharp `limitInputPixels`); antivirus queue (`files/jobs/file-scan.processor.ts`); object keys are generated by the server; downloads carry an RFC 6266 `Content-Disposition`.
- **Storage.** Public media in Cloudflare R2, video in Bunny, sensitive files (chats, case files, verification documents) in encrypted S3 (STRICT_RULES «Хранение»); uploads go straight to storage by presigned URL, never through the API.

## 3. Authentication paths and controls

Login methods (`LoginMethod` in `apps/api/src/modules/auth/services/login-method-policy.service.ts`) and their admin switch:

| Method | Path | Controls |
|---|---|---|
| `password` | `POST /auth/password/login` | scrypt N=2^16 r=8 p=2 + rehash; per-account and per-IP backoff before the hash; uniform answer and dummy hash for unknown accounts; App Check + challenge after repeated failures; new passwords checked against the 10k common list, HIBP k-anonymity and context words (`security.password_context_words`, zxcvbn-ts) |
| `phone` (SMS code) | `POST /auth/otp/request`, `/auth/otp/verify` | only for registration and «Забыл пароль» (owner rule); HMAC-stored, 6 digits, single use (Lua GETDEL), TTL `OTP_CODE_TTL_SECONDS`, ladder per identifier+IP and a 24 h cap (`auth.otp_global_failure_cap`); App Check (group `sms`) |
| `email` (code / magic link) | `/auth/otp/*` with `channel=email`, magic link | behind the `email_login` flag, off on prod; magic link bound to a device verifier |
| `passkey` | `/auth/passkeys/*` | WebAuthn (phishing-resistant); adding / removing needs re-authentication |
| social: `google`, `apple` | `POST /auth/social` | ID token `aud`, `nonce` issued by the server (`auth.social_nonce_ttl_sec`), max token age (`auth.social_token_max_age_sec`), `email_verified`, no auto-link by e-mail |
| `qr` (web sign-in from the phone) | `/auth/qr/*`, socket `/qr` | the phone approves; status only over the socket, never a token |
| admin | `/admin/auth/*` | login + password, then TOTP (or a recovery code, or a passkey) — mandatory; IP allowlist; 8 h absolute session; recovery of the super admin only with the authenticator / recovery code, then the secret question (O2) |

Common: new-device and sign-in-change notifications; «Это был не я» ends every session; `/auth/phone/status` has the sign-in challenge and a uniform answer time (`security.phone_status_min_ms`, O4); re-authentication (a fresh `X-Reauth-Token`, 5 min, single use, or a sign-in within 10 min) before changing credentials, adding sign-in methods, removing passkeys, deleting the account.

## 4. Sessions

- **Access token:** HS256 JWT, 15 min (`JWT_ACCESS_TTL_SECONDS`), `iss`/`aud`/`typ` per token type, `kid` from a fixed key set; per-request blacklist of ended sessions.
- **Refresh token:** opaque, stored as a hash, rotated on every use with reuse detection (the whole chain ends); inactivity limit `JWT_REFRESH_TTL_DAYS` (60 days after the last use); absolute chain lifetime is the admin setting `auth.session_absolute_days` (see STAGE2_SECURITY #13; 0 = off).
- **Web:** the refresh token lives in the HttpOnly `__Secure-lb_rt` cookie (path `/api/v1/auth`, SameSite=Strict); the admin JWT in `__Host-lawbid_admin` (8 h).
- **Concurrency:** one phone session and one website session per account (a new sign-in of the same kind ends the other, `signed_in_elsewhere`); the admin sees and ends a user's sessions; the user sees sessions and ends one or all others.
- **Ending:** logout, logout-all, logout-others, «Это был не я», password change (other sessions end), password reset (all end), ban / deletion (all end).

## 5. Authorization

- Every route is authenticated by the global guard unless marked `@Public()`; roles (`client`, `attorney`, `admin`) and, for staff, admin roles + per-area permissions (`apps/admin/src/lib/rbac.ts` mirrors the server's `admin-permissions`).
- Object level: policies per resource (`files/files.policy.ts`, `file-access.service.ts`, case participants, chat membership); the matrix is tested end to end in `apps/api/test/authz-matrix.e2e-spec.ts`.
- Field level: DTO presenters return only the needed fields; secrets never leave the server.
- Admin: separate host, IP allowlist, TOTP + passkey, a fresh 2FA step-up for sensitive actions (`admin.step_up_ttl_seconds`), every action in the hash-chained audit journal. No second-admin approvals (owner decision).

## 6. Cryptographic inventory

| Key / secret | Algorithm / mode | Used for | Rotation |
|---|---|---|---|
| `MESSAGE_ENC_KEYS` + `MESSAGE_ENC_ACTIVE_KID` | AES-256-GCM, random 96-bit IV, AAD | message texts and edits, chat file names, case «Личные данные», optional journal text | new `kid` once a year (`docs/runbooks/KEY_ROTATION.md`) |
| `SECRETS_MASTER_KEYS` + `SECRETS_ACTIVE_KID` | AES-256-GCM envelope (`common/secrets/secret-envelope.ts`) | integration keys from the admin, assistant codes, bar-registry keys, admin TOTP secrets | as needed, same way |
| `ADMIN_TOTP_ENC_KEY` | AES-GCM (legacy `v1` format) | old admin TOTP secrets only | keep while `v1` rows exist |
| `JWT_KEYS` + `JWT_ACTIVE_KID` | HMAC-SHA256 (HS256 only) | access / reauth / admin tokens | new kid by hand, old kept for the token lifetime |
| `OTP_CODE_SECRET`, `OTP_KEY_PEPPER` | HMAC-SHA256 | one-time codes and their keys | with the secrets rotation |
| `AUTH_EVENT_PEPPER`, `CONTACTS_PEPPER` | HMAC-SHA256 | identifiers in the auth journal, phone-book hashes | with the secrets rotation |
| user passwords | scrypt N=2^16, r=8, p=2, 16-byte salt | sign-in | rehash on the next sign-in when weaker |
| admin passwords, secret answers | scrypt (`admin-password.util.ts`) | admin sign-in, recovery | — |
| refresh tokens, reauth tokens, recovery codes, invite / feed tokens | SHA-256 of a CSPRNG value | stored as hashes only | — |
| TLS | TLS 1.2+ (`ELBSecurityPolicy-TLS13-1-2-2021-06`, CloudFront TLSv1.2_2021); Redis `rediss`; PostgreSQL `verify-full` against the RDS global CA bundle baked into the images | all traffic | ACM / RDS managed |
| `EDGE_ORIGIN_SECRET` | constant-time compare | CDN → API origin header | with the secrets rotation |
| `HEALTH_DETAIL_TOKEN` | constant-time compare | detail of `/health/ready` | with the secrets rotation |
| TURN REST credentials | HMAC-SHA1 (RFC 5389 / TURN REST API) | relay logins (minutes) | static auth secret in SSM |

CSPRNG: `crypto.randomBytes` / `randomInt`; `Math.random` only for jitter and sampling. SHA-1 / MD5 only where a protocol demands it (HIBP range, ETag, uuid v5, TURN long-term key). Keys are moved from `process.env` into memory at start (`common/secrets/key-holder.ts`).

## 7. Outbound communication

| Destination | Why | Guard |
|---|---|---|
| AWS (S3, KMS, SES, Secrets Manager, CloudWatch, ECS, RDS) | storage, keys, mail, ops | IAM task roles |
| Cloudflare (R2, Calls / TURN, Turnstile) | public media, calls, bot check | API tokens in secrets |
| Bunny Stream | video | API key |
| Stripe | payments | signed webhooks |
| Persona | identity verification | webhook signature + timestamp tolerance |
| Twilio / SMS provider | codes (two cases only) | spend caps |
| Google / Apple | sign-in token keys | `aud`, nonce |
| Firebase (FCM, App Check) | pushes, app attestation | service account |
| Pwned Passwords (HIBP) | breached passwords | k-anonymity, 5 hex chars only, timeout |
| Sentry | errors, CSP reports | scrubbing (`telemetry/scrub.ts`) |
| link previews, bar registries | user-given URLs | SSRF-safe fetch (`link-preview/safe-fetch.ts`: DNS checked on the socket, private ranges refused, 3 redirects, 1 MB, 5 s) |

Outbound `fetch` calls share the sockets of `common/http/outbound-agent.ts`. Every AWS SDK client (S3, R2, SES, Rekognition, KMS, CloudWatch, ECS and the other ops clients) passes a shared time limit from `common/http/aws-request-handler.ts` (connect 3 s; API calls end in 10 s, storage gives up after 30 s idle); `src/architecture/aws-client-timeouts.spec.ts` fails on a client without one. Browsers may call only the hosts in the CSP `connect-src` (web: `infra/modules/web/main.tf`; admin: `apps/admin/src/lib/csp.ts`).

## 8. Data classification

| Class | Examples | Where | Protection |
|---|---|---|---|
| Secret | keys, password / answer hashes, TOTP secrets, refresh hashes, integration secrets | Secrets Manager, encrypted columns | never returned by the API; Prisma reads them only on purpose |
| Sensitive (attorney–client) | chats, case files and private details, verification documents, payments | encrypted S3, AES-GCM columns, RDS encrypted at rest | `Cache-Control: private, no-store`; access by participants only; audit |
| Personal | names, phone, e-mail, profile | RDS | masked for staff (`admin-pii-mask`), reveal audited and capped |
| Public | public profiles, posts, reviews, avatars, SEO pages | R2 / CDN | `public` cache only for credential-less requests |

## 9. Dependencies and remediation

- Inventory: CycloneDX SBOMs of `package-lock.json` and `apps/mobile/pubspec.lock`, SPDX SBOMs and BuildKit provenance of every image, GitHub build-provenance attestations (`.github/workflows/deploy.yml`).
- Scanners: Dependabot (7-day cooldown), `npm audit` gate (high and critical block), osv-scanner, CodeQL, gitleaks, Trivy on the shipped image digest (critical blocks the deploy).
- Time frames: critical — fixed before the next deploy (the gates block); high — within 7 days; moderate / low — with the next dependency update round; every major version update before release (owner rule «latest stable versions»).
- Dangerous functionality: no `eval` / dynamic code in the API; Swagger off in production; debug routes only in development (`DevModule`).
