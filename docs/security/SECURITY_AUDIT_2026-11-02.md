# Аудит безопасности LawBid — 02.11.2026

Репозиторий публичный, прод не трогали. Всё проверено **чтением кода и запуском сканеров в облаке**; на живом сервере и на телефонах ничего не проверялось. Слово «факт» ниже значит, что я видел это в коде или в выводе команды. «Предположение» значит, что вывод сделан по логике и на проде не проверен.

Всё, что можно исправить без больших обновлений, исправлено в этом PR.

## Проверено и чисто (факт: код прочитан)

- Все маршруты по умолчанию закрыты глобальным `JwtAuthGuard`. Все ~70 публичных (`@Public`) просмотрены по списку; разобраны вебхуки Stripe, Bunny, LiveKit, Twilio (подпись), SES/SNS (подпись и разрешённые адреса, `redirect:'error'`), `infra/workflow` (OIDC-токен GitHub, проверка репозитория, файла workflow и ветки main), `alarm-events` (токен), `push-actions`, `app-events`, календарь (секретная ссылка и подписанные ссылки), демо-коды (10 попыток за 10 минут на IP).
- Админка: каждый admin-контроллер имеет `@AdminEndpoint`, охранник проверяет аудиторию токена, сессию в Redis, роль из БД на каждый запрос, наличие 2FA.
- Токены: HS256 закреплён, аудитории разведены по типам, повторное использование refresh-токена убивает цепочку.
- QR-вход, OTP, загрузки (magic bytes, SHA-256, антивирус, квоты), чат (каждый доступ идёт через проверку участника), сокеты (`conversation:join`, `channel:watch`, `presence:watch` — с проверками).
- SQL: все `$queryRawUnsafe` с параметрами или проверенным именем; `Prisma.raw` только на константах. ValidationPipe с `whitelist` и `forbidNonWhitelisted`. helmet, CORS по политике, `trust proxy` задан.
- SSRF: превью ссылок идёт через `safe-fetch` с проверкой адреса на уровне сокета и перепроверкой при каждом редиректе.
- CI: все действия закреплены по SHA, нет `pull_request_target`, в `run:` нет подстановки пользовательского текста.
- Terraform: открыты в мир только ALB, TURN и LiveKit; у TURN есть `denied-peer-ip`, `no-cli`, `no-tcp-relay`; IMDSv2 везде; БД не публичная и зашифрована; `*` в IAM — только там, где AWS не поддерживает ограничение по ресурсу (метрики, Cost Explorer, X-Ray).
- Flutter/Android/iOS: токены в `flutter_secure_storage`, `allowBackup=false`, нет cleartext, только системные сертификаты, экспортированные компоненты Android защищены разрешением FCM.
- Секреты в репозитории: поиск по дереву и по **всей истории** (3994 коммитов всех веток, шаблоны AWS/Stripe/GitHub/Slack/Google/приватные ключи) — ничего настоящего, только заглушка `AKIAABCDEF…` в тексте документа. Про засвеченный TURN-секрет (скриншот) в репозитории следа нет; ротация остаётся задачей владельца.

## Повторное сканирование зависимостей (02.11, вечер, после #567 и #608)

Факт (запущено в облаке):
- **API, только продакшен-зависимости** (`npm audit --omit=dev --workspace apps/api`): critical 0, high 3 (`prisma`, `@prisma/config`, `deepmerge-ts`; это один совет GHSA-ggr8-5vv4-36mx, только в CLI Prisma при миграциях, не в работающем API; в списке исключений до 2027-01-31, лечится мажором Prisma 7), moderate 17. Все moderate лежат в цепочках, где npm предлагает только мажорное обновление (`archiver`/`exceljs`/`uuid`/`minimatch`/`glob`, `@sentry/nestjs`, `@nestjs/swagger` → `js-yaml`) или сидят во вложенных копиях (`gaxios`, `gcp-metadata`, `google-gax`, `rimraf`, `zip-stream`). `npm audit fix` без `--force` ничего безопасного не меняет, обходить правило «пакет моложе 7 дней» не стали.
- **Админка**: после #608 high и critical нет (`npm-audit-gate --workspace apps/admin`: 0). Остаются moderate в `minimatch` линтера и тестов.
- **CI**: раньше гейт стоял только у API. Теперь тот же гейт (с тем же списком исключений) стоит и в `admin-ci.yml`, поэтому новые high/critical в админке сломают сборку, а не пролежат незамеченными.

Не проверено (честно): зависимости Flutter. `api.osv.dev` из облака недоступен, SDK Dart/Flutter в облаке нет, поэтому `pubspec.lock` не сканировали. Эту работу уже делает CI: блокирующий шаг `Dependency audit (OSV, blocking)` в `mobile-ci.yml` (OSV-Scanner по `pubspec.lock` + `pub-audit-gate`, исключения в `.github/pub-audit-allowlist.json`). Его последний результат смотреть там, а не в этом отчёте.

## Не проверено (честно)

- Прод: настройки в админке, правила WAF (не трогаем по решению владельца), реальные права IAM в AWS, открытые порты на живом аккаунте.
- Зависимости Flutter (`pub`): сканер не запускали, SDK в облаке нет. Есть CI-гейт `pub-audit-gate`.
- IDOR: 193 контроллера — прочитаны выборочно самые чувствительные (чат, файлы, сокеты, админка, вход). Остальные не просматривались построчно. Стоит один раз прогнать сценарные e2e «чужой id» на отдельном стенде.
- Нагрузка и DoS: отдельный поток (ноут владельца).
- `/code-review high` и `/security-review` по готовому diff прогнаны на обоих PR (#567, #608), находок высокой уверенности нет.
