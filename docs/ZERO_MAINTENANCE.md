# Сервер без обслуживания — что делает система сама

Владелец 2026-10-05: «я не понимаю серверы и базы — пусть всё работает
само; если что-то сломается, я не справлюсь». Ниже — всё, что защищает
LawBid, и кто за что отвечает. Письма и кнопки: [runbooks/OWNER.md](runbooks/OWNER.md).

## Падения и перезапуски

| Что | Как | Где в коде |
|---|---|---|
| Упал сервер приложения | AWS проверяет `/health/live` каждые 15 с, заменяет за ~1 мин | `infra/modules/ecs` (healthCheck) |
| Завис обработчик фоновых задач | Пишет «пульс» каждые 30 с; нет пульса 2 мин — AWS его заменяет | `src/jobs/jobs.runner.ts`, `infra/modules/ecs` |
| Задача упала посреди работы | BullMQ возвращает «застрявшие» задачи в очередь, 3 попытки с паузой | `src/jobs/jobs.runner.ts` |
| Неудачное обновление | Откат на прошлую версию сам (circuit breaker) + кнопка Rollback | `infra/modules/ecs`, `.github/workflows/rollback.yml` |
| Отказ зоны AWS / Redis | Redis с репликой переключается сам (полный размер); на запуске — замена узла | `infra/modules/redis` |
| Redis переполнен | `noeviction`: задачи никогда не теряются молча; тревога на 80 % | `infra/modules/redis`, `monitoring` |

## База данных

| Что | Как |
|---|---|
| Копии и восстановление | Управляемый PostgreSQL: автоматические копии и восстановление на любую минуту (PITR); проверка свежести каждый час (`ops.backup-check`) и перед каждой миграцией |
| Перегрузка соединениями | Не больше `DB_POOL_SIZE` (10) соединений на копию сервера, ожидание 10 с (`src/prisma/prisma.service.ts`) |
| Зависший запрос | Лимиты на стороне базы: 30 с на запрос приложения (`infra/postgres/role-settings.sql`) |
| Конфликты записи | Повтор транзакции сам (`src/prisma/tx-retry.util.ts`) |
| База медленная | Тяжёлые пересчёты сами на паузу 15 мин (`ops.guard`, выключатель в админке) |
| Опасная миграция | CI не пропустит удаление/переименование столбца без двухшаговой схемы (`apps/api/scripts/check-migrations.mjs`) |
| Учебное восстановление | Раз в квартал, `scripts/ops/restore-drill.sh`; самопроверка напоминает |

## Нагрузка и деньги

| Что | Как |
|---|---|
| Наплыв людей | Сервер растёт сам (CPU 60 % и запросы на копию), за минуту |
| Не «дёргаться» | Убирает мощность не раньше 10 мин спокойствия |
| Большой счёт | Бюджет AWS: письма 50/80/100 %, на 100 % — минимум до конца месяца (`ops.cost-check`) |
| Странный рост расходов | AWS Cost Anomaly Detection: ежедневное письмо, если сервис подорожал на $20+ |
| Платные сервисы (SMS, почта, видео) | Лимиты в минуту/день/месяц (`docs/COST_PROTECTION.md`) |
| Атаки | WAF + лимиты запросов (`infra/modules/alb`, throttler) |

## Тревоги и проверки

- 22 тревоги CloudWatch; каждое письмо начинается с «LawBid: что случилось. Что делать: … Инструкция: ссылка».
- Каждое утро GitHub «Self-check»: API, тревоги, подписка на почту, бюджет, сервисы, бэкап, учебное восстановление.
- Админка → Система → **Здоровье системы**: светофор по API, фоновым задачам, базе, Redis, файлам, видео, очередям, бэкапам и расходам + кнопки.
- Без платных сервисов мониторинга: только AWS и открытый код.

## Делается при «ставь на AWS»

1. `terraform apply` (создаёт бюджет, тревоги, права кнопок, проверку пульса).
2. Выполнить `infra/postgres/role-settings.sql` на боевой базе (`psql`).
3. После выбора хостинга базы: ключ только для чтения — в админку → Ключи и сервисы → Хостинг базы данных (проверка свежести бэкапа).
4. В кабинете хостинга базы: лимит расходов (если есть) и его письма об авариях.
5. Подтвердить письмо подписки на тревоги; `DEPLOY_ENABLED=true` включит самопроверку.
