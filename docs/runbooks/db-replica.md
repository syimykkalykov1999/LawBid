# Копия базы для чтения (read replica)

Выключено по умолчанию. Два независимых способа, оба не меняют ничего, пока не включены.

## Способ 1: кнопка в админке (рекомендуется)

Нужно один раз в Terraform: `db_replica_toggle = true` (prod `variables.tf`) и `terraform apply` владельцем. Это добавляет только права API на ОДИН экземпляр `<база>-readreplica` и маленькую роль мониторинга. Базу не создаёт.

«Масштаб» → «Копия базы для чтения» → «Включить» (2FA, затем второй админ подтверждает). AWS создаёт копию 15-30 минут. Карточка показывает: Создаётся / Включено / Отстаёт / Удаляется / Ошибка, отставание в секундах.

Как приложение ей пользуется (само, без выката):

- читает из копии только поиск, профили, ленты (то, что и так может быть на секунды старым: `PrismaReadService.db`);
- начинает, когда копия `available` и отстаёт не больше 10 с; прекращает при отставании больше 30 с;
- если копия исчезла, создаётся, удаляется, сломалась или отстала, чтения сами идут в основную базу;
- запись и чтение собственных записей человека всегда в основной базе;
- рубильник без Terraform: переменная окружения `DB_REPLICA_ENABLED=false`.

«Выключить» удаляет копию (приложение уже читает из основной базы).

Почему не Lambda и не Terraform: создание копии делает сам RDS, ждать процессу нечего; ответ «что сейчас» кэшируется в Redis на 25 секунд (70 задач делают около двух запросов к AWS за полминуты). Terraform эту копию не знает (она создана вне его состояния), поэтому `terraform apply` её никогда не пересоздаёт и не удаляет. Копии из `growth.rds_read_replicas` называются иначе (`-replica-N`), не конфликтуют.

Защиты от удаления у копии нет намеренно: её удаляет кнопка, а кнопка требует 2FA и второго админа.

## Способ 2: через Terraform (growth)

`growth = { rds_read_replicas = 1 }`: создаёт копию с тем же ключом KMS, группой параметров (`rds.force_ssl`, медленные запросы), Performance Insights, мониторингом 60 с, защитой от удаления (как у основной базы, если база наша), и тревогой `ReplicaLag` (> 60 с 10 минут, письмо). Приложение получает `DB_REPLICA_HOST` и строит адрес из `DATABASE_URL` (тот же пользователь и пароль). Секрет заполнять не надо.

Не включайте оба способа сразу: два разных адреса копии.

## Автомасштабирование базы и копия

Пока у основной базы есть копия, автомасштабирование (`docs/architecture/DB_AUTOSCALE.md`) НЕ меняет её размер: функция видит `ReadReplicaDBInstanceIdentifiers`, пишет причину `has_replicas` и раз в неделю шлёт письмо. Копии нужен `max_connections` не меньше, чем у основной, поэтому размер меняется вручную вместе. Кнопка создаёт копию того же класса, какой у основной базы сейчас.

## Шарды

Копия повторяет только основную базу (семью G, `DATABASE_URL`). Если задан `DATABASE_URL_SHARDS` или запрос привязан к другой физической базе, чтения идут из её основной базы. Копии на каждую шард-базу не построены.

## Если копия «Отстаёт» долго

1. Смотрите нагрузку записи на основной базе (`ops/db-contention`) и размер копии.
2. Чтения уже идут из основной базы. Ничего срочного.
3. Если не проходит: «Выключить», потом «Включить» (новая копия, класс по текущей основной).
