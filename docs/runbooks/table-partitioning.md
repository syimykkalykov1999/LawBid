# Разделение таблицы по месяцам: инструкция

Устройство и замеры: `docs/architecture/TABLE_PARTITIONING_READY.md`.

## Ничего не делать, пока

Миграции ничего не делят и не блокируют (только добавляют функции обслуживания). `audit_log`, `auth_events` и `data_access_log` делятся по месяцам только кнопкой ниже (онлайн-ранер), когда таблица выросла. После этого ночная задача `partition.maintain` (02:40 UTC) создаёт два месяца вперёд. Проверка: админка «Масштаб», карточки «по месяцам: да (N кусков)».

## Разделить ещё одну таблицу кнопкой

1. Один раз: создать роль базы, владеющую этой таблицей (`lawbid_partition`), положить URL в секрет `PARTITION_DATABASE_URL` (`extra_secrets` в Terraform), выкатить. Без него карточка только показывает состояние.
2. «Масштаб» → карточка таблицы → «Запустить» (один код 2FA, второй админ не нужен).
3. Идёт в фоне. Прогресс на карточке. «Пауза» / «Продолжить» в любой момент. «Остановить» до переключения: копия удаляется, исходная таблица не менялась.
4. Ошибка шага: на карточке текст, кнопка «Повторить шаг». После трёх подряд ошибок задача ждёт руки.
5. После переключения 7 дней хранится старая копия, обратный триггер держит её полной: «Вернуть как было» (быстро, один код 2FA). Потом «Завершить»: старая копия удалена навсегда, откат кнопкой невозможен.

Нужно свободного места примерно 1,1 от размера таблицы на время работы и 1 размер таблицы до «Завершить».

## То же из командной строки

```
export PARTITION_DATABASE_URL=...            # роль-владелец
node dist/src/cli/partition-table.js plan data_access_log       # сухой прогон, ничего не пишет
node dist/src/cli/partition-table.js start data_access_log --yes
node dist/src/cli/partition-table.js tick                       # или ждать задачу partition.tick
node dist/src/cli/partition-table.js status data_access_log
node dist/src/cli/partition-table.js pause|resume|abort data_access_log
node dist/src/cli/partition-table.js undo data_access_log --yes
node dist/src/cli/partition-table.js finalize data_access_log --yes   # --force раньше 7 дней
```

Без `--yes` команды `start`, `undo`, `finalize` только печатают план.

## Если что-то пошло не так

- Переключение (swap) не берёт блокировку за 3 секунды: оно само повторится на следующей минуте, таблица в это время работает.
- Колонки старой и новой таблицы разошлись (была миграция во время копирования): ошибка «колонки разошлись». «Остановить» и начать заново после миграции.
- Куски закончились (задача не работала > 2 месяцев): строки падают в запасной кусок `<таблица>_default`, ничего не теряется. `SELECT lawbid_ensure_month_partitions('audit_log', 2)` создаст месяцы; если строки месяца уже в запасном куске, PostgreSQL откажет: перенести их вручную.
- Срок хранения: `PARTITION_RETENTION_MONTHS` в `partition.service.ts` (пусто = не удаляем). Отцепленные куски остаются таблицами `<таблица>_pГГГГ_ММ`; архивировать и удалять руками.
