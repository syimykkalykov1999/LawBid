# Redis: переход на кластер (шарды)

Когда нужен: Redis упёрся в потолок самого большого узла (память) или в одно ядро (EngineCPU > 70 % на r7g.xlarge+), см. [REDIS_AUTOSCALE.md](../architecture/REDIS_AUTOSCALE.md) §3. Раньше не нужен: кластер дороже и сложнее.

Код готов, переключатель выключен. Что внутри и откуда взято: [REDIS_CLUSTER_READY.md](../architecture/REDIS_CLUSTER_READY.md).

## Переключатель владельца

Одна строка в `terraform.tfvars` (prod):

```
redis_cluster_mode = "standby"   # 1) построить кластер рядом, приложение его не трогает
redis_cluster_mode = "on"        # 2) приложение переходит на кластер
```

Флаг приложения (`REDIS_CLUSTER=true`) и адрес (`REDIS_URL`) переключаются из этой же строки одним применением. Размер: `redis_cluster_shards` (по умолчанию 2), `redis_cluster_replicas_per_shard` (1), `redis_cluster_node_type` (пусто = как `redis_node_type`).

Применяет только владелец, кнопкой Run на сохранённом плане. После правки tfvars загрузите копию в Secrets Manager `lawbid-prod/terraform-tfvars`.

## Безопасный порядок (новый кластер рядом, старый остаётся)

1. **Подготовка (без риска).** Убедитесь, что деплой с кодом cluster-ready уже на проде (ветка `claude/redis-cluster-ready`), и `redis_cluster_mode = "off"` не менялся. Тест `redis-cluster-scan.spec.ts` зелёный в CI.
2. **Построить кластер: `standby`.** Поставьте `redis_cluster_mode = "standby"`, сделайте план, проверьте, что создаются только `…-redis-cl`, группа параметров `…-redis7-cluster` и секрет `…/REDIS_CLUSTER_URL`. Нажмите Run. Старый Redis и приложение не меняются. Создание занимает 15–30 минут.
3. **Проверить кластер.** В AWS → ElastiCache группа `…-redis-cl` в статусе `available`, режим кластера включён, шардов столько, сколько в tfvars. (По желанию: разовая задача ECS с `REDIS_CLUSTER=true` и `REDIS_URL` из `REDIS_CLUSTER_URL` и пробой `PING`.)
4. **Окно переключения** (ночью по США, вне деплоя ECS): очереди в Redis — не данные, их нельзя перенести. Поэтому:
   - админка → Масштаб → поставить тяжёлые задачи на паузу;
   - дождаться, пока очереди опустеют (админка → Здоровье системы → очереди = 0, не меньше 5 минут подряд). Stripe-вебхуки и push досчитаются; что не успело, потеряется только как задание (источник правды — база);
   - **Redis не источник правды**: кэши, лимиты, OTP-попытки и сессии админов начнут с нуля. Админов попросит войти заново (один раз), коды OTP в полёте надо запросить заново.
5. **Переключить: `on`.** `redis_cluster_mode = "on"`, план, Run. Terraform подставит `REDIS_URL` (адрес конфигурации кластера) и `REDIS_CLUSTER=true` в API и воркер, ECS сделает обычное плавное обновление. Сокеты переподключатся сами.
6. **Проверить** (первые 15 минут): `/health` зелёный, админка → Здоровье системы без красного, push и чаты доходят, в логах нет `CROSSSLOT` / `MOVED` ошибок, очереди работают (воркер забирает задачи). Снять паузу тяжёлых задач.
7. **Откат** (пока старая группа жива): `redis_cluster_mode = "standby"`, план, Run; приложение вернётся на старый Redis (он работал всё время и свободен). Очереди и кэши снова начнут с нуля.
8. **Через неделю без проблем.** Старая группа ещё нужна LiveKit; удаляйте её только после переноса LiveKit. Автомасштаб Redis при `on` отключается (его лесенка не для кластера).

## Менять размер кластера потом

Шарды и тип узла меняются в AWS онлайн (ElastiCache → группа → Изменить число шардов / тип узла; terraform эти поля не откатывает, `ignore_changes`). Данные между шардами переезжают сами (онлайн-решардинг). Не делайте это во время деплоя ECS.

## Если что-то пошло не так

- В логах `CROSSSLOT`: найдена команда с ключами из разных слотов. Откат по шагу 7, напишите Claude «CROSSSLOT» и приложите строку лога.
- Сокеты не доходят между серверами: проверьте, что у API и воркера одинаковый `REDIS_CLUSTER` (адаптер при `true` принудительно шардированный).
- Нельзя вернуть кластерную группу обратно в обычную: откат всегда на старую группу.
