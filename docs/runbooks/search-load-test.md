# Search under load (2026-10-15)

Run on a local PostgreSQL 16 (Docker) with **500 000 users, 2 000 000 posts, 1 000 000 cases**
(generated by `scripts/ops/search-load-gen.sql`), the app and Redis on the same Mac.

```sh
# 1. a migrated empty database, then the generator (about 10 minutes)
psql "$DB" -f scripts/ops/search-load-gen.sql
# 2. the latency table (needs PERF_SEARCH=1; E2E_DATABASE_URL points at that database)
PERF_SEARCH=1 E2E_DATABASE_URL="$DB" npx jest --config apps/api/test/jest-perf.json --forceExit
```

## Before (plainto_tsquery, no ordered index) — SQL time, warm machine
| query | before |
|---|---|
| posts, common word ("immigration") | 1.9–3.3 s (reads all 2M posts) |
| posts, two words | 2.2–2.7 s |
| cases, common word | 1.5 s |
| rare word | 25–60 ms |

## After (weights + prefix + ordered partial index + time budget) — HTTP, first call (cold) / repeat (cached 5 min)
| endpoint | cold | warm p50 |
|---|---|---|
| posts: common / rare / two words | 245 / 147 / 144 ms | 9–11 ms |
| posts: prefix ("immigr") / typo / handle | 21 / 314 / 191 ms | 7–8 ms |
| posts: words nobody wrote | ≤ 2.1 s (3 attempts × 700 ms budget) | 6 ms |
| cases: common / two words / prefix / typo | 510 / 399 / 213 / 726 ms | 3–5 ms |
| people (@handle, name, filters) | 5–65 ms | 2–5 ms |
| suggest | 2–8 ms | 1–2 ms |

What made the difference: the partial index `posts_published_created_idx` (the planner read the whole table
for a common word: 2.3 s → 7 ms), whole words tried before prefixes (the planner estimates them well), and a
700 ms database budget per attempt (a prefix nobody has can no longer walk millions of rows).

## Limits and the way up
- Cases are visible per attorney (state × practice pairs); a very broad licence set with a common word can
  take 0.5–1 s cold. The ranked ids are cached for 5 minutes per attorney and filter set.
- Beyond tens of millions of rows: put OpenSearch / Meilisearch behind `SearchProvider` (the interface exists;
  switch with a flag), fed from an outbox table by the worker. Postgres stays the fallback.
