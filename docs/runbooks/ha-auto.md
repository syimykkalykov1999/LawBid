# Вторая копия базы и запасной узел Redis: сами включаются и выключаются (2026-11-02)

Решение владельца: пока людей мало, платить за вторую копию базы (Multi-AZ, ≈ $14/мес) и запасной узел Redis (≈ $12/мес) не нужно. Они **добавляются при росте и убираются при спаде сами**, без правок кода, консоли AWS и терминала.

## Как работает

Раз в 10 минут один из серверов API смотрит, сколько людей онлайн (открытые соединения, метрика `OpenSockets`, среднее за час). Настройки в админке → Настройки:

| Настройка | По умолчанию | Смысл |
|---|---|---|
| `ha.mode` | `auto` | `off` — не трогать, как есть; `on` — копии держать всегда (добавить, если нет, и не убирать); `auto` — по нагрузке |
| `ha.provision_online_users` | 200 | сколько человек онлайн в среднем нужно **3 часа подряд**, чтобы добавить копии; 0 = по нагрузке никогда не добавлять |
| `ha.release_days` | 7 | сколько суток подряд онлайн должен быть **меньше половины порога** (100), чтобы копии убрать |

Защиты от «дёргания»:
- Убирать можно, только если данные есть минимум за 90 % часов окна. Нет данных (метрика пропала, сервер перезапускался) — ничего не убираем.
- Шаг в обратную сторону — не раньше чем через 24 часа после предыдущего.
- Пока AWS занят ресурсом (изменение ещё идёт), шаг ждёт.
- У Redis два шага в каждую сторону: добавить — узел, потом автопереключение; убрать — выключить автопереключение, потом узел.

Пока копий нет, автоматический рост **размера** базы и Redis стоит на паузе и присылает письмо (смена размера одиночной базы даёт простой на минуты). После включения копий рост работает сам.

## Что будет сразу после выкладки

Сейчас обе копии включены (проверено на проде 02.11). Автомат уберёт их **не раньше чем через 7 суток** после выкладки: ему нужны данные за неделю (метрика `OpenSockets` появляется с этой выкладкой), а при их отсутствии он ничего не убирает. Если 7 суток людей онлайн меньше 100, копии уберутся сами; до этого платим как сейчас. Хотите убрать сразу, один раз вручную: `ha.release_days` не ускорит; нужны команды ниже.

Единственный разовый `terraform apply`: `database_multi_az = false`, `redis_replicas = 0` (значения в tfvars), право `elasticache:IncreaseReplicaCount` / `DecreaseReplicaCount`, и автомасштаб Redis создаётся и без запасного узла. Сам apply копии не убирает: Terraform узлы Redis больше не сравнивает.

## Простой, честно (из документации AWS; на нашей базе не проверено)

- **Включение** Multi-AZ у существующей базы: без остановки, но на время создания копии (минуты, у больших баз дольше) возможна просадка скорости диска. Добавление узла Redis: без остановки.
- **Выключение** Multi-AZ: AWS заявляет без остановки. Уменьшение узлов Redis: сначала выключается автопереключение, затем узел удаляется; приложение это не перезапускает.
- **Пока копий нет и падает зона AWS**: база одна, восстановление из резервной копии от десятков минут до нескольких часов, последние секунды данных могут пропасть. Redis: узел заменяется за минуты, очереди и временные данные теряются. Это осознанный риск до появления людей; при росте копии включатся сами.
- Автомат не может включиться мгновенно: нужны 3 часа подряд выше порога и ещё 20–40 минут на создание копии. Резкий всплеск за час копий не добавит.

## Вручную (необязательно)

Убрать сейчас, не дожидаясь недели:
```
aws rds modify-db-instance --db-instance-identifier lawbid-prod-postgres --no-multi-az --apply-immediately
aws elasticache modify-replication-group --replication-group-id lawbid-prod-redis --no-automatic-failover-enabled --no-multi-az-enabled --apply-immediately
aws elasticache decrease-replica-count --replication-group-id lawbid-prod-redis --new-replica-count 0 --apply-immediately
```
(автомат после этого на 24 часа не включит обратно; если ждёте людей, поставьте `ha.mode` = `on`). После включения копий в `terraform.tfvars` вернуть `database_multi_az = true`, чтобы проверка плана молчала.
