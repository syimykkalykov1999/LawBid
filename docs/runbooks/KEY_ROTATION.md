# Ключи шифрования: что где лежит и как менять

Для владельца: пошаговая инструкция с названиями кнопок в AWS есть в админке, раздел «Руководства» → «Раз в год менять ключи шифрования и включить проверенное шифрование до базы». Ниже коротко, что устроено.

## Где лежат ключи

| Переменная | Для чего | Менять |
| --- | --- | --- |
| `MESSAGE_ENC_KEYS` + `MESSAGE_ENC_ACTIVE_KID` | тексты сообщений, имена файлов в чатах, «Личные данные» дел, свободный текст журнала (если включён) | раз в год, новым `kid` (`m1` → `m2` …) |
| `SECRETS_MASTER_KEYS` + `SECRETS_ACTIVE_KID` | ключи интеграций из админки, коды помощников, ключи реестров адвокатов, секреты аутентификаторов админов | по необходимости, тем же способом |
| `ADMIN_TOTP_ENC_KEY` | старый формат секретов аутентификатора админов (`v1`) | не менять, пока в базе есть строки `v1` |
| `JWT_KEYS` + `JWT_ACTIVE_KID` | подпись токенов | вручную, новый kid, старый оставить на срок жизни токенов |

С 2026-10-25 при старте API и worker ключи копируются в память процесса и **удаляются из `process.env`** (`src/common/secrets/key-holder.ts`): их не видят дочерние процессы, `/proc/<pid>/environ` и сборщики ошибок. Имена ключей также в списке скрытых полей отчётов (`telemetry/scrub.ts`).

## Правило «новый kid раз в год»

Один ключ AES-GCM со случайным IV нельзя использовать бесконечно (NIST SP 800-38D: не больше 2^32 запечатываний; мы тревожимся на 1 миллиарде). Плитка «Ключи сообщений» (Система → Здоровье системы) считает сообщения по ключам при каждом проходе перешифровки и краснеет при 1 000 000 000 под одним ключом. Это строка «Выпустите новый ключ (kid)». Ключи по разговорам (свой ключ на чат, через KMS) пока не делаем, это следующий этап (`docs/SECURITY_TODO.md`).

## Как менять kid

1. Добавить новый ключ в конец списка, **старый оставить**.
2. Сделать новый активным (`*_ACTIVE_KID`), перезапустить сервисы.
3. Подождать, пока фоновая задача перешифрует всё (плитка «Ключи сообщений», кнопка «Перешифровать заново»; для `SECRETS_MASTER_KEYS` ещё кнопка «Перешифровать» в Ключи и сервисы).
4. Только когда плитка показала, что старый kid не нужен (нулевой счёт «застрявших»), убрать его из списка.

Что перешифровывается: сообщения и их правки, имена файлов (`messages.file_name`), «Личные данные» (`cases.private_details`), коды помощников, ключи реестров, секреты аутентификаторов. Секрет аутентификатора в старом формате `v1` читается как раньше и переписывается в новом формате при следующем входе админа (или кнопкой «Перешифровать»). Когда в базе не осталось `v1`, `ADMIN_TOTP_ENC_KEY` можно заменить на любое новое значение: теперь он нужен только для старых строк.

Исключение: журнал дел (`case_journal`) нельзя переписать (добавление только в конец и цепочка хэшей). Если включён переключатель «Шифровать текст в журнале дел», каждый kid, под которым записаны журнальные строки, остаётся в `MESSAGE_ENC_KEYS` на весь срок хранения (5 лет). По умолчанию он выключен.

## Проверка случайности ключей

На production и staging ключи должны быть похожи на случайные: `openssl rand -base64 32`. Слова и повторы приложение отвергает при старте и называет переменную. Запасной выход `KEY_STRENGTH_CHECK=off`.

## Пароли

Новые пароли хэшируются scrypt N=2^16, r=8, p=2 (OWASP). Старые хэши (N=2^14/2^15, p=1) работают и обновляются при следующем успешном входе. Один хэш занимает около 64 МиБ памяти и ~100–200 мс одного ядра: на малом ECS-задании много одновременных входов упрётся в память, следите за плиткой API.
