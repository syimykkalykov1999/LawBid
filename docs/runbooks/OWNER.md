# Пришло письмо от AWS — что делать (для владельца)

Вам не нужно понимать серверы. Система сама:

- **перезапускает** упавший сервер приложения и обработчик фоновых задач (AWS проверяет их каждые 15–30 секунд);
- **откатывает** неудачное обновление на прошлую версию (ECS circuit breaker);
- **растёт и сжимается** с нагрузкой: мощность добавляется за минуту, убирается не раньше чем через 10 минут спокойствия;
- **сдерживает расходы**: письма при 50 %, 80 % и 100 % бюджета; на 100 % сервер держится на минимуме до конца месяца;
- **разгружает базу**: если база стала медленной, тяжёлые пересчёты сами встают на паузу на 15 минут;
- **проверяет бэкапы** каждый час и **всё остальное** каждое утро (GitHub → Actions → «Self-check»).

Где смотреть: **админка → Система → Здоровье системы**. Зелёное — всё хорошо. Под жёлтым и красным написано, что делать.

## Письма и что делать

Тема письма от AWS начинается с `ALARM: "lawbid-prod-…"`. Через несколько минут обычно приходит `OK: "…"` — значит, система справилась сама, и делать ничего не нужно.

| Название в письме | Что случилось | Что делать |
|---|---|---|
| `api-5xx-ratio` | Приложение выдаёт ошибки | Подождать 15 минут (неудачное обновление откатится само). Не прошло — GitHub → Actions → **Rollback production** → ввести прошлую версию. |
| `api-p95` | Приложение медленное | Ничего: сервер растёт сам. Повторяется каждый день — написать Claude «поднять потолок сервера». |
| `api-unhealthy-hosts` | Один сервер не отвечает | Ничего: AWS заменит его сам. |
| `api-no-running-tasks` / `worker-no-running-tasks` | Сервер не запускается | 10 минут подождать; потом **Rollback production** на прошлую версию. |
| `queue-backlog` | Фоновые задачи копятся | Админка → Здоровье системы → **Перезапустить фоновые задачи**. |
| `db-down` | База данных не отвечает | Открыть CockroachDB Cloud: если там авария, её чинит провайдер. Приложение переподключится само. |
| `db-slow`, `tx-retries` | База медленная | Ничего: тяжёлые задачи уже на паузе. Каждый день — написать Claude «база медленная». |
| `redis-cpu`, `redis-memory` | Быстрая память загружена | Держится больше суток — при следующем «ставь на AWS» увеличить Redis. |
| `api-cpu`, `worker-cpu` | Сервер на пределе | Каждый день — поднять потолок (`api_max_tasks`) при «ставь на AWS». |
| `aws-budget-reached` | Бюджет месяца исчерпан | Ничего: сервер уже на минимуме. Нужна полная мощность — **Обычный режим** в Здоровье системы. См. [cost.md](cost.md). |
| Письмо «AWS Budgets» | Потрачено 50 / 80 / 100 % бюджета | Просто знать. Поднять бюджет: `monthly_budget_usd` при «ставь на AWS». |
| Письмо «AWS Cost Anomaly Detection» | Какой-то сервис внезапно стал дороже | Переслать Claude — разберёт, откуда. |
| `backup-stale` | Нет свежего бэкапа базы | CockroachDB Cloud → Backups. Ошибка — написать в их поддержку или Claude «бэкап». |
| `stripe-webhooks` | События оплат не обработались | Деньги не теряются. Написать Claude «Stripe DLQ». |
| `payments-failed` | Много неудачных оплат | Stripe Dashboard → Payments: проблема у банка или Stripe. Людям напоминания идут сами. |
| `journal-integrity` | **Важно:** нарушен журнал кейсов | Ничего не удалять, сразу написать Claude «журнал кейсов». |
| `sms-spend`, `cost-budget` | Платный сервис упёрся в лимит | Это защита от больших счетов. Поднять лимит: Система → Настройки (`budget.*`). |
| `ses-bounce-rate`, `ses-complaint-rate` | Письма не доходят / жалобы на спам | См. [ses.md](ses.md). |
| `treasury-setup-needed` | Деньги не поделены на «Прибыль» и «Расходы» | Stripe → Settings → Payouts → **Manual** (один раз). См. [treasury.md](treasury.md). |
| `treasury-low` | На Stripe мало денег на месяц расходов | Ничего срочного: расходы получили сколько было. Мало на карте для расходов — пополнить один раз. |
| `treasury-payout-failed` | Банк не принял выплату | Stripe → Balances → Payouts: проверить банк. Деньги остались в Stripe. |
| `treasury-bank-changed` | **Важно:** в Stripe поменялись банки | Не вы — сразу в Stripe: удалить чужой банк, сменить пароль. См. [treasury.md](treasury.md). |
| `payroll-funds-low` | На Stripe не хватает на ближайшую зарплату | Подождать поступлений или пополнить Stripe. Зарплата уйдёт сама, когда денег хватит. |
| `payroll-auto-failed` | Stripe не принял зарплату сотруднику | Зарплаты → История: человеку заново открыть ссылку Stripe, потом «Выплатить». |

Письмо **GitHub «Run failed: Self-check (production)»** — откройте его: в отчёте по-русски написано, что именно не так (✅ / ❌) и что делать.

## Кнопки, которые могут понадобиться

Все в **админке → Система → Здоровье системы** (только супер-админ, нужен код 2FA):

- **Перезапустить фоновые задачи** — если «Фоновые задачи» красные больше 10 минут.
- **Пауза тяжёлых задач** — разгрузить базу вручную (приложение работает как обычно).
- **Держать минимум / Обычный режим** — запретить серверу расти (экономия) или вернуть рост.

И в GitHub → Actions:

- **Rollback production** — вернуть прошлую версию приложения одной кнопкой.

## Что делает только человек

- Один раз для «Прибыль и резерв» (Деньги): в Stripe поставить выплаты на **Manual**. Все деньги идут на один счёт (Chase), расходы и прибыль разделены в отчёте. См. [treasury.md](treasury.md).
- Раз в квартал — **учебное восстановление базы** ([restore-drill.md](restore-drill.md), скрипт `scripts/ops/restore-drill.sh`). Можно поручить Claude.
- Подтвердить письмо **«AWS Notification - Subscription Confirmation»** после первого запуска (иначе тревоги не придут; утренняя самопроверка напомнит).
- В CockroachDB Cloud выставить **лимит расходов** (Spend limit) и включить их собственные письма об авариях (Alerts) на ту же почту.
