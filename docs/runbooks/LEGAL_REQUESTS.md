# Запросы госорганов и судов: как это устроено и что делать

Простыми словами. Названия кнопок в внешних сервисах оставлены на английском.

## Что делает система сама

1. **Заведение запроса**: Админка -> Запросы госорганов -> форма. Тип, орган, закон, срок ответа, страна, человек. Если есть запрет рассказывать пользователю (gag order), отметьте галочку и дату окончания.
2. **Напоминания**: раз в час система проверяет сроки. За `legal.reminder_days` (3) дней до срока и после него дежурным админам приходят push и письмо. То же за 3 дня до конца запрета рассказывать и после него. Выключатель: `legal.reminders_enabled` в Настройках.
3. **Заморозка (legal hold)**: в карточке запроса «Заморозка данных». Можно заморозить человека, кейс, чат или группу. Пока заморозка действует, автоматическая очистка эти данные не трогает. Для запроса типа `preservation` заморозка по умолчанию на 90 дней (`legal.preservation_days`). По закону США продление ещё на 90 дней: создайте новую заморозку.
4. **Выгрузка**: поставить в очередь, воркер соберёт ZIP. Внутри `manifest.json` (хэш SHA-256 каждого файла, орган, основание, кто и когда запросил) и `manifest.sig` (подпись манифеста). Скачать можно `legal.export_max_downloads` раз (5), каждое скачивание пишется в журнал. Кнопка «Кто и когда трогал» показывает цепочку.
5. **Письмо пользователю**: кнопка «Отправить письмо». Если запрет рассказывать действует, сервер откажет. Текст правится в Настройках: `legal.notice_template_ru` и `legal.notice_template_en`.
6. **Отчёт прозрачности**: Запросы госорганов -> «Отчёт прозрачности по годам». Только счётчики.

## Какие автоматические удаления уважают заморозку

Проверено все задачи, которые стирают данные людей. Заморозку соблюдают:

| Задача | Что хранит при заморозке человека/кейса |
|---|---|
| legal.retention | текст удалённых сообщений, постов, историй, вопросов |
| privacy.anonymize | сам аккаунт (не обезличивается) |
| sessions.cleanup | сессии и устройства |
| notifications.retention | уведомления |
| journal.retention | журнал кейса (по кейсу и по сторонам) |
| exports.cleanup | файлы выгрузки данных человека |
| storage.retention | события входа (auth_events), активность, просмотры |
| storage.gc | файлы человека в хранилище |
| tasks.archive-purge | архив задач адвоката |
| legal-qa.sweep | удалённые вопросы и ответы |
| fraud.sweep | антифрод-хэши |

Не требуют заморозки, и вот почему:

- `chat.disappearing`: только помечает сообщение удалённым (строка остаётся), настоящее стирание делает `legal.retention`, а он заморозку уважает. Если бы мы оставили сообщение видимым, люди увидели бы, что есть заморозка, а при gag order это нельзя.
- `crashes.purge`: отчёты о падениях не привязаны к человеку.
- `otp.cleanup`: временные ключи в Redis.
- `outreach.retention`: внешние контакты, не пользователи.
- `demo.sweep`: демо-аккаунты.
- `legal.exports` (срок файла выгрузки): файл можно собрать заново, пока данные заморожены.

Если появится новая задача, которая стирает данные людей, она обязана вызвать `activeHeldIds` из `apps/api/src/common/legal-hold/legal-holds.ts` и получить свой тест в `legal-hold-jobs.spec.ts`.

## Что должен сделать владелец (один раз)

1. **Ключ подписи (необязательно, лучше)**. Без ключа манифест защищён HMAC: это доказывает целостность только внутри LawBid. Чтобы суд мог проверить подпись сам, создайте ключ Ed25519:
   `openssl genpkey -algorithm ed25519 -out legal-manifest.pem`
   Положите содержимое файла в секрет `LEGAL_MANIFEST_SIGNING_KEY` в AWS Secrets Manager (или в `.env` сервера), перезапустите API и воркер. Файл никому не отправляйте и в репозиторий не кладите. Открытую часть: `openssl pkey -in legal-manifest.pem -pubout`. Её можно показать суду.
2. **Юрист**: попросите юриста проверить тексты `legal.notice_template_ru/en` и порядок ответа на запросы. Это не юридическая консультация, а техническая реализация.
3. **Адрес для запросов**: опубликуйте в разделе Law enforcement guidelines (политика для госорганов) адрес, куда присылать запросы. Сейчас такой страницы нет.

## Источники (проверены 2026-10-25)

- 18 U.S.C. 2703(f), запрос на сохранение данных: 90 дней, одно продление ещё на 90 дней. Текст закона: https://www.law.cornell.edu/uscode/text/18/2703
- 18 U.S.C. 2705(b), приказ о неразглашении: суд может запретить сообщать пользователю, только если есть риск для расследования. https://www.law.cornell.edu/uscode/text/18/2705
- Решение апелляционного суда округа Колумбия по делу X Corp (июль 2025): слишком общий приказ о неразглашении на год не соответствует закону. Из этого: у приказа должна быть дата окончания, поэтому в системе есть `nondisclosure_until` и напоминание. https://media.cadc.uscourts.gov/opinions/docs/2025/07/24-5089-2126121.pdf
- Практика платформ: Adobe и Okta сообщают пользователю о запросе заранее, кроме случаев, когда запрещает приказ, и уведомляют после его окончания. Отчёты прозрачности публикуют числа по типам запросов, странам и затронутым аккаунтам. https://www.okta.com/legal/government-request-transparency-report-2025/ и https://www.adobe.com/trust/transparency/transparency-2024.html
- Цепочка хранения (chain of custody) для цифровых доказательств: хэш каждого файла, подпись списка, журнал «кто, когда, что». Это общепринятая практика (ISO/IEC 27037, NIST SP 800-86), реализована как в `manifest.json` и `manifest.sig`.
