# Вход, сессии, подбор паролей: что включить и как читать тревогу

Пакет «auth hardening 2» (2026-10-25, пункты S14-1 … S14-13 из раунда 14).
Всё включено так, что у честных людей ничего не меняется; новые защиты,
которым нужно обновление приложения или сайта, выключены настройкой.

## Что изменилось в поведении

| Что | Как теперь |
|---|---|
| Код входа на уже зарегистрированный номер | Тот же ответ `200 sent`, но SMS не уходит (раньше 409 «номер зарегистрирован» выдавал, кто у нас есть). Приложение узнаёт «войдите по паролю» только из `phone/status` |
| Сброс пароля | Одинаковый ответ и время для известного и неизвестного номера; ошибка кода всегда `AUTH_OTP_INVALID` |
| Обновление входа (refresh) | Одна сессия-победитель; повтор только что использованного токена в течение 10 секунд отдаёт тот же новый токен, позже — это кража и все сессии цепочки закрываются |
| Новое устройство | Вход без `X-Device-Id` считается новым устройством; вход из новой страны (по заголовку страны) тоже шлёт предупреждение; refresh из новой страны — тоже, один раз за переезд |
| «Это не я» | `POST /auth/wasnt-me`: закрывает все сессии аккаунта и пишет в журнал (`wasnt_me`) |
| Вход через Google / Apple | Идёт через ту же общую функцию входа, что код и пароль (баны по телефону, почте, устройству) |
| Одноразовая почта | Новый аккаунт с адреса из списка запрещённых доменов не открывается (и по коду, и через Google/Apple). Существующие аккаунты входят как раньше. Точки и `+метки` в Gmail — один ящик для счётчиков |
| Неверные коды | Попытки и блокировка считаются на пару «номер + адрес», чужие ошибки не блокируют владельца; 20 ошибок за сутки с любых адресов сжигают текущий код (нужен новый) |
| Passkey | Для обычных пользователей проверка «это вы» (биометрия/PIN) обязательна и при создании, и при подтверждении действий. Админские ключи (аппаратные) — как раньше |
| Список сессий | Добавлены маскированный адрес, страна (если известна), браузер; просроченные не показываются. Экран приложения не менялся |

## Настройки (Админка → Система → Настройки)

| Ключ | По умолчанию | Когда менять |
|---|---|---|
| `security.otp_legacy_purpose_fallback` | включено | Выключить, когда все версии приложения запрашивают код с назначением `reauth` / `link` (параметр `purpose` у `otp/request`). Тогда код, запрошенный «для входа», больше не подходит для смены данных |
| `security.signup_block_disposable_email` | включено | Выключить только если блокировка мешает честным людям |
| `security.new_country_alert_enabled` | выключено | Включить, когда до API доходит страна входа. Каждое предупреждение стоит письмо и пуш; не больше одного в сутки на аккаунт |
| `security.auth_challenge_after_failures` | 0 (выключено) | Поставить 3–5 после того, как приложение и сайт шлют токен App Check / Turnstile на вход. После стольких неверных паролей/кодов за 15 минут (для одного адреса в 5 раз больше) следующая попытка требует токен |
| `security.app_check.replay_protection` | выключено | Включать вместе с `security.app_check.mode = enforce`, когда приложение шлёт одноразовые токены (`getLimitedUseToken()`) на `otp/request` (телефон), `password/reset/request`, `phone/status`. Каждый токен принимается один раз |

## Шаги владельца

1. **Страна входа.** Предупреждения «новая страна» работают только если до API
   доходит заголовок `CloudFront-Viewer-Country` (CloudFront → Behaviors →
   Origin request policy `AllViewerAndCloudFrontHeaders-2022-06` или своя с этим
   заголовком) либо `CF-IPCountry` (Cloudflare). Если API за ALB без CloudFront,
   страны нет, и ничего не срабатывает (ничего не ломается).
2. **Terraform.** В `infra/modules/monitoring/main.tf` добавлены метрика
   `AuthFailures` и тревога `…-auth-failure-rate` (300 ошибок входа за 5 минут).
   `terraform plan` → `apply` делает владелец; сам пакет Terraform не применял.
3. **Тревога сработала.** Это подбор паролей или кодов. Включите
   `security.auth_challenge_after_failures` (3–5), проверьте
   `security.app_check.mode` (при `enforce` бот без приложения отсекается),
   посмотрите журнал: `metric: auth_failure`, поле `kind` (`password`,
   `otp_verify`, `reset_confirm`).
4. **Приложение (следующий шаг).** Чтобы выключить `legacy_purpose_fallback` и
   включить `replay_protection`, приложение должно: (а) просить код для смены
   данных / добавления способа входа с `purpose: reauth | link` и своим access
   token; (б) брать одноразовый токен App Check на трёх маршрутах. Сервер к
   этому готов.
5. **SMS и сайт.** Строка «привязки к домену» (`@lawbid.dev #123456`) добавляется
   только когда нет хеша приложения Android: SMS Retriever требует, чтобы хеш был
   последней строкой, а домен тоже должен быть последним. Для сайта на Android это
   значит, что код приходит без привязки, пока в Twilio нет отдельного отправителя.
