# Укрепление инфраструктуры (аудит раунд 4, 2026-10-25): шаги владельца

Ничего не применено. Всё новое выключено или является только тревогой.
Каждый пункт: что даёт, какая переменная, что нажать. Всегда сначала
`terraform plan`, смотреть, что нет удалений и замен.

## 0. Что применится само при обычном apply (только тревоги и снижение порога)

- 6 тревог базы, 2 тревоги памяти ECS, ALB 5xx, срок сертификата, порты NAT,
  квоты Fargate (infra-alarms.md). Порог тревоги NAT: 100 → 20 ГБ в сутки.
- Лимит WAF по IP на отправку кодов поднят с 20 до 60 за 5 минут (пункт 8)
  и добавлены новые правила **только в режиме count** (измеряют, не блокируют).
- Защита ALB от удаления (`alb_deletion_protection = true` по умолчанию в prod).
- Копия медиа в us-west-2 (`replicate_media`, по умолчанию true в prod, пункт 5)
  и перестали копироваться маркеры удаления для документов. Стоит хранение
  медиа во втором регионе.

## 1. Роль ops (S4-1): права «Масштаб / Запуск / Расходы» отдельно от API

Сейчас роль задач API и worker умеет менять базу (`rds:ModifyDBInstance` может
сменить пароль мастера и поставить срок бэкапов 0), Redis, ECS, бюджеты.
Один взлом API = взлом базы. Решение: отдельная роль `lawbid-prod-ops`; её
берёт на 15 минут только код админских кнопок через STS с секретным
ExternalId (его знает только задача, он в Secrets Manager).

Порядок (важно, не наоборот):
1. Выкатить релиз с кодом (`apps/api/src/common/ops/ops-credentials.ts`).
   Без `OPS_ROLE_ARN` ничего не меняется.
2. В Secrets Manager tfvars задать `ops_role_external_id` (32+ случайных
   символов), `ops_role_split = true`. `terraform plan`: должны появиться роль
   `lawbid-prod-ops`, секрет `OPS_ROLE_EXTERNAL_ID`, правка политики роли задач.
3. apply; новые задачи получают `OPS_ROLE_ARN`. Проверка: админка → Масштаб →
   кнопка «Перезапустить worker» работает, в CloudTrail событие
   `AssumeRole` для `lawbid-prod-ops`.
4. Откат: `ops_role_split = false`, apply (права вернутся на роль задач).

Честно: кто получил полный RCE (выполнение кода) в API, прочитает и секрет;
защита закрывает кражу учётных данных задачи (SSRF, утечка переменных) и
уменьшает «радиус». Полная изоляция потребует Lambda вне VPC.

## 2. Выход из строя одной зоны (S4-2, S4-11)

Принятый риск и включение одной правкой: nat-endpoints.md, раздел «Принятый риск».

## 3. База в Terraform (S4-3)

1. `adopt_existing_database = true` в tfvars. В `imports.tf` уже есть блок
   `import`; ресурс `aws_db_instance.existing` с `prevent_destroy`.
2. `terraform plan`: должно быть «1 to import» и показаться отличие только по
   Multi-AZ / сроку бэкапов / защите от удаления / Performance Insights.
   Класс, диск, версия, сеть, ключ, пароль игнорируются. Если plan хочет
   **replace** — остановиться и написать Claude.
3. apply (изменения базы применятся в окно обслуживания).
4. После воскресного переключения Multi-AZ в консоли: `database_multi_az = true`,
   чтобы дрейф-проверка видела, если Multi-AZ кто-то выключит.

## 4. Межрегиональные бэкапы RDS (S4-6)

`rds_cross_region_backups = true`: снимки и журналы транзакций копируются в
us-west-2, восстановление на любую секунду там. RPO минуты вместо суток.
Стоит хранение копии (≈ размер базы). Не требует пункта 3. Срок:
`rds_cross_region_backup_retention_days` (14). Проверка: RDS Console →
Automated backups → Replicated.
Холодный регион (отдельно, не автоматизировано): ECR replication, секреты,
Route 53; план в backups.md.

## 5. Копия медиа (S4-5)

`replicate_media = true` (в prod по умолчанию). Реплицируются только НОВЫЕ
файлы. Старые: S3 Console → bucket `lawbid-prod-media` → Management →
Replication rules → `media-to-replica` → Create replication job (Batch
Replication), один раз. Маркеры удаления не копируются: случайно удалённое
фото останется в копии (версии в копии живут 90 дней после удаления).
Для документов то же: `delete_marker_replication = Disabled`.
Изолированная копия в другом аккаунте с Object Lock уже закодирована и
выключена (`backup_copy_account_id` + `backup_vault_lock_mode`).

## 6. Балансировщик (S4-7)

- Сейчас: липкость 24 часа на всю группу API. Это перекашивает нагрузку после
  роста и «прибивает» обычные запросы к одной задаче.
- Включение: `alb_websocket_target_group = true` — отдельная липкая группа
  только для `/socket.io/*`, остальной API без липкости и с
  `least_outstanding_requests`. **Внимание:** провайдер AWS пересоздаёт ECS-сервис
  api при добавлении группы (короткий перебой) — применять в тихое время.
- Позже (изменение приложения, не сделано): клиенты Socket.IO
  `transports: ['websocket']` (без long-polling), тогда липкость не нужна совсем.

## 7. Лимиты WAF (S4-8)

Новые правила: `otp-rate-per-ip-device` (IP + заголовок `x-device-id`, 20 / 5 мин),
`auth-login-rate-per-ip` (300 / 5 мин на IP), `auth-refresh-rate-per-device`.
Последние два в режиме `waf_auth_rate_action = "count"`: неделю смотреть
метрики WAF; чисто — поставить `"block"`.
Честно про CGNAT: у одного адреса оператора тысячи людей. Правило с ключом
IP+устройство разводит их. Запрос БЕЗ заголовка устройства AWS в этом правиле
не считает, поэтому «голое» правило по IP оставлено запасным и поднято
до 60 (было 20): злоумышленник без заголовка получает 60, а не 20.
Выключить ключ устройства: `waf_device_header = ""`.

## 8. Роль деплоя (S4-9)

Права ECS теперь ограничены нашим кластером/сервисами/семействами задач.
Дальше: `deploy_trust_main_branch = false` в `infra/bootstrap` (локальное
состояние, запускает владелец). **До этого** добавить `environment: production`
в jobs, которые берут `AWS_DEPLOY_ROLE_PROD` на main без окружения:
`deploy.yml` (build), `web-deploy.yml`, `seo-deploy.yml`, `self-check.yml`,
`aws-inventory.yml`. Иначе эти запуски перестанут входить в AWS. Тогда любой
push в main больше не получит права ECS без вашего подтверждения.

## 9. Состояние Terraform (S4-14)

`state_replica_enabled = true` в `infra/bootstrap`: копия bucket состояния в
us-west-2 + свой KMS-ключ. После этого дать роли drift-проверки
(`AWS_PLAN_ROLE`) `kms:Decrypt` на `state_kms_key_arn`. Тревоги на чтение
состояния нет (в bootstrap нет SNS-темы): отдельная задача.

## 10. Защита ALB от удаления (S4-10)

`alb_deletion_protection` (true в prod). Чтобы осознанно удалить: сначала false, apply.
