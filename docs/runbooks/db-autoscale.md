# Автомасштабирование базы данных: как это работает и как управлять

Устройство и расчёты: [docs/architecture/DB_AUTOSCALE.md](../architecture/DB_AUTOSCALE.md).
Имя в AWS (prod): Lambda `lawbid-prod-db-autoscale`, параметры SSM
`/lawbid-prod/db-autoscale/mode` и `/lawbid-prod/db-autoscale/state`, база
`lawbid-prod-postgres`, регион us-east-1.

## Как это работает (коротко)

- Каждые 5 минут Lambda смотрит нагрузку. Тяжело (процессор > 70 % 15 минут,
  память < 10 %, соединения > 80 % 10 минут, кончились кредиты t4g) — база
  переходит на **один размер больше**, вам приходит письмо.
- Каждую ночь в 03:30 (Чикаго): если 72 часа подряд было спокойно (процессор
  < 30 %, соединения < 40 %, память в порядке) и на меньшем размере хватит места —
  **один размер меньше**, письмо с экономией.
- Смена размера = около 1 минуты паузы (переключение на запасную копию).
- Не работает во время выкладки новой версии, при незавершённом изменении
  базы, без Multi-AZ, при репликах чтения.

## Письма и что они значат

| Письмо | Что делать |
|---|---|
| «База увеличена: A → B (...)» | Ничего. Если повторяется каждый день — база мала для нагрузки, это нормально, она растёт. |
| «База уменьшена: A → B (...)» | Ничего. |
| «База под большой нагрузкой, но уже на потолке» | Решение за вами: поднять `db_autoscale_max_class` (и бюджет `monthly_budget_usd`), см. ниже. |
| «Автомасштабирование стоит на паузе: ...» | Реплики чтения или нет Multi-AZ. Размер менять вручную, пока причина не уйдёт. |
| «ПРОБНЫЙ РЕЖИМ, ничего не изменено» | Режим `dry-run`: так она бы поступила. |
| Тревога `lawbid-prod-db-autoscale-errors` | Сбой самой программы. База осталась как была. Напишите Claude «автомасштаб базы». |

## Как выключить

Быстро, без Terraform (действует на следующем запуске, до 5 минут):

```bash
aws ssm put-parameter --region us-east-1 --name /lawbid-prod/db-autoscale/mode --type String --overwrite --value off
```

Значения: `on` (работает), `dry-run` (только письма «что сделала бы»), `off`
(ничего не делает). Terraform после создания это значение **не трогает**: обычный
«ставь на AWS» не включит выключенное обратно.

Насовсем: в `terraform.tfvars` прода `db_autoscale_enabled = false` и
«ставь на AWS» (Lambda, расписания и тревога удалятся; размер базы останется
каким был). Первые дни после запуска разумно поставить `db_autoscale_mode = "dry-run"`
в tfvars перед первым применением (или выставить `dry-run` командой выше).

## Как задать размер вручную

1. Выключите автомасштаб (команда выше), иначе через 72 часа ночью он вернёт «по
   нагрузке» (вниз) или сразу поправит вверх при нагрузке.
2. Через Lambda (соблюдает проверки «база свободна», пишет письмо, запоминает время):

```bash
aws lambda invoke --region us-east-1 --function-name lawbid-prod-db-autoscale \
  --cli-binary-format raw-in-base64-out \
  --payload '{"action":"force","class":"db.t4g.medium"}' /dev/stdout
```

   Допустимы только размеры из лесенки. Или напрямую (любой размер):
   `aws rds modify-db-instance --db-instance-identifier lawbid-prod-postgres --db-instance-class db.t4g.medium --apply-immediately`.
3. Автомасштаб после ручной смены считает её изменением и 72 часа не уменьшает базу.

Посмотреть, что она видит сейчас: `--payload '{"action":"status"}'`, логи в
CloudWatch `/aws/lambda/lawbid-prod-db-autoscale` (каждая проверка пишет строку
`decision` с причиной: `calm`, `deploying`, `cooldown_down`, `target_cpu_tight`...).

## Как изменить потолок и пол

`terraform.tfvars` прода:

```hcl
db_autoscale_max_class = "db.r7g.2xlarge"   # потолок (по умолчанию db.r7g.xlarge, ≈ $698/мес)
db_autoscale_min_class = "db.t4g.small"     # пол (по умолчанию db.t4g.micro)
```

Перед поднятием потолка проверьте бюджет: `monthly_budget_usd = 350`
срабатывает на дорогих ступенях.

## Цены по ступеням

Экземпляр с Multi-AZ, on-demand, us-east-1, ≈ в месяц (диск и бэкапы отдельно;
цены примерные, AWS Price List API на 2026-10-24).

| Ступень | Размер | Память | Соединений | $/мес |
|---|---|---|---|---|
| 1 | db.t4g.micro | 1 ГБ | ~99 | ≈ 23 |
| 2 | db.t4g.small | 2 ГБ | ~198 | ≈ 47 |
| 3 | db.t4g.medium | 4 ГБ | ~396 | ≈ 94 |
| 4 | db.t4g.large | 8 ГБ | ~792 | ≈ 188 |
| 5 | db.r7g.large | 16 ГБ | ~1585 | ≈ 349 |
| 6 | db.r7g.xlarge (потолок) | 32 ГБ | ~3171 | ≈ 698 |
| 7 | db.r7g.2xlarge | 64 ГБ | 5000 | ≈ 1396 |

Без Multi-AZ вдвое дешевле. Сейчас (до воскресенья, пока Multi-AZ не включён)
autoscale стоит и ничего не меняет.

## Если что-то пошло не так

- База после смены «висит» дольше 3 минут: RDS консоль → Events; Multi-AZ
  переключение обычно 1–2 минуты. Не запускайте второе изменение, пока статус не
  `available`.
- Автомасштаб «качается» (вверх-вниз каждые несколько дней): поднимите `min_class`
  на ступень выше текущей или поставьте `db_autoscale_tuning = { down_window_h = 120 }`.
- Хотите отключить уменьшение, но оставить рост: `db_autoscale_min_class` = текущий размер.

## Потолок «по деньгам» (cost registry, 2026-10-25)

Помимо `db_autoscale_max_class` (жёсткий потолок из Terraform, по умолчанию `db.r7g.xlarge`) есть второй, **денежный** потолок: параметр SSM `/<имя стека>/db-autoscale/max-class`. Его пишет задача `economy.guard` каждые 5 минут из допустимого расхода месяца: база может стоить не больше 35 % допустимой суммы (при бюджете $350 это `db.t4g.medium`, ≈ $94). Lambda берёт меньший из двух потолков, поднять выше Terraform-потолка денежный не может. Стартовое значение задаёт `db_autoscale_initial_ceiling_class` (по умолчанию `db.t4g.medium`). Выключатель: админка → **Расходы** → «Потолок размера базы и Redis по деньгам» (Выкл = действует только потолок из Terraform). Положения самого автомасштаба (Выкл / Вкл = только письма / Авто) переключаются там же, это тот же параметр `mode`, что и в этой инструкции.
