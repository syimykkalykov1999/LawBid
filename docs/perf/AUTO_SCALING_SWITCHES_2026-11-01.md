# Авто-включение с ростом: что есть в коде и что нет (01.11.2026)

Принцип владельца: пока проект маленький, дорогое и сложное выключено; с ростом включается само (и само возвращается). Ниже — что уже так работает, что включается руками по метрике, и почему. «Проверено по коду» = читал код/Terraform; «из аудита» = взято из PDF-сверки по названиям модулей, код глубоко не читал.

## Как это сделано: само, кнопка в админке, шаги в документе или ничего (проверено по коду)

Короткий ответ на вопрос владельца: предыдущая работа смешанная. Часть работает **само**, часть — **кнопкой в админке** (часто с step-up), часть — **строкой в Terraform по лестнице роста** (`docs/perf/GROWTH_LADDER_2026-10-23.md`, все переключатели в `growth = { ... }` в `terraform.tfvars`, пустая строка = выключено и бесплатно). Ничего из этого не включается «само по метрике» вне AWS-модулей ниже.

| Компонент | Само (где в коде) | Кнопка / настройка в админке (где) | Шаги в документе | Итог |
|---|---|---|---|---|
| Размер БД | Lambda `db-autoscale` вверх/вниз (`infra/modules/db-autoscale`, режим в SSM `on/dry-run/off`) | Админка → «Экономика»: «Увеличить / Уменьшить» (`POST /admin/economy/increase|decrease`, step-up; работает только на AWS) | `docs/runbooks/db-autoscale.md`, `docs/architecture/DB_AUTOSCALE.md` | Само + кнопка + док |
| Redis | Lambda `redis-autoscale` | та же кнопка «Экономика» (`target: redis`) | `docs/runbooks/redis-autoscale.md`, `REDIS_CLUSTER_READY.md` | Само + кнопка + док |
| Реплика чтения БД | Нет | «Масштаб»: `POST /admin/ops/db-replica` создать/удалить (step-up; нужен `db_replica_toggle` в Terraform); код читает с реплики, если задан `DATABASE_REPLICA_URL` | `docs/runbooks/db-replica.md`, лестница роста, ступень 3 | Кнопка + Terraform + док |
| Контейнеры API/worker (ECS) | Автоскейл по CPU/запросам/очереди (`infra/modules/ecs`, `endpoints-autoscale`) + «страж расходов» (`common/economy/economy.service.ts`, флаг `economy_guard`): потолок контейнеров по доле выручки | «Экономика»: правило трат, режим потолка, ручные максимумы (`PATCH /admin/economy/settings`) | лестница роста | Само + настройки админки |
| Очереди и воркеры | Скейл воркера по глубине очереди (из аудита, `infra/modules/ecs`) | «Масштаб»/«Система»: `restart-worker`, `queues/retry-failed`, `heavy-jobs` (`admin-ops.controller.ts`) | runbooks очередей | Само + кнопки |
| OpenSearch | Нет: ни создания, ни переключения само | Настройка `search.engine` (`postgres` / `shadow` / `engine`), `search.engine_kind`, таймаут; «Индекс поиска»: start / swap / rollback (`search-index.controller.ts`); автоматический запасной возврат на Postgres при сбоях движка (брейкер в `search-switch.provider.ts`: 5 ошибок подряд → 30 с на Postgres) | Terraform `opensearch_enabled` (`modules/growth`), `docs/architecture/SEARCH_READY.md` | Кнопки + Terraform + док; авто-переключения по метрике нет |
| Партиции / шардирование | Нет | «Масштаб»: `partitions/:table/start|undo|finalize|pause|retry|mode|abort`, `admin-shards`: split / rollback / resume | ADR 0003/0011, `SHARDING_READY.md` | Кнопки + док |
| Звонки (SFU / mesh / TURN) | Само по числу участников и по здоровью Cloudflare (`calls.service.ts`) | «Масштаб»: проверка пути звонков `calls-path` (`admin-ops.controller.ts`), настройки `calls.*` | runbook звонков | Само + проверка в админке |
| CDN | Медиа и веб через CloudFront уже стоят; | Нет | Terraform `cdn-waf`; CDN перед API в списке «позже» | CDN перед API: ничего |
| Статус-страница, пейджер | Нет | «Статус-страница»: инциденты (`admin-status-page.controller.ts`) | `STATUS_PAGE.md`, `paging.md` | Док + Terraform |

Вывод: «увеличить-уменьшить» БД и Redis есть и само, и кнопкой; контейнеры идут само под потолком расходов; всё остальное (реплика, OpenSearch, шарды) — осознанно кнопкой/Terraform по лестнице роста, потому что стоит денег и меняет архитектуру. Что можно сделать автоматическим дальше, написано в таблице ниже; пороги ставим после повторного нагрузочного теста.

## Сколько это стоит со старта и где потолок (только цифры из кода и Terraform)

Источники: `infra/envs/prod/launch.tfvars.example` (боевого `terraform.tfvars` в репозитории нет, прод я не видел), `infra/modules/db-autoscale`, `infra/modules/redis-autoscale`, `infra/modules/budget`, `apps/api/src/common/economy/economy.rules.ts` (цены ступеней: список цен AWS us-east-1 на 24.10), `app-settings.defaults.ts`. Цены ступеней и оценка «≈ $150–170 стартовый размер» взяты из комментариев этих файлов, я их не пересчитывал.

| Компонент | Что работает со старта | Примерно $/мес со старта | Потолок автомасштаба |
|---|---|---|---|
| API и worker (ECS Fargate) | по 1 задаче (`min_tasks = 1`), 0,5 vCPU; добавляемые под нагрузкой задачи на Spot | входит в «≈ $150–170» стартового стека (оценка из `launch.tfvars.example`) | жёсткий: `api_max_tasks = 50`, `worker_max_tasks = 20`; реальный потолок каждые 5 мин считает «страж расходов» из выручки (`economy.max_spend_percent = 50 %` от выручки за 30 дней, но не меньше `economy.min_threshold_usd = 350`), при превышении трат падает до минимума |
| БД (RDS) | `db.t4g.micro` | $23 (ступень `DB_TIERS`) | лестница до `db.r7g.xlarge` ($698 с Multi-AZ, `max_class` по умолчанию); выше только письмом владельцу; стартовый потолок «по деньгам» стоит app через `initial_ceiling`/экономику |
| Redis | `cache.t4g.micro` + 1 реплика | $23 за группу (`REDIS_TIERS`; в комментарии tfvars «≈ $12» без реплики и «+ ≈ $12» реплика) | `max_node_type = cache.r7g.large` (≈ $320 с репликой) |
| NAT, endpoints | один NAT, интерфейс-эндпоинты выключены (создаёт Lambda при большом трафике) | экономия ≈ $33 и ≈ $29 (по комментариям) | Lambda создаёт и убирает сама |
| Звонки | свой coturn выключен, звонки через Cloudflare TURN/SFU | стоимость по использованию Cloudflare; в коде есть цена звонка (`unitUsdPerCall`) и суточный тормоз `economy.daily_brake_days` | суточный предел денег «по звонкам» считает страж расходов |
| Сторонние сервисы (SMS, почта, проверка личности, хранилище, перевод, видео Bunny, модерация картинок) | `COST_PROVIDERS` в `cost-guard.constants.ts` | по использованию | У каждого есть предел в минуту / в сутки / в месяц (`budget.<провайдер>.*`), сам растёт с ростом и падает при спаде (`cost-autoscale.rules.ts`), предупреждение при 80 % |

**Бюджет и тревоги (есть в Terraform, `modules/budget`):** месячный бюджет `monthly_budget_usd = 350` (из `launch.tfvars.example`): письма на `alert_emails` при 50 % и 80 % реального расхода (то есть $175 и $280) и прогнозные письма 80 % и 100 %; суточная проверка аномалий (порог `anomaly_threshold_usd = 20`); при 100 % бюджета воркер (`ops-guard.job.ts`) сам прижимает автомасштаб к минимуму до конца месяца. Отдельные бюджеты по сервисам задаются в `service_budgets` (по умолчанию пусто).

**Чего нет, честно:**
- Боевое значение `monthly_budget_usd` и `alert_emails` в репозитории не видно (в примере стоит `REPLACE@gmail.com`). Это шаг владельца: проверить, что в прод-tfvars стоит почта, которую он читает, и сумма, на которую он согласен.
- Лимитов расходов на стороне Bunny и Cloudflare (в их кабинетах) в Terraform нет: это не AWS. Защита только внутри приложения (предел `video` и суточный тормоз), а лимит в кабинете провайдера, если он у них есть, ставит владелец.
- Порог тревоги «50 / 100 / 200 $», который просили, я не добавлял: бюджетные письма уже есть на 50 % и 80 % от суммы бюджета и прогноз 100 %, дублировать нечего. Если нужны именно $50 и $100, это одна строка `budget_forecast_thresholds`/`monthly_budget_usd` в tfvars и `terraform apply` с Mac.

## Честно про эту итерацию

Новых авто-переключателей в код я не добавлял. Причина: единственные пороги, которые можно задать безопасно без данных прода, уже стоят (участники звонка, размер файла, нагрузка БД/ECS). Остальные (реплика, OpenSearch, адаптивные лимиты) зависят от реальных метрик и от денег; выдуманный порог либо включит дорогое зря, либо заблокирует людей. Чтобы пороги появились, нужен повторный нагрузочный тест и неделя метрик после запуска; когда они будут, тест порога и переключатель делаю отдельным PR.
