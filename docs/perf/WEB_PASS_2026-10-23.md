# Web pass, 2026-10-23: fast and cheap like Instagram's web

Scope: the Flutter web build (`apps/mobile`, `flutter build web --wasm`),
served from S3 + CloudFront (`.github/workflows/web-deploy.yml`,
`infra/modules/web`).

## How the big web clients ship (what we copied, what Flutter cannot do)

| Practice | Instagram / WhatsApp / Telegram Web | LawBid after this pass |
|---|---|---|
| Hashed, immutable assets (`max-age=1y, immutable`) | all files | app, engine, assets, fonts under `v/<sha>/` |
| HTML is `no-cache`, tiny, shows a skeleton at once | yes | `index.html` splash in the theme tokens, logo inline |
| Code splitting, lazy routes | per route bundles | deferred imports for ~80 screens (JS build only, see below) |
| Brotli | yes | `.br` twins of the app and the engine (needs the function update) |
| Preload of the main bundle from HTML | `<link rel=preload>` | injected by `boot_head.js` (WasmGC browsers) |
| Service worker caching | WhatsApp / Telegram: yes | none, on purpose (below) |
| PWA manifest | yes | id, scope, maskable icons |

Which browser gets what: WasmGC browsers (Chrome/Edge 119+, Firefox 120+,
Safari 18.2+) run `main.dart.wasm` + `skwasm` (Chrome-like) or
`skwasm_heavy` (Safari, Firefox: they lack image codecs / Chromium break
iterators, flutter.js chooses). Everything older gets `main.dart.js` +
`canvaskit`. The wasm path is the one most visitors take.

What was done to the size:

* `--tree-shake-icons` is already on in release; the icon fonts shrank from
  3.3 MB to ~72 KB (nothing to add).
* Optimisation levels are Flutter's defaults for release (dart2js `-O4`,
  dart2wasm `-O2`, "sound", Flutter's own choice); not changed.
* ~80 rarely-first-used screens (chat conversation, calls, stories,
  verification, team, settings pages, payments, channels, groups...) are now
  `deferred as` libraries behind `DeferredScreen`
  (`lib/core/navigation/deferred_screen.dart`). Result on the JS fallback:
  main.dart.js -13 % (raw, gzip and brotli). **The WebAssembly build is not
  split**: Flutter 3.47's tool does not pass dart2wasm's deferred-loading flag
  (no `*.wasm` parts in the output), so for wasm the imports are still plain
  and `loadLibrary()` finishes at once. It costs nothing there and will start
  paying when Flutter ships wasm deferred loading. On the phones nothing
  changes either.
* Dropping fonts: the two text fonts (Inter 0.9 MB, Source Serif 4 1.2 MB)
  are in the app's `FontManifest`, so the engine downloads both before the
  first frame (~0.96 MB brotli of the 4.9 MB cold start). They are used
  everywhere (headings are serif); subsetting needs `fonttools`
  (`pyftsubset`, not installed here) and a decision on which scripts to keep
  (the app is multilingual), so this is left to the owner.

## What changed

1. **Immutable layout** (`scripts/deploy/web-immutable.py`, step "Move the heavy
   files under v/<sha>/" in `web-deploy.yml`): `main.dart.*`, `canvaskit/`,
   `assets/` move to `v/<sha>/` and the Flutter loader is pointed there
   (`entrypointBaseUrl`, `canvasKitBaseUrl`, `assetBase`). Those files are
   uploaded with `Cache-Control: public,max-age=31536000,immutable`. The page
   files (`index.html`, `flutter_bootstrap.js`, `manifest.json`, `boot_*.js`,
   `sqlite3.wasm`, `drift_worker.js`) keep `max-age=0,must-revalidate` (the same
   as `no-cache` for a browser; CloudFront keeps them by the release path,
   `s-maxage=1y`). Icons: one day.
   It works with the already-applied CloudFront function: `v` is in
   `web_app_paths`, so `/v/<sha>/x` is read from `releases/<live>/v/<sha>/x`.
2. **Brotli** (`scripts/deploy/web-gzip-big.sh`): gzip of every file >1 MB as
   before, plus `.br` twins of `main.dart.{js,wasm}` and `canvaskit/**.{js,wasm}`
   (`wasm` 3.64 -> 2.68 MB). CloudFront cannot choose between a `.gz` and a
   `.br` object, so the viewer-request function (`infra/modules/web/main.tf`) now
   rewrites to `<file>.br` when the browser sends `Accept-Encoding: br` and
   the release is marked `br_<sha>` in the key-value store (the deploy writes
   the mark before it switches the release; rollbacks to older releases have
   no mark and keep serving gzip). **Needs `terraform apply` of the web module;
   until then the twins sit unused and everything still works with gzip.**
   Files below 10 MB that are not twinned (fonts, mjs, sqlite3) are compressed
   by CloudFront itself (br or gzip, `compress = true`).
3. **Tabs open across a deploy**: the same function change maps
   `/v/<sha>/...` to that sha's own release folder, so a tab left open on the
   old release still finds its own lazy parts after the live release moved.
4. **First paint** (`index.html`, `boot_head.js`, `boot_end.js`): the splash uses
   the app's own colours (light `#FFFFFF`/gold `#C8A765`, dark
   `#0B0B0D`/`#D8BC84`; the old dark splash was `#0D1117`, a different black than
   the app's, which flashed), the logo is inline so the first paint needs no
   second request, `boot_end.js` is `defer`, API `preconnect`, and after 12 s
   the splash says "taking longer, reload" (it used to spin for ever). The
   WasmGC preloads (`modulepreload` for `main.dart.mjs` and the engine JS,
   `preload` for the two wasm files) start the download from the HTML instead
   of after `flutter_bootstrap.js`; no console warnings about unused
   preloads (checked).
5. **Service worker**: Flutter 3.47's `flutter_service_worker.js` is a stub
   that unregisters itself and reloads the open tab once; the loader only
   registers it when a registration already exists (visitors with an old
   caching worker). It caches nothing, so it cannot serve a stale release.
   Kept on purpose: it removes workers installed by older builds. No new
   caching worker was added: with `v/<sha>/` immutable files the HTTP cache
   already gives repeat visits without a network, and a caching worker would
   add a second invalidation story next to the release switch. The push worker
   (`firebase-messaging-sw.js`) has no fetch handler.
6. **Startup bug found and fixed** (`third_party/passkeys_web`): the upstream
   plugin calls into `bundle.js` (a script from github.com) while the plugin
   registers; with the web page's content security policy (script-src does not
   list github.com) the script is refused, `init()` throws, and the app never
   draws a frame. Reproduced on the unmodified main build by blocking that
   URL. The patched copy catches it; the bundle is added after the first
   frame (and only where WebAuthn exists), so it no longer delays the start.
   Passkeys work again only once the CSP allows the address or the file is
   served from our domain (owner step below).
7. **Browser lifecycle** (`lib/core/platform/web_lifecycle.dart`): see below.
8. **PWA**: `manifest.json` has `id`, `scope`, `start_url "/"`, maskable icons,
   a white `background_color` matching the splash; `index.html` has
   `theme-color` for both schemes, `color-scheme`, `apple-mobile-web-app-capable`,
   `apple-touch-icon`, the viewport. Installable in Chrome/Edge (manifest + icons +
   HTTPS; no worker needed since Chrome 108).

## Browser lifecycle hook (for the connectivity / realtime owners)

`lib/core/platform/web_lifecycle.dart`, started once in `runLawBid`
(`WebLifecycle.attach()`, web only, no-op on phones):

```dart
WebLifecycle.events           // Stream<WebLifecycleEvent>
WebLifecycle.isVisible        // tab is in the foreground
WebLifecycle.isOnline         // navigator.onLine
WebLifecycle.settling         // true for 5 s after the page came back
ref.watch(webLifecycleProvider)  // the same as a StreamProvider
// WebLifecycleEvent: kind (visible, hidden, online, offline, pageHide,
// pageShow, freeze, resume), awayFor (how long the page was away),
// isComingBack
```

How to use it: on `isComingBack` with `awayFor > ~30 s`, reconnect the socket
and fetch deltas; shorter, do nothing. Do not show "connection lost" while
`WebLifecycle.settling`. A socket opened before `pageHide` is dead after
`pageShow` (back-forward cache). The first consumer is the web QR login: it no
longer polls from a hidden tab and polls once on return.
`core/connectivity/**` and `realtime_client.dart` were not touched.

## Server economy on the web (audit)

* Same Dio stack as the phones: ETag layer, retry, idempotency, App Check
  (checked in `core/network`). The web has no extra pollers; the only
  web-only poll (QR login, 10 s fallback next to a socket) now stops when the
  tab is hidden.
* The Drift caches are in-memory only on the web (`drift_memory_web.dart`);
  the byte limits come from the same `CacheLimits`/`CacheMaintenance`, so memory
  is bounded by the same ceilings (http 32 MB, messages 50 MB, feed 8 MB...).
  **Consequence: every page load refetches the i18n bundles (ru + en), the
  language list, countries and `/config/bootstrap`** (5 requests on a cold
  start, observed). With validators (`ETag`/`Cache-Control`) on those API
  responses the browser's own cache turns them into 304s; that is a server
  setting (`apps/api`, not touched here). A persistent web cache (IndexedDB,
  the drift worker is already shipped) is the real fix and is a bigger piece
  of work.
* Images and link previews: the web uses the same widgets and CDN URLs as
  the phones; the browser's HTTP cache replaces `flutter_cache_manager`.
* Guest browsing on the web: the guard lets a guest into the feed with the
  same calls as on a phone (bootstrap, i18n, countries, feed); no extra
  call was added.

## Follow-up: fonts, reload caches, polling (2026-10-23, later)

### Fonts (cold start)

Research. Both text fonts cover only Latin, Cyrillic, Greek and Vietnamese
(`Inter` 2 849 characters, `Source Serif 4` 918). Every other script of the
85 languages (Arabic, Indic, CJK, Hebrew, Thai...) already falls back to the
system font, so a per-script split into separate families would split nothing:
all of what these files hold is needed by the Latin / Cyrillic / Greek
languages, which are most of the 85. Flutter web also downloads every family
of the `FontManifest` before the first frame, so "only the active locale"
is not possible without changing the font loading itself.

What is safe, and was done (`apps/mobile/tool/slim_fonts.py`, `fonttools`):
the weight axis narrowed from 100-900 to 400-900 (the app never asks for
lighter than w400; measured in a test page: the engine does move the `wght`
axis, w400..w900 all render differently), the private-use area and the
enclosed-alphanumeric plane dropped, the stylistic-set / character-variant /
discretionary-ligature features dropped (kerning, ligatures, case, tabular /
proportional / lining / oldstyle figures, slashed zero, fractions kept).
Every outline of every kept character at w400-w900 is equal to the original
within 0.5 font units (12 438 + 5 490 glyph instances compared); the 85
languages lose no character (776 private-use symbols and 3 enclosed letters
only).

The optical-size axis stays. Pinning it would save another ~250 KB brotli
(FreeType on the web and Android never moves it), but CoreText moves it by
itself at large sizes: the golden tests (macOS rasteriser) changed by ~2.5 %
of the pixels, i.e. iOS headings would look different. A name table with the
named instances cut, or `post` glyph names / `BASE` dropped, did the same
(2.5 %), so those stay as upstream. With the shipped files the goldens are
pixel-equal.

### Reload caches (5 requests)

* API: `GET /i18n/bundle/:lang` answers 304 for the full bundle and now for a
  `?since=` delta too (the tag carries `since`), `Cache-Control: private,
  no-cache`. `/i18n/languages`, `/countries`, `/config/bootstrap` already
  had `max-age` and (Express's body tag, or the cheap tag) 304: now covered by
  an e2e. CORS: `If-None-Match` is an allowed request header and `ETag` an
  exposed response header. Without these a browser page on another origin
  could neither send the validator nor read the tag, so the app's HTTP cache
  never stored anything on the web.
* App: on the web only these public answers (`anon` rows of `/i18n/*`,
  `/countries`, `/config/bootstrap`) go to a persistent store (IndexedDB,
  `lawbid_public_cache`); everything else keeps living in the tab's memory.
  A reload: bundle, languages = 304 with no body; bootstrap and countries
  = no request at all when the server's config version has not moved
  (`fromLocal`) / within 24 h. Phones are unchanged.

### Polling while the socket is down

`MissedPoller` (`lib/core/realtime/missed_poller.dart`): when the socket drops
and stays down it asks `GET /realtime/missed?since=<cursor>` every
`pollingFallbackIntervalSeconds` (30), only while the app / tab is in front
and signed in; it stops when the socket is back or the app / tab goes to the
background. The reconnect logic is untouched.

## Round 2 (2026-10-26, smoothness P6): compression, isolation, icon fonts

Check any time: `scripts/dev/check-web-headers.sh` (terraform fmt/validate +
the rules below); `--live https://lawbid.dev` also asks the live site.

### Compression and caching (a)

Already in place: every behavior `compress = true` with CachingOptimized
(gzip + brotli), the big `.js/.wasm/.json` pre-gzipped (CloudFront skips
>10 MB), brotli twins of the app and the engine, `v/<sha>/` = a year +
`immutable`, page-level files `max-age=0, must-revalidate`. CloudFront's
compressible types include `application/wasm`, `font/ttf`, `font/otf`,
`text/javascript` (AWS "Serve compressed files", read 2026-10-26).

Added: the fonts are uploaded pre-gzipped with an explicit `font/ttf` /
`font/otf` type (no reliance on `aws s3 sync` guessing a compressible type),
and they and `main.dart.mjs` get brotli twins too. Those twins are served
only for releases marked `br2_<sha>` (a separate marker, so a tab still open
on an older release, which has `br_<sha>` but no font twins, never gets a
`.br` that does not exist).

### Cross-origin isolation (b) — switch `web_cross_origin_isolation`, OFF

With it on, the app's page gets `Cross-Origin-Opener-Policy: same-origin` +
`Cross-Origin-Embedder-Policy: credentialless`: `crossOriginIsolated` is
true in Chrome / Edge / Firefox and Flutter picks multi-threaded skwasm.
Safari ignores `credentialless` and stays single-threaded (works as today).
The company site never gets the headers; the card page `/pay.html` gets its
own behavior without them (Stripe's frames).

| what the app loads | under COEP credentialless |
|---|---|
| our own files, API (CORS), media CDN / S3 / Bunny via fetch (CORS) | works |
| `<img>` / `<video>` from other hosts (no-cors) | works, sent without cookies (we send none) |
| Firebase Messaging / Installations (fetch, service worker) | works |
| passkeys (`passkeys_bundle.js` is ours; WebAuthn is not affected) | works |
| Cloudflare Turnstile (web sign-up), App Check reCAPTCHA | **cross-origin iframes**: blocked unless the frame itself sends COEP; not verified |
| Stripe on `/pay.html` | not isolated (own behavior) |
| links opened in a new tab (`launchUrl`) | works (no opener needed) |

So the switch stays off until a staging check: set
`web_cross_origin_isolation = true` on a test stack, open sign-up with
Turnstile on and a page that starts App Check, and confirm in DevTools that
`crossOriginIsolated === true` and neither frame is blocked
(`ERR_BLOCKED_BY_RESPONSE`). If a frame is blocked, keep it off.

### Icon fonts (c)
