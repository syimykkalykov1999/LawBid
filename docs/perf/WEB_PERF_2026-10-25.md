## S17-1 owner steps (the proxy)

1. `web_api_proxy = true` in the prod tfvars, `terraform apply` (CloudFront roll-out 5-15 min). Review the plan first: one new origin, three new behaviors (`/api/*`, `/pay.html`, `/pay.js`) and a third response-headers policy.
2. Set the secret `WEB_API_BASE_URL` to `https://<web host>/api/v1`, run Web deploy.
3. Check: `curl -sI https://<web host>/api/v1/health` is served by the API, `Cache-Control` unchanged, no `x-cache: Hit`; log in on the web (the refresh cookie path `/api/v1/auth` is host-only and keeps working same-origin); upload a photo; open a chat (the websocket stays on `wss://<api host>`).
4. Rollback: set the secret back to `https://<api host>/api/v1` and redeploy (the proxy can stay).

Risk to know: the ALB WAF rate limits see CloudFront edge IPs for proxied calls, not the visitor. The CloudFront WAF (`cdn-waf`, per-IP) already guards this distribution,; before turning the proxy on, confirm the ALB WAF per-IP rules key on the forwarded IP (or raise them for the CloudFront ranges), otherwise web users share one bucket. This is the reason the proxy is OFF by default.
