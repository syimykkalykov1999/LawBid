# Облачные нагрузочные тесты: смета и план (по пробным кредитам AWS)

2026-11-02. Решение владельца: облако разрешено за счёт пробных кредитов AWS. **Этот документ — только план и смета, ничего не запускалось и не тратилось.** Все цены — прайс AWS США по константам `loadtest/scripts/estimate-cost.mjs` (±30 %); где я вывожу цену сам (RDS крупнее 2xlarge, Fargate 2 ГБ/vCPU) — помечено «вывод».

## Главное
1. **Всё нужное уже есть в репозитории**: отдельная копия системы `infra/envs/loadtest` (не прод, теги `Project=lawbid-loadtest`, роли с явным запретом на прод), k6 на Spot-машинах в AWS, калькулятор цены, кнопка в GitHub с подтверждением суммы, сторож `load-test-watchdog.yml`. Описание: `docs/runbooks/LOAD_TEST.md`. Новый Terraform-стенд писать не надо.
2. **Но стенд `m10` занижен.** Он собран по замеру 28.10 (до ленты и поиска): 40 задач API × 0,5 vCPU = 20 vCPU и база `db.r7g.2xlarge` (8 vCPU) на 5 000 запросов/с. Ноутбучный тест 02.11 (#578) на реальной смеси дал: ≈30 запросов/с на vCPU API и ≈150 запросов/с на vCPU базы (479 запросов/с съели 3,1 vCPU базы). Для 5 000 запросов/с это ≈ **80–170 vCPU API** и ≈ **32 vCPU базы**. Запуск `m10` как есть почти наверняка упрётся в базу уже около 1 200 запросов/с и покажет красное, потратив $20. (Цифры ноутбука — оценка для Fargate: калибровка на реальном Fargate нужна, см. ступень 1.)
3. **«Миллионы людей» надо разделить.** `m1` и `m10` — это 1 и 10 млн людей **в день** (пик 1 500 и 5 000 запросов/с, ≈ 3 100 и ≈ 10 400 человек онлайн одновременно). **Миллионы одновременно онлайн** — это 480 тыс. запросов/с: на одной базе-лидере (даже самой большой RDS, 64 vCPU) это невозможно по расчёту, там нужны реплики чтения, кэш ленты и шарды. Такой «стенд» стоил бы тысячи долларов за час и проверял бы заведомо известное. Большие компании так не тестируют: они проверяют одну «ячейку» (shard + её API) на пределе и умножают ячейки.

Расчёт `m10-v2` (2 ч жизни стенда): фиксированная часть как в `m10` (ALB 0,57 + NAT 0,31 + endpoints 0,08 + IPv4 0,10 + воркеры 0,51 + TURN 0,02 + генераторы 0,36 + CloudFront 5,23 + WAF 6,05 + трафик 0,75 + прочее 0,64) = 14,6; Redis 1,75; база `db.r7g.8xlarge` 2 ч × $4,416 (вывод: линейно от 2xlarge $1,104) + диск = 8,85; API 75–125 vCPU в среднем × 2 ч × $0,0494 за vCPU-час (вывод: 1 vCPU + 2 ГБ по ценам Fargate) = 7,4–12,4. Итого $32,6–37,6.
Ступень 3: WAF ≈ 120 млн запросов × $0,6 = $72; API $100–170; база и реплики ≈ $50; CloudFront ≈ $50; генераторы (≈100 Spot-машин) ≈ $10. Это порядок, не смета.

## Бюджет и аварийная остановка (что уже есть)
- Кнопка **откажется стартовать**, если верхняя граница (оценка ×1,5) больше суммы `confirm_cost`, которую впишет владелец; запуск ждёт подтверждения в окружении `load-test`.
- Стоп-правило k6: ошибок > 5 % или p95 > 2 с в течение 60 с; потолок жизни стенда 120 минут (`limits.max_wall_minutes`).
- Сторож раз в час сносит всё с тегом `Project=lawbid-loadtest` старше 4 часов и красит прогон (письмо владельцу).
- Роли ограничены тегом/именем стенда, на ресурсы `Project=lawbid` (прод/staging) — явный запрет.
- Что **добавить** (нужно сделать в PR после согласования): (а) AWS Budget на аккаунт или на тег `Project=lawbid-loadtest` с порогами 50/80/100 % кредитов и письмом; **авто-остановка по бюджету** (Budget Action → политика, запрещающая создание ресурсов, или Lambda, дергающая `terraform destroy`) — сейчас сторож реагирует по времени, не по сумме; (б) поднять лимиты `limits.max_api_tasks=48` и `api_max_tasks ≤ 48` в `variables.tf` под `m10-v2` (50×2 vCPU) и профиль `m10-v2`/`m100k` в `profiles.json`; (в) в модуль добавить `db.r7g.8xlarge` в `estimate-cost.mjs`. Значение `monthly_budget_usd = 1` в `infra/envs/loadtest/main.tf:129` проверить: для прогонов его надо согласовать со сметой.

## Что нужно от владельца (один раз, без моего доступа к AWS)
1. В Терминале Mac под админом AWS: `cd infra/bootstrap-loadtest && terraform init && terraform apply` — создаст две роли (если уже применялось, пропустить; я не знаю, применялось ли). Нужны **вход в AWS с правами администратора и подтверждение, что пробные кредиты покрывают Fargate, RDS, ElastiCache, EC2, CloudFront и WAF** (AWS Billing → Credits; Marketplace и часть сервисов в кредиты не входят — проверить срок и остаток).
2. GitHub → Settings → Environments → `load-test` (Required reviewers = владелец) и секреты `AWS_LOADTEST_ROLE`, `LOADTEST_CERTIFICATE_ARN`, `AWS_LOADTEST_WATCHDOG_ROLE` (см. `docs/runbooks/LOAD_TEST.md`, раздел 4).
3. Квоты Service Quotas (us-east-1): для `m10-v2` Fargate vCPU ≥ 200 (On-Demand и Spot) и EC2 vCPU ≥ 40; для ступени 3 — ≥ 2 000 (AWS одобряет запрос за часы–дни, это бесплатно). Для `m1` хватает 16.
4. Решение по порядку: **начать со `smoke` и `m1`** (≈ $8 вместе), после них я пересчитаю `m10-v2` по настоящим числам.
