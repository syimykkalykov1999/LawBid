# Веб-версия для компьютера (desktop layout) — план, 2026-10-28

Статус: **только план (фаза 1)**, код приложения не меняется.
Картинки-макеты: `docs/architecture/desktop-web-mockups-2026-10-28.html`
(открыть двойным щелчком в браузере).

## 1. Коротко (для владельца)

1. Сейчас на компьютере сайт — это колонка шириной с телефон (680 px) посередине
   и меню слева. Остальной экран пустой.
2. Делаем как Instagram / WhatsApp / Telegram в браузере: **меню слева**, а
   справа — **две-три колонки**, где это помогает: список чатов + открытый чат
   рядом; список дел + открытое дело рядом; лента + боковая панель (сроки,
   активные дела, подсказки); профиль и поиск — плитки в 3–5 столбцов.
3. **Телефон не меняется вообще.** Новый вид включается только в браузере и
   только когда окно шире **1024 px** (обычный ноутбук). Планшет (600–1023 px)
   остаётся как сейчас: узкое меню слева + колонка.
4. Удобства компьютера: подсветка при наведении мышью, **Enter — отправить**,
   **Shift+Enter — новая строка**, **Esc — закрыть**, **стрелки ← → в
   просмотре фото**, **Ctrl/⌘+K — поиск**, нормальные полосы прокрутки, вместо
   «шторок снизу» — окна посередине и меню рядом с кнопкой. Правая кнопка мыши
   не нужна ни для чего.
5. Текст не растягивается на весь экран: у каждой колонки есть предельная
   ширина, чтобы было удобно читать.
6. Проверка документов (верификация): документы можно загрузить с компьютера
   (перетащить файл), а **селфи — по QR-коду на телефоне**, компьютер сам
   увидит, что готово.
7. Работа разбита на **5 частей (5 PR)**, примерно **13–18 рабочих дней** в
   сумме. Первая — фундамент (меню, ширины, прокрутка, клавиши, тесты-снимки),
   дальше — чаты, дела, лента/поиск/профиль, окна и скорость.
8. Каждая часть проверяется снимками экрана на 1440×900 и 1280×800, а
   снимки телефона обязаны остаться **бит-в-бит такими же**.

## 3. Исследование (живой поиск 2026-10-28; даты источников указаны)

- **Instagram web** — левое меню (Главная, Поиск, Интересное, Reels,
  Сообщения, Уведомления, Создать, Профиль), сворачивается до иконок на
  узком окне; меню остаётся на месте при открытии поста/профиля. Редизайн
  ноябрь 2022 ([9to5mac 2022-11-08](https://9to5mac.com/2022/11/08/instagram-web-gets-new-more-modern-interface-and-yet-no-ipad-app/),
  [MakeUseOf](https://www.makeuseof.com/instagram-web-new-look-what-changed/)).
  В 2025–2026 менялось в основном мобильное приложение: Reels и сообщения
  выше в навигации ([designcompass 2025-10-01](https://designcompass.org/en/2025/10/01/instagram-testing-reels-focused-tab-layout/),
  [9to5google 2026-02-20](https://9to5google.com/2026/02/20/instagrams-reels-first-redesign-might-get-a-customizable-your-feed-video)).
  Наши собственные замеры instagram.com (2026-10-16, в коде
  `web_media_width.dart`): колонка поста 470 px, профиль 935 px, 3 плитки 3:4.
- **WhatsApp Web** — узкая вертикальная полоса слева (Чаты, Статусы, Каналы,
  Сообщества, Архив, Избранное), затем список чатов, затем открытый чат;
  панель «Данные контакта» открывается третьей колонкой справа. Источники:
  [WABetaInfo](https://wabetainfo.com/whatsapp-is-rolling-out-a-redesigned-sidebar-interface-for-the-web-client/),
  [Green-API 2025](https://green-api.com/en/blog/2025/meet-the-updated-whatsapp-web-client-interface/),
  [Dataconomy 2025-03-21](https://dataconomy.com/2025/03/21/whatsapp-web-new-look-is-all-about-dark-mode-vibes),
  [BetaNews 2025-05-16](https://betanews.com/2025/05/16/whatsapp-unveils-a-new-look).
- **Telegram Web A / K** — две версии, A по умолчанию; обе: список чатов
  слева + чат, правая панель профиля по кнопке; Web A недавно сближена по
  виду с K ([bugs.telegram.org #63179](https://bugs.telegram.org/c/63179),
  [Telegram Info: WebK vs WebA](https://tx.me/s/tginfoen?q=%23WebK)).
  Достоверного описания «трёх колонок всегда» не нашлось — правая панель
  открывается по требованию.
- **LinkedIn / Upwork** — свежих (2025–2026) первичных описаний раскладки
  поиском не нашлось; LinkedIn с редизайна 2017 — лента в центре + боковые
  панели ([Search Engine Journal](https://www.searchenginejournal.com/linkedin-redesign-desktop/184210/)).
  Upwork прямо пишет, что тестирует новый вид ленты заказов
  ([Upwork support](https://support.upwork.com/hc/en-us/articles/211063078)).
  Для «список дел + детали» берём проверенный шаблон list-detail.
- **Material 3 (каноничные раскладки)** — три шаблона: list-detail,
  supporting pane (основное ~70% / вспомогательное ~30%), feed. Две панели
  рядом — с ширины «expanded» (840) и шире; на узком — переход на отдельную
  страницу ([Android canonical layouts](https://developer.android.com/develop/ui/compose/layouts/adaptive/canonical-layouts),
  [SAP Fiori list-detail v26.4](https://www.sap.com/design-system/fiori-design-android/v26-4/layouts/list-detail/list-detail)).
  Классы ширины: compact <600, medium 600–839, expanded 840–1199,
  large 1200–1599, extra-large ≥1600 (по документации M3; поиск не дал
  первичной таблицы — сверить при реализации).
- **Flutter (официально)** — не выбирать раскладку по типу устройства, только
  по доступной ширине (`LayoutBuilder`/`MediaQuery.sizeOf`); не растягивать
  текст на всю ширину; на большом экране список → сетка; Material-виджеты уже
  поддерживают мышь/клавиатуру, главные сценарии должны проходиться с
  клавиатуры ([docs.flutter.dev best practices](https://docs.flutter.dev/ui/adaptive-responsive/best-practices),
  [large screens](https://docs.flutter.dev/ui/adaptive-responsive/large-screens)).
  Google-пакет `flutter_adaptive_scaffold` закрыт; есть форк
  `adaptive_scaffold_router` (связка со `StatefulShellRoute`, состояние
  вкладок сохраняется при смене ширины) — [pub.dev](https://pub.dev/packages/adaptive_scaffold_router),
  [DEV: migrating off flutter_adaptive_scaffold](https://dev.to/akhilesh002/migrating-off-the-discontinued-flutteradaptivescaffold-keeping-gorouter-and-your-state-3cem).
  **Решение: пакет не берём**, своя тонкая обёртка поверх уже существующего
  `shell_layout.dart` (меньше зависимостей, полный контроль «телефон не
  меняется»).
- **Скорость Flutter web** — skwasm заметно быстрее CanvasKit на старте и по
  кадрам; многопоточность требует COOP/COEP; без поддержки — откат на
  CanvasKit ([docs.flutter.dev Wasm](https://docs.flutter.dev/platform-integration/web/wasm),
  [Flutter web renderers](https://docs.flutter.dev/platform-integration/web/renderers),
  [skwasm vs CanvasKit, 2026](https://sagnikbhattacharya.com/blog/flutter-web-skwasm-vs-canvaskit)).
  Главная причина рывков при прокрутке на вебе — декодирование картинок
  ([Flutter blog: What's next on the Web](https://flutter.dev/blog/flutter-whats-next-on-the-web)).

## 4. Пороги ширины (breakpoints)

Ширина окна в логических пикселях. Всё ниже действует **только при
`adaptiveShellOn` (веб)**; на телефонах/планшетах-приложениях флаг выключен —
ничего не меняется.

| Класс | Ширина | Меню | Контент |
|---|---|---|---|
| phone | < 600 | нижняя панель (как сейчас) | как сейчас |
| tablet | 600–839 | узкое меню 76 px (как сейчас) | одна колонка (как сейчас) |
| tablet-wide | 840–1023 | меню 220 px с подписями (как сейчас) | одна колонка 680 (как сейчас) |
| **desktop** | **1024–1439** | меню 76 px (иконки, подписи всплывают при наведении) или 220 px при ≥1280 | **2 колонки** (список + детали / основное + боковая панель) |
| **desktop-wide** | **≥ 1440** | меню 220 px с подписями | **до 3 колонок** (чаты: + панель контакта; дело: + чат дела) |

Новая константа `kShellDesktopMinWidth = 1024`, `kShellDesktopWideMinWidth =
1440`, перечисление `ShellLayout` получает `desktop` и `desktopWide`.
Существующие пороги 600/840/680 **не трогаем** — планшетная ветка остаётся
как есть, её снимки тоже не меняются.

Предельные ширины (чтобы было удобно читать):
- лента постов 470 (как Instagram), боковая панель ленты 320;
- список чатов 360 (≥1440: 400), текст сообщения ≤ 640 внутри чата;
- список дел 400, карточка дела ≤ 760, правая панель дела 340;
- профиль ≤ 1100 (3–4 столбца плиток 3:4);
- поиск ≤ 1200 (сетка `maxCrossAxisExtent` 280 → 3–5 столбцов);
- настройки: меню разделов 300 + страница ≤ 680;
- вход/регистрация: 480 (как сейчас) + картинка-бренд слева при ≥1024.

## 5. Навигация — что меняется

1. **Маршруты (URL) и 4 ветки `StatefulShellRoute` не меняются.** Ссылки,
   глубокие ссылки, push-уведомления, телефон — всё прежнее.
2. **Левое меню на компьютере получает 2 пункта, которых на телефоне нет в
   панели:** «Сообщения» (`/inbox`) и «Уведомления» (`/inbox?tab=notifications`)
   со счётчиками, как у Instagram/WhatsApp. На телефоне они остаются как
   сейчас (свайп ленты / иконка в шапке). Порядок: Лента, Поиск, Сообщения,
   Моё (дела), Уведомления, Создать, Профиль; внизу — Настройки, «Ещё».
3. **Список + детали без новых маршрутов.** Страница `/chat/:id` на
   компьютере рисуется как `[список чатов | чат]`; `/inbox` — как
   `[список | пустая заглушка «Выберите чат»]`. Аналогично `/mine` +
   `/mine/case/:id` (`AppRoutes.myCasePattern`) и `/mine/work/:id`. Список
   берётся из уже существующих Riverpod-провайдеров (`chat_list_controller`),
   поэтому при переходе между чатами список не перезагружается и позиция
   прокрутки сохраняется (держим `PageStorageKey`). Замена чата справа — без
   анимации «въезда» (как WhatsApp Web), смена URL через `context.go` с
   `replace`, чтобы «Назад» в браузере не копил десятки чатов.
4. **`ContentColumn` перестаёт врать о ширине только на desktop-классе.**
   Сейчас он подменяет `MediaQuery.size` на 680, чтобы экраны думали «я на
   телефоне». На desktop внутри каждой панели подмена остаётся (каждая панель
   = «маленький телефон»), а решения о раскладке принимает новая обёртка
   **снаружи** — так экраны внутри почти не меняются, а значит, и телефон.
5. **Шторки снизу → окна / всплывающие меню** на desktop: `showAppSheet`
   (центральная точка) на desktop открывает `Dialog` шириной ≤ 560 или
   `MenuAnchor` рядом с кнопкой (меню «...» у сообщения, поста, дела).
6. **Esc** закрывает верхнее окно/меню/просмотр медиа; если открыт чат в
   двухпанельном виде — снимает выбор (как WhatsApp Web).

- Боковая панель только ≥1280; содержимое — из существующих данных (сроки
  `deadlines`, дела `mine`, рекомендации `search`), без новых запросов к API
  тяжелее, чем уже есть. Панель прилипает (sticky) при прокрутке ленты.
- На 1024–1279: лента по центру, панели нет.
- Наведение: подсветка карточки, курсор-рука на кнопках, двойной щелчок =
  лайк (как Instagram web), видео — пауза при уходе мыши не нужна.

```

│    │                      │────────────────────────────────────│ Заблокировать  │
│    │                      │ [📎] [Сообщение…            ] [😊][➤]│                │
└────┴──────────────────────┴────────────────────────────────────┴────────────────┘
 76      список 360–400            чат (текст ≤ 640)                 340, только ≥1440
```

- В двухпанельном режиме меню слева сжимается до иконок (76 px), как
  WhatsApp/Instagram в сообщениях.
- Клавиши: Enter — отправить, Shift+Enter — перенос, ↑ в пустом поле —
  редактировать своё последнее сообщение, Esc — закрыть ответ/выбор/чат,
  Ctrl/⌘+K — поиск по чатам, Alt+↑/↓ — предыдущий/следующий чат.
- Файлы: перетащить в окно чата (drop zone), вставка картинки из буфера
  (Ctrl/⌘+V).

## 7. Общие компоненты (добавить в `core/navigation/shell/` и `core/design_system/`)

| Компонент | Назначение |
|---|---|
| `ShellLayout.desktop/desktopWide` + `windowClassOf(context)` | Один источник правды о ширине; читается из `View`, не из подменённого `MediaQuery`. |
| `DesktopShell` (расширение `MainShell`) | Меню 76/220 + область панелей; сворачивает меню до иконок в двухпанельных экранах. |
| `ListDetailLayout(list:, detail:, empty:)` | Две панели с фиксированной шириной списка, делителем 1 px, сохранением прокрутки списка. На phone/tablet отдаёт только `detail` (или `list`) — экран как сейчас. |
| `SupportingPaneLayout(main:, pane:, paneWidth: 320/340)` | Основное + липкая правая панель (лента, дело). |
| `ReadableWidth(max:)` | Ограничение ширины текста/форм (обобщение `WebMediaWidth`). |
| `HoverSurface` / `hoverHighlight` | Единый эффект наведения (фон +4% непрозрачности, курсор-рука), выключен на сенсоре. |
| `DesktopShortcuts` | `Shortcuts`+`Actions` на уровне приложения: Esc, Ctrl/⌘+K, `/`; на уровне экранов — Enter/Shift+Enter, ←/→, Alt+↑/↓. Только при `adaptiveShellOn`. |
| `AppScrollBehavior` | Видимые полосы прокрутки на desktop, без «перетаскивания мышью» списков, плавная прокрутка колёсиком. На телефоне — поведение по умолчанию (как сейчас). |
| `showAdaptiveSheet` / `AdaptiveMenu` | Шторка на телефоне; окно ≤560 или меню у кнопки на desktop. |
| `DropZone` | Перетаскивание файлов (чат, дело, верификация) — через `super_drag_and_drop` или `desktop_drop` (выбрать в PR 2 после проверки веб-поддержки). |
| `MediaViewerDialog` | Просмотр фото/видео окном: ← → , Esc, колёсико — масштаб. |

## 8. Скорость (performance plan)

1. Оставляем `--wasm` (skwasm, откат на CanvasKit); COOP/COEP уже заданы —
   добавить в smoke-проверку деплоя, что заголовки реально отдаются (иначе
   skwasm тихо уходит в однопоточный режим).
2. **Картинки декодируем в размер показа**: `ResizeImage`/`cacheWidth =
   ширина_плитки × devicePixelRatio` для сеток (профиль, поиск), аватаров,
   превью в чатах. На широкой сетке это главная экономия памяти и рывков.
3. Ленивые списки: `ListView.builder`/`SliverGrid` везде; правая панель и
   список чатов — отдельные `RepaintBoundary`; новые сообщения в чате не
   перерисовывают список.
4. Никаких `Opacity`/`saveLayer` для эффекта наведения — только цвет фона.
5. Ветки оболочки остаются в `IndexedStack` (уже так) — при переключении
   вкладок нет перезагрузки.
6. Изменение размера окна: раскладка пересчитывается по `LayoutBuilder` без
   пересоздания состояния экранов (ключи на панелях).
7. Замер: Chrome DevTools Performance на 1440×900, сценарии «прокрутка ленты
   30 с», «переключение 20 чатов», «сетка профиля 300 плиток»; цель —
   нет кадров > 16 мс в 95% и память < 400 МБ. Результаты — в PR 5.
