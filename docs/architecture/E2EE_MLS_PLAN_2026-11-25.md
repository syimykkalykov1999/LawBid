# Сквозное шифрование чатов на MLS (пункт 25: H4 + K3)

Статус: план (PR 1 из 4). Дата: 2026-11-25. Решение владельца 25.11: «изучи … как гуглский инста тик ток вацап и тд … так же сделай и у нас самый лучший вариант выбери а если он должен быть с лимитами то в админке сделай его настраиваемым».

## Коротко для владельца

- Сейчас чат шифрует сервер: ключ у нас (KMS), поэтому LawBid технически может прочитать переписку. После этой работы текст, голосовые и файлы шифрует телефон отправителя, а расшифровывает только телефон получателя. Сервер хранит и пересылает только «кашу».
- Берём стандарт MLS (RFC 9420, 2023). На нём сейчас работают Google Messages и Apple Messages для RCS (2025–2026), Wire, Webex, звонки Discord (DAVE) и Cloudflare Orange Meets. WhatsApp и Messenger сидят на протоколе Signal, но его библиотека libsignal под AGPL, нам её брать нельзя (только идея). MLS одинаково годится для чата вдвоём, для чата дела с помощниками и для групп, а потом и для звонков.
- Готовые библиотеки, лицензия MIT: в приложении `openmls` для Dart 4.0.0 (обёртка OpenMLS 0.9.2 на Rust, готовые сборки для iPhone, Android, Mac), в вебе `ts-mls` 1.6.4 (TypeScript). Наш веб собирается в режиме `--wasm`, а `openmls` для Dart там пока не работает (ограничение flutter_rust_bridge), поэтому в вебе вторая библиотека того же стандарта. Сервер шифр не трогает: он только раздаёт ключи и пересылает.
- Переключатель в админке `chat.e2ee_mode`: Выкл / Вкл / Авто, по умолчанию Авто. Авто — шифрование включается в чате само, когда у всех его участников приложение уже умеет шифровать. Лимиты, которые есть у платформ, — тоже настройки (устройств на аккаунт, людей в зашифрованной группе, сколько сообщений уходит с жалобой).
- Что меняется для людей: в чате появляется жёлтая плашка WhatsApp «Сообщения и звонки защищены сквозным шифрованием…» и экран «Код безопасности» (60 цифр и QR, как у WhatsApp). Больше внешний вид не меняется.
- Чем платим (так же, как WhatsApp и Messenger): сервер больше не может искать по тексту, переводить, проверять антивирусом и скрывать контакты в зашифрованных сообщениях. Поиск и перевод уходят на телефон, проверка файлов — по жалобе. Скрытие контактов до принятия ставки — правило площадки, поэтому до принятия чат дела остаётся как сейчас (решение ниже, настройка `chat.e2ee_after_unlock`).
- Старые сообщения остаются читаемыми: они так и лежат под ключом сервера. Шифрование начинается с момента включения в каждом чате, в чате появляется системная строка.

## 2. Почему MLS, а не Signal

1. Лицензия: libsignal (Signal) — AGPL-3.0, по правилу №1 только идея. OpenMLS и ts-mls — MIT, их копируем целиком (строки в `THIRD_PARTY_NOTICES.md`).
2. Один механизм для 1:1, чата дела с помощниками и групп: добавление и удаление участника — коммит, ключ меняется для всех за O(log n), а не «каждому отдельно».
3. Тот же MLS потом даёт ключи для зашифрованных звонков через SFU (пункт K3, как Discord DAVE и Cloudflare Orange Meets). Звонки сейчас закреплены и в этой работе не трогаются.
4. Отраслевой стандарт 2025–2026: Google, Apple (для RCS), GSMA, Cisco, Discord.

## 3. Устройство (RFC 9750: служба доставки и служба проверки подлинности)

```
Телефон / веб (OpenMLS или ts-mls)          Сервер LawBid (служба доставки, DS)
 ├─ ключ подписи устройства (Ed25519)  ──►  mls_devices          (кто, какое устройство, открытый ключ)
 ├─ KeyPackage × N + last-resort        ──►  mls_key_packages     (выдача по одному, атомарно)
 ├─ создать группу чата                 ──►  mls_groups           (conversation_id ↔ group_id, epoch)
 ├─ коммит (добавить/убрать, обновить)  ──►  mls_commits          (строгий порядок: принимается только для текущей эпохи)
 ├─ Welcome новому устройству           ──►  mls_welcomes         (адресно, одно устройство)
 └─ сообщение (PrivateMessage, шифр)    ──►  messages.type = mls, messages.ciphertext (текст сервер не видит)
```

- Подлинность: учётная запись LawBid + ключ подписи устройства. Идентичность в MLS — `userId:deviceId` (BasicCredential). Сервер принимает KeyPackage только от устройства этой учётной записи.
- Порядок коммитов: сервер — «строго согласованная» служба доставки (RFC 9750 §5.2, как у Wire): коммит для эпохи N принимается, только если группа сейчас в эпохе N; иначе 409 и клиент сначала догоняет. Так две ветки состояния не появляются.
- Состав группы сервер сверяет со списком участников чата: в коммите клиент указывает, какие устройства добавлены и убраны; сервер отвергает чужие устройства и требует убрать устройства человека, которого убрали из чата. Шаг 2 (PR 3): сервер дополнительно разбирает открытые коммиты (PublicMessage) через ts-mls и сверяет сам.
- Сообщение: `messages` с типом `mls`. Остаются порядок `seq`, отметки «доставлено/прочитано», список чатов, исчезающие сообщения, удаление для всех (удаляется шифр). Колонки текста пустые.

### 3.1 Когда чат шифруется (переключатель)

`chat.e2ee_mode` (Выкл / Вкл / Авто, по умолчанию Авто):

| Режим | Что происходит |
|---|---|
| Выкл | Новые группы MLS не создаются, сервер не принимает сообщения `mls`; приложение пишет по-старому (серверное шифрование). Уже зашифрованные сообщения остаются читаемыми на телефонах. В чате системная строка о смене |
| Вкл | Шифрование в каждом чате, где оно разрешено (см. ниже). Участник без умеющего приложения видит «Обновите приложение, чтобы читать сообщения» (как WhatsApp/Wire при переходе) |
| Авто | Шифрование включается в чате, когда у **всех** участников есть хотя бы одно устройство с ключами MLS; до этого чат пишет по-старому |

Где шифрование не включается никогда: чаты демо-мира (боты пишут с сервера), служебные/системные чаты и чат поддержки. До принятия ставки — по настройке `chat.e2ee_after_unlock` (по умолчанию да, см. 4.2).

Сервер сообщает приложению состояние чата (`e2ee: off | pending | on`) в ответе на чат, приложение решает, как отправлять.

## 4. Конфликты с тем, что уже есть, и как их решают большие

| Наше | Что ломает шифрование | Решение (как у кого) |
|---|---|---|
| Поиск по чатам (слепой индекс `message_search_tokens`, BUG-1) | Сервер не знает слов | Поиск на телефоне по локальной базе drift (WhatsApp, Messenger). Сервер не пишет токены для `mls` |
| Перевод сообщения (`chat-translation.service`) | Сервер не видит текста | Перевод только по нажатию: телефон отправляет этот один текст в перевод, сервер не хранит (как Meta AI в WhatsApp — только то, что человек сам отдал). Позже — на устройстве |
| Скрытие контактов до принятия (`contact-detector`, `contact_masked`) | Сервер не видит текст | 4.2 |
| Проверка файлов антивирусом (#1300 «сначала отправка, потом проверка») | Сервер видит только шифр | 4.1 |
| Модерация чатов, админ-просмотр (`admin-private-content`, `moderation`) | Нет содержимого | Только метаданные; содержимое — из жалобы (жалующийся телефон отдаёт сообщения + franking-ключ, сервер проверяет метку) |
| Юридическая выгрузка и хранение 90 дней (`legal-export`, `legal-retention`) | Содержимого нет | В выгрузке метаданные и пометка «зашифровано сквозным шифрованием»; хранение 90 дней применяется к шифру; экспорт чата делает участник со своего телефона |
| Выгрузка своих данных (`data-export`) | Сервер не может расшифровать | Как WhatsApp «Запросить информацию аккаунта»: метаданные с сервера, переписка — «Экспорт чата» в приложении |
| Пуш с текстом (`push-dispatcher`) | Текста нет | Пуш без текста; Android сам расшифровывает (data-push, `chat_style`); iPhone — расширение уведомлений (шаг 2) |
| Ссылки-превью (`link-preview`) | Сервер не видит ссылку | Превью строит телефон отправителя и кладёт в сообщение (WhatsApp, Signal) |
| Помощники и команда (OQ-048, `sent_by_membership_id`) | — | Помощник — участник группы MLS со своими устройствами; добавили/убрали — коммит, новая эпоха |
| Демо-мир | Боты пишут с сервера | Демо-чаты не шифруются |
| Веб | `openmls` для Dart не работает в `--wasm` | ts-mls через `dart:js_interop`; ключи в IndexedDB, ключ шифрования хранилища — неизвлекаемый `CryptoKey` (как в `openmls` web) |
| Звонки (K3) | — | Не трогаем (закреплено). Потом: ключ звонка из эпохи MLS группы (экспортёр MLS), как Discord DAVE |
| Группы (`ChatGroup`) | — | Служба доставки общая (ключ — `kind + id`), но группы по решению владельца 17.11 — следующее обновление; включаем для них отдельным PR |

### 4.1 Антивирус

WhatsApp и Messenger не проверяют зашифрованные файлы на сервере. У нас три защиты вместо серверной проверки: (1) телефон получателя не открывает файл сам, только по нажатию, и показывает тип и размер; (2) по жалобе жалующийся телефон отдаёт файл и его ключ, сервер прогоняет его через тот же ClamAV и модерацию; (3) настройка `files.e2ee_scan_on_report` (да). Для зашифрованного файла `scan_status = skipped_e2ee`, получатель видит его сразу (в #1300 он ждал проверки — это остаётся для незашифрованных чатов).

### 4.2 Скрытие контактов до принятия ставки

Это правило площадки (как у Airbnb, Upwork, Fiverr: их переписка до сделки не шифруется сквозным шифрованием именно ради защиты от ухода мимо площадки и мошенничества). Решение: при `chat.e2ee_after_unlock = да` чат дела шифруется с момента, когда контакты открыты (`contacts_unlocked`), то есть после принятия ставки; до этого он идёт по-старому с маскированием. При «нет» — шифрование сразу, маскирование делает телефон отправителя (обходится изменённым приложением; поэтому по умолчанию «да»).

## 5. Вложения

1. Телефон делает случайный ключ 32 байта, шифрует файл AES-256-GCM кусками по 64 КиБ (формат потокового AEAD Tink: `nonce_prefix`, номер куска, флаг последнего куска).
2. Загрузка как сейчас: presign → прямой PUT в S3 (`purpose = chat_attachment_e2ee`), `scan_status = skipped_e2ee`.
3. В зашифрованное сообщение кладутся `fileId`, ключ, SHA-256 шифра и открытого файла, имя, тип, размер, превью-картинка (маленькая, внутри сообщения).
4. Получатель скачивает шифр, проверяет хэш, расшифровывает. Пересылка — новое сообщение с тем же `fileId` и ключом (без повторной загрузки, как у WhatsApp).

## 6. Резервная копия и новые устройства

- Новое устройство видит сообщения с момента, когда его добавили в группу (как WhatsApp до восстановления и Wire).
- Резервная копия (шаг 1): телефон выгружает свою историю (drift) в файл, шифрует AES-256-GCM ключом из 64-значного кода восстановления (HKDF-SHA256), грузит напрямую в S3 (`purpose = chat_backup_e2ee`, один файл на пользователя, новая копия заменяет старую). Код показывается один раз, как в WhatsApp.
- Шаг 2 (после выпуска, шаг владельца — расход AWS): пароль вместо 64 цифр через HSM / Nitro Enclave с ограничением попыток и OPAQUE (как WhatsApp 2021, обновлено в мае 2026).

## 7. Код безопасности (копия экрана WhatsApp)

- Экран «Код безопасности»: QR сверху, ниже 60 цифр (12 групп по 5), текст «Чтобы убедиться, что сообщения и звонки с {имя} защищены сквозным шифрованием, сравните этот код с кодом на их устройстве…», кнопка «Сканировать код».
- Код: открытый алгоритм «числового отпечатка» Signal/WhatsApp (5200 итераций SHA-512 над версией, открытыми ключами всех устройств человека по порядку и идентификатором; 30 цифр на каждого, порядок по идентификатору). Готовой MIT-библиотеки на Dart нет: libsignal AGPL — переписываем алгоритм по описанию (≈30 строк), это единственный свой код в криптографии.
- В чате строка «Код безопасности {имя} изменился. Нажмите, чтобы узнать подробнее» при новом или убранном устройстве собеседника.
- Плашка вверху чата: «Сообщения и звонки защищены сквозным шифрованием. Никто вне этого чата, даже LawBid, не может их прочитать или прослушать. Нажмите, чтобы узнать подробнее.»
