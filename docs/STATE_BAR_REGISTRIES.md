# Автопроверка лицензий адвокатов по штатам (owner 2026-10-05)

Решение владельца: «если достану API — внедрение не нужно: добавляю ключ по
штату, и приложение начинает проверку».

## Как это работает
1. Адвокат вводит штат + номер лицензии и даёт присягу — **одобряется сразу**
   (самоподтверждение, `verification.self_attestation_auto_approve`, без изменений).
2. Если у штата в админке включена автопроверка, сразу после одобрения номер
   и имя сверяются с реестром штата. Результат сохраняется:
   - на лицензии — `attorney_licenses.auto_check_result` (результат, провайдер,
     `checkedAt`, имя/статус из реестра, `raw` — короткая копия записи);
   - на заявке — строка `verification_checks` (`check_type = bar_lookup`).
3. Совпало — ничего не происходит. Не совпало имя / номер не найден / статус не
   «действует» — лицензия **остаётся подтверждённой**, но получает отметку
   `registry_flag` (`name_mismatch` / `not_found` / `not_active`) и появляется в
   админке: **Верификация → вкладка «Сверка с реестром»**. Автоматически никого не
   отклоняем. Ошибка или недоступность реестра ничего не меняет.
4. Если самоподтверждение выключено — прежнее правило: все лицензии заявки
   совпали с реестром → заявка одобряется без проверяющего, иначе ждёт человека.
5. Раз в месяц (`licenses.registry-recheck`) все подтверждённые лицензии
   включённых штатов проверяются заново; исчезнувший или недействующий номер
   возвращается в очередь проверяющего.

## Где настраивать
Админка → **Система → Ключи и сервисы → «Реестры адвокатов по штатам»**
(только super admin; сохранение просит код 2FA). У каждого из 50 штатов + DC:

| Способ | Когда | Что ввести |
| --- | --- | --- |
| Вручную | по умолчанию | ничего; при жалобе админ открывает ссылку на коллегию |
| Нью-Йорк — data.ny.gov | только NY, готовый | ничего (токен приложения — по желанию, поднимает лимит) |
| Открытые данные штата (Socrata) | штат публикует список адвокатов на data.<штат>.gov | домен, ID набора, названия колонок, «действующие» статусы, токен по желанию |
| Любой API с ключом | API коллегии или платного сервиса | адрес с `{bar_number}` `{state}` `{first_name}` `{last_name}`, как передавать ключ (header / bearer / query), пути к статусу и имени в JSON, ключ |

Кнопка **«Проверить»** делает один запрос на образцовом номере и показывает,
что ответил реестр. **«Те же настройки и ключ для других штатов»** копирует
способ и ключ (удобно, если один платный сервис проверяет много штатов).

Ключи шифруются тем же мастер-ключом, что и остальные ключи
(`SECRETS_MASTER_KEYS`), админке показываются только последние 4 символа.
Запросы идут только на публичные https-адреса, без редиректов, 8 секунд
таймаут, ответ до 512 КБ.

## Какие штаты готовы сейчас
Проверено 2026-10-03/05 (`/mnt/project-files/verification/lawyer-license-sources.xlsx`):
бесплатный официальный API есть **только у Нью-Йорка** (data.ny.gov `eqw2-r5nb`).
CA, TX, FL, IL, WA и остальные дают только поиск на сайте (IL и TX запрещают
роботов) — их не парсим. Для них: получить API у коллегии или у платного
сервиса проверки лицензий и вставить в «Любой API с ключом».

`auto_bar_check` больше не читается. Миграция `20261005010000` перенесла
его состояние в строку NY.

## API
- `GET/PUT /admin/verification/registries[/:state]`, `POST …/:state/test`,
  `POST …/:state/copy` — super admin.
- `GET /admin/verification/registry-flags`,
  `POST /admin/verification/licenses/:id/registry-check` (проверить сейчас, без
  смены статуса), `POST …/registry-flag/clear` — проверяющий и super admin.
