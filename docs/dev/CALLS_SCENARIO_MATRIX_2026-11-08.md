# Звонки 1:1 — матрица сценариев (08.11.2026)

Ветка `claude/callkit-decline`. Повод: на prod-айфоне «Отклонить» на заблокированном экране не доходило до сервера, звонящий звонил дальше, а кнопка звонка в чате возвращала в тот же старый звонок; иногда после отклонения играла мелодия без экрана звонка; на разблокированном айфоне с приложением в фоне приходил только обычный пуш «Входящий звонок».

## Что нашли (проверено по коду и логам прода)

1. **Отклонение не доходило.** Логи прода 08.11 (CloudWatch `/lawbid/lawbid-prod/api`): звонок создан в 1794170606744, вызываемый (08b3ecbf…) отправил два `POST /calls/<id>/decline` с id, которых сервер никогда не создавал (54649711…, 7b61ce56…) → 404. Настоящий звонок отклонён не был.
   - flutter_callkit_incoming 3.1.6 (iOS) сообщает Dart об отклонении с данными **последнего** звонка, показанного по VoIP, а не отклонённого. На один звонок телефон получал два VoIP-пуша (старый и новый VoIP-токен одного входа). Второй показывался как «одноразовый» звонок со случайным id, и после этого каждое отклонение уходило с этим случайным id.
   - Нативная отправка (`AppDelegate.onDecline`, у неё правильные данные звонка) работала **только** когда приложение было закрыто. В фоне решение оставалось за Dart, а iOS усыпляет приложение сразу после конца звонка CallKit.
2. **Мелодия без экрана.** Нативный `onDecline` ждал ответа сервера (до 8 с + повтор) и только потом выполнял `action.fulfill()`. Пока действие не выполнено, CallKit может продолжать звонить.
3. **Обычный пуш вместо экрана звонка.** Сервер шлёт айфону FCM-пуш «Входящий звонок» только если VoIP-пуш не ушёл. Соединение HTTP/2 с Apple держалось между звонками без проверки. Соединение, оборванное сетью в простое, роняло следующий звонок, и вместо VoIP уходил обычный пуш.
4. **Android, приложение закрыто.** «Отклонить» на полноэкранном звонке или в уведомлении попадало в фоновый isolate push-а, где его никто не слушал. Сервер не узнавал об отклонении.
5. **Возврат в старый звонок.** Сервер держал звонок «ringing», приложение звонило им снова, и кнопка звонка в чате открывала старый звонок.

## Что сделано (готовые решения, MIT)

- iOS `onDecline` теперь работает всегда, как в README flutter_callkit_incoming. `fulfill` выполняется сразу, запрос идёт под background task с билетом звонка. Билет запоминается по id звонка из VoIP-пуша, поэтому работает и для звонка, который первым показал сокет. Свои концы звонков приложение помечает (`call.appEnded.<id>`), и такие концы отклонением не считаются. Одноразовые звонки помечены так же.
- Android: `LawbidApplication` регистрирует `CallkitEventCallback` (README плагина, «MainApplication.kt»). `CallDecline` отправляет `POST /calls/:id/status/decline {t}` с билетом из push-а и при закрытом приложении.
- Сервер: один VoIP-пуш на один телефон (цепочку входа), старые токены той же цепочки удаляются. К Apple: повтор на новом соединении при обрыве и PING раз в 60 с (как heartBeat в node-apn).
- Сервер: если человек сам начинает звонок, пока ему звонят (не отвечено), этот звонок закрывается как «отклонён». Звонящий сразу слышит отказ, новый звонок получает новую сессию. Отклонённый, завершённый или пропущенный звонок принять нельзя (409).
- Приложение помнит звонки, отклонённые на этом телефоне (и нативно, пока оно спало). Такой звонок оно больше не показывает и повторяет отклонение серверу. Поздний VoIP-пуш такого звонка не звонит.

## Проверка владельцем на телефоне (после новой сборки)

1. iPhone, приложение в фоне, экран заблокирован: Samsung звонит → «Отклонить». У Samsung звонок сразу «отклонён», мелодия на айфоне сразу стихла.
2. То же, но приложение смахнуто (закрыто).
3. Сразу после этого в чате на айфоне нажать «звонок»: должен начаться **новый** звонок.
4. iPhone разблокирован, приложение свёрнуто: входящий звонок показывает баннер звонка (зелёная и красная кнопки), а не обычный пуш. Проверить несколько раз подряд, в том числе после 10+ минут без звонков.
5. Samsung, приложение смахнуто: айфон звонит → на Samsung «Отклонить» на полноэкранном звонке. У айфона сразу «отклонён».
6. Обычный путь (экран включён, приложение открыто, оба телефона): позвонить, принять, положить, отклонить. Должно работать как сейчас.
