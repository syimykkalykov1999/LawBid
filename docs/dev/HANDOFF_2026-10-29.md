## 1. Владелец и как с ним работать
- Не программист. Отвечать **по‑русски, коротко (2–4 строки), простыми словами**, без терминов. Команды для него — только готовыми блоками Run.
- **Ждать, пока договорит,** и только потом начинать. Не начинать то, о чём не просил.
- **Пароли, коды, ключи за него не вводить.** Продакшн‑изменения (terraform apply, IAM, SSM, CloudFront, кнопка Approve деплоя) — только он.
- **Внешний вид приложения не менять** без его прямой просьбы.
- **Никаких «двух подписей» (four‑eyes)** в админке — только код 2FA.
- **Честный отчёт:** проверено / не проверено / сломано. Никогда «всё работает» без проверки.
- **Экономия токенов** — его главный денежный вопрос: одна задача за раз, 3–4 помощника максимум, помощники на Sonnet, тяжёлые проверки — программами, а ИИ читает только итог. Не присылать ему видео и скриншоты.
- **Секреты никогда не класть в репозиторий** (он ПУБЛИЧНЫЙ). Ключи живут в GitHub Secrets и AWS Secrets Manager; новый ключ владелец вставляет сам в настройках. Предложение «файл с ключами под паролем в репо» отклонено: публичный репо + короткий пароль = взлом за секунды.

## 2. Главные правила (подробно — AGENTS.md)
1. **Только копируем** проверенный открытый код (MIT/Apache/BSD) — **целиком**, не смешивая со своим; свой код только если готового нигде нет **и владелец прямо разрешил**.
2. GPL/AGPL — не копировать; изучить и построить так же.
3. Каждый чужой файл — проверка на вирусы и опасные строки (пример: официальный пример flutter_callkit_incoming шлёт данные звонков на сервер автора — никогда его не копировать).
4. Одинаково для iPhone, Android, сайта, админки, сервера.
5. Лёгкость: телефон не греется, сервер не пропускает файлы через себя, кэш везде, качество как Instagram.
6. Любой push — только после полной проверки «как в CI» локально; одна отправка — один прогон CI.
