# Скорость везде: замер по видам контента (строка 37 владельца, 13.11.2026)

Поручение: «скорость везде для всех видов контента». До этого: карта приёмов скорости [`SPEED_MATRIX_2026-11-09.md`](SPEED_MATRIX_2026-11-09.md), остатки [`SPEED_GAPS_2_2026-11-09.md`](SPEED_GAPS_2_2026-11-09.md), PR #856 (мгновенная публикация, публичные файлы только в R2) и #879 (стикеры, комментарии, голосовые на сайте, админка). Этот документ — не карта по коду, а **замер**: сколько ждёт человек на каждом виде контента, есть ли ETag/304, кэш CDN, сжатие и какой размер.

## Итог

- **Прод (api.lawbid.dev, lawbid.dev, admin.lawbid.dev, media.lawbid.dev; 12.11 ~23:00–00:30 по Неваде, только чтение, без входа):** все ответы API с данными идут с ETag и отвечают 304 на повтор; JSON сжат brotli (в 2–4 раза); фото и аватары — R2 через Cloudflare (`cf-cache-status: HIT`, `immutable`, год); сайт и пакет Flutter web — CloudFront `Hit`, brotli, пакет по версии с `immutable`. Сервер отвечает за 0–60 мс сверх одного пути до AWS (~100 мс отсюда). **Медленного по вине кода на проде не найдено.**
- **Нагрузочная копия lt (10 млн пользователей, 1 млн адвокатов, 30 млн постов, 5 млн чатов; 127.0.0.1:3055, один пользователь):** всё, что видит пользователь, — 12–160 мс; админка — 13–144 мс, **кроме двух страниц доверия: `/admin/trust/queue` 3,7 с и `/admin/trust/stats` 1,7 с (304 не спасал: 3,5 с и 1,7 с).** Причина доказана и исправлена — ниже, PR `claude/speed-admin-trust`.
- Порог «медленно» — 300 мс на ответ сервера (тот же `PERF_BUDGET_MS`, что у `test/perf-admin.e2e-spec.ts`).

## Как мерил

- `curl`, 5 запросов подряд, медиана; `ttfb` — первый байт с новым TLS-соединением (так ждёт телефон после паузы); `сервер+путь` = `ttfb − TLS` (работа сервера + один путь туда-обратно; на проде один путь ≈ 100 мс: `/health/live` = 102 мс). Размер «по сети» — с `Accept-Encoding: br, gzip`, «сырой» — без сжатия. 304 — повтор с `If-None-Match` и теми же заголовками (`X-Image-Formats`, `Accept-Encoding`: у постов и картинок тег зависит от них — без них 200, это правильно).
- Прод без входа: открытые и гостевые адреса (лента, рилсы, пост, карточка адвоката, поиск, каталог). Истории, чаты, дела без входа отвечают 401 — их скорость мерил на копии lt.
- lt: токены — пересоздал подпись у засеянных аккаунтов помощника нагрузки (`/data/lt/fx-10m`, те же `sub`/`sid`, сессии уже есть), ключ читается из контейнера и не печатается; для админа — ключ сессии в Redis на 3 ч, как `seed-admin-sessions.sh`. Только GET. Второй стенд (lt2) не трогал.
- Гостевой поиск на проде ограничен 30 запросами в минуту на адрес — замер разнесён по окнам.

## Медленное → доказанная причина → исправление

### `/admin/trust/queue` и `/admin/trust/stats` (PR `claude/speed-admin-trust`)

**Причина (доказана).** `AttorneyTrustService.queue()` (`apps/api/src/modules/attorney-trust/attorney-trust.service.ts`) искал очередь одним запросом: «не очищен» И (`ИЛИ` из шести фактов по четырём таблицам: ссылка на фирму ждёт, имя не совпало, два удержания по жалобе, флаг реестра у лицензии, заявка с документами). `ИЛИ` поверх нескольких связей не может взять ни один индекс, поэтому PostgreSQL шёл по всем адвокатам в порядке id и проверял каждого:
- выборка `pg_stat_activity` во время запроса: один и тот же `SELECT … FROM attorney_profiles LEFT JOIN attorney_trust j0 … j5` от 440 до 2 967 мс;
- `EXPLAIN (ANALYZE, BUFFERS)` того же условия: `Parallel Index Scan using attorney_profiles_pkey … rows=980 000`, `Rows Removed by Filter: 980000`, 1 152 743 буфера;
- `/admin/trust/stats` ждёт тот же `queue({ limit: 1000 })` (`admin-trust.service.ts`), поэтому медленный тоже;
- 304 не помогал: тег — хэш тела, обработчик всё равно выполняется.

**Исправление (как уже сделано в коде).** Стандартная замена `ИЛИ` на объединение — та же, что `CallHistoryService.newestMine` (perf-страж 08.11): каждый факт — свой запрос (те же условия + один факт, первые 2 000 по id), id объединяются, первые 2 000 читаются целиком одним запросом. Первые 2 000 каждого факта содержат первые 2 000 объединения, поэтому строки очереди те же самые. Запросы идут по очереди, а не разом (на проде `DB_POOL_SIZE=3`). Для двух фактов индекса не было (`firm_link_status`, `name_check`: `Parallel Seq Scan on attorney_trust`, 9 213 буферов, 137 мс) — добавлены обычные b-tree, как уже стоят у `payments_hold` и `bids_hold` (`@@index` в `schema.prisma` + миграция `20261128090000_attorney_trust_queue_indexes`, обычный `CREATE INDEX`, как `20261120090000_partition_ready_journals`: на проде таблица крошечная, короткая блокировка записи; через `prisma/concurrent/` нельзя — шаг CI «No drift» читает базу до них и видит лишний индекс).

**До / после (lt, 1 млн адвокатов, настоящий клиент Prisma, по 5 прогонов, медиана):**

| | Запрос базы очереди |
|---|---|
| До: один запрос с `ИЛИ` | **1 390 мс** (под нагрузкой через API — 3 722 мс) |
| После, без новых индексов | 58 мс |
| После, с двумя индексами | **10,5 мс** (−99 %) |
| Старый запрос даже с индексами | 1 470 мс (индексы сами по себе не помогают — нужна именно разбивка) |

Индексы на lt строились внутри транзакции, которая откатывалась: на стенде помощника нагрузки ничего не осталось.

**Проверки (Linux-ноутбук, своя временная Postgres 16 / Redis 7 / mailhog, не стенд нагрузки):** `prisma migrate deploy` на чистой базе, `run-concurrent` дважды, «No drift» — нет разницы; `check-migrations.mjs` и `squawk-cli 2.70.0` по новой миграции — 0 замечаний; `prettier` + `eslint` по файлу — чисто; `tsc` (typecheck) — 0; unit `attorney-trust` + `verification` — 25 наборов / 274 теста зелёные; e2e `owner-attorney-trust` (в нём очередь по `name_mismatch` и флагу реестра) + `owner-privacy-moderation` — 23/23. Без почтового сервера один e2e падает с 500 и на коде `main` тоже (письмо фирме) — это окружение, с mailhog как в CI зелёный.

## Что не замерено и почему

- **Видео (HLS старт) и рилсы с данными:** на проде ни одного видео-поста, на lt видео выключено (Bunny не настроен) — нечего мерить. Кэш кусков видео и трафик проверены тестом в #879 (`video_cache_blocks_test.dart`: второй просмотр −67 % байтов).
- **Голосовое:** в фикстуре lt нет голосовых в первых 40 чатах; на проде без входа не открыть. По коду: подписанная ссылка S3 c `private, max-age=3600`, телефон кэширует файл на диске (`voice_files.dart`), сайт — в Cache Storage (#879).
- **Страницы админки в браузере (полная загрузка с JS):** админка закрыта входом; замерены её запросы API (выше) и статические куски (`immutable`).
