# Контроль массового персонала: исследование (2026-10-26)

Задача: до ~1000 админов-исполнителей (проверка документов, модерация, поддержка, бухгалтерия). Система сама считает, кто плохой и кто лучший, сама предлагает действие (предупредить / снять с очереди / заменить) и считает сдельную оплату. Владелец видит только короткий список.

Важная оговорка про источники: официальные страницы Uber, Lyft, DoorDash, Meta-подрядчиков точных цифр не публикуют или публикуют по городам. Цифры ниже из вторичных источников помечены "(неофициально)". Для Meta/Accenture/Genpact есть только вакансии, публичных порогов нет. Это сказано честно, ничего не выдумано.

## 2. Что выбрать

**Лучшей одной компании нет. Берём гибрид из трёх частей:**

1. Рейтинг в скользящем окне как у Uber/Fiverr: простая цифра, понятные пороги, сначала предупреждение, потом действие. Минимум данных (как у Upwork и MTurk) обязателен: пока мало решений, никаких выводов.
2. Выборочная перепроверка и эталонные тесты как у подрядчиков по модерации Meta: случайные решения перепроверяет другой человек; изредка подсовываем задачу с известным ответом (golden set). Это единственный способ ловить тихую халтуру, когда клиенты не жалуются. Для юридического сервиса это важнее всего.
3. CSAT и AutoQA как у Zendesk QA: для поддержки оценка клиента после закрытия + ИИ-проверка диалогов.

Почему не Uber один: оценка пассажира шумная, а у нас ошибка проверяющего документ может стоить дорого и не видна сразу. Почему не MTurk: отклонение одним человеком без апелляции несправедливо.

**Пять стартовых цифр:**
1. Окно: последние 30 дней (но не менее 50 решений; для финансов 20).
2. Минимум решений для оценки: 30. Ниже: статус "мало данных", действий нет.
3. Случайная перепроверка: 5% решений (новичкам первые 14 дней 20%), плюс 1 эталонная задача на 50 обычных.
4. Пороги: рейтинг 85 из 100 = норма; ниже 75 = предупреждение; ниже 60 при N 30+ = предложение снять с очереди; три предупреждения за 60 дней = предложение заменить.
5. Апелляция: сотрудник один раз за 7 дней оспаривает спорный случай, решает автоматический повторный разбор другим случайным исполнителем (без второго админа-утверждающего).

## 3. Готовые инструменты

Все цены сторонние оценки 2025-2026, у вендоров публичной цены почти нет, проверять при покупке.

| Инструмент | Цена (оценка) | Подходит? |
|---|---|---|
| Zendesk QA (бывший Klaus, куплен Zendesk в феврале 2024) | от ~$35 за агента в месяц (заявлено Zendesk), нужен Zendesk-план от $19/агент | Сделан под чаты Zendesk. Для своей админки (не Zendesk) неудобен, API для чужих систем в поиске подтвердить не удалось. Для 1000 человек: ~$35 000/мес. Дорого |
| MaestroQA (возможно переименован в Rippit) | без списка цен; для 10-30 агентов оценка $12-30 тыс. в год | Тоже заточен под колл-центры, для 1000 дорого |
| Observe.AI | неофициально $100-500 за место в месяц | Для голосовых звонков, нам не нужен |
| EvaluAgent | заявлено от $35 за пользователя в месяц | Аналогично |

**Вывод:** все готовые решения оценивают диалоги поддержки и стоят порядка $35/человек/мес, то есть ~$35 тыс./мес на 1000 человек. Они не знают наших задач (проверка документа, решение модерации). Наша админка и так хранит каждое решение. Поэтому: считаем свой рейтинг самим кодом (простая математика, $0), а ИИ-разбор диалогов поддержки добавляем позже по нашему же ключу ИИ только на выборку (сотни рублей в день). Готовое покупать можно только для узкой группы поддержки (до ~50 агентов), если владелец захочет.

## 4. Проект для LawBid

Принципы: всё ВЫКЛЮЧЕНО по умолчанию; пороги задаёт админ; считается раз в ночь в снимок (как админ-статистика), никаких тяжёлых запросов вживую; никаких вторых админов-утверждающих (только 2FA-код); мобильное приложение не меняется (только веб-админка).

### Метрики по ролям
- Verifier (проверка документов): число проверок, среднее время, % решений, отменённых при перепроверке (overturned), жалобы пользователя после закрытия, результат эталонных задач.
- Moderator: число решений, % отменённых при апелляции, % не совпавших с перепроверкой, эталонные задачи.
- Support: число закрытых обращений, время первого ответа, CSAT (палец вверх/вниз от пользователя), повторное обращение по тому же вопросу, ИИ-оценка выборки.
- Finance: число операций, ошибки сверки, исправленные проводки, срок обработки.

### Сигналы качества (одинаково для всех)
1. Жалоба или апелляция после закрытия.
2. Решение отменено другим.
3. Палец пользователя.
4. Случайная перепроверка (5%).
5. Эталонная задача.

### Формула рейтинга (0-100), окно 30 дней
Рейтинг = 50% точность (по перепроверке и эталонам) + 25% отсутствие отмен и жалоб + 15% вердикт пользователей (где есть) + 10% скорость и дисциплина (в срок). Если сигнала для роли нет, его вес перераспределяется на остальные. Если решений меньше 30: "мало данных".

### Флаги (авто)
- Жёлтый: рейтинг ниже 75, или две жалобы за неделю, или провал эталона.
- Красный: рейтинг ниже 60 при 30+ решениях, или три отмены подряд, или явный признак спешки (слишком быстро и всегда "одобрить").
- Зелёный/лучший: топ 5% по рейтингу за 30 дней при 30+ решениях.

### Предлагаемые действия (система предлагает, владелец одним нажатием подтверждает или система применяет сама, если админ включил авто-режим)
1. Предупреждение сотруднику (автоматически).
2. Больше перепроверок (с 5% до 20%).
3. Снять с очереди (временно).
4. Заменить (после трёх предупреждений за 60 дней).
Для лучших: приоритет в очереди и бонус.
Владелец видит один короткий список: "плохие" и "лучшие", остальных не видит.

### Сдельная оплата
Выплата = (число принятых решений x ставка за тип задачи) x коэффициент качества + бонус.
Коэффициент качества: рейтинг 90+ даёт 1.10; 75-89 даёт 1.00; 60-74 даёт 0.90; ниже 60 даёт 0.75 и очередь урезается. Решения, отменённые при перепроверке, не оплачиваются (как в MTurk, но с апелляцией). Ставки, коэффициенты и бонус задаёт админ. Вход в существующие начисления (payroll accruals) раз в ночь.

### Техническая основа (кратко)
Одна таблица "сигналы качества" (кто, что, когда, тип) и одна ночная задача, которая пишет снимок по сотруднику (рейтинг, N, флаги, предложение). Админка читает только снимок. Апелляция: повторный разбор случайным исполнителем той же роли, без утверждения вторым админом. Выключатель на каждую роль и каждое действие отдельно, по умолчанию off.

### Что нужно решить владельцу
- Авто-применять снятие с очереди или только предлагать (рекомендация: сначала только предлагать).
- Размер коэффициентов оплаты.
