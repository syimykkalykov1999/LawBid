## 0. Важное: `apps/web` не существует

В задаче «веб» назван Next.js-клиентом `apps/web`. В репозитории такого каталога нет (`apps/` = `admin`, `api`, `mobile`, `status-page`). **Веб для пользователей — это тот же Flutter-проект `apps/mobile`, собранный под браузер** (`flutter build web --wasm`, `.github/workflows/web-deploy.yml`; оболочка `apps/mobile/web/`). Поэтому «есть на вебе» почти всегда означает «общий Dart-код, один билд с приложением», а настоящие расхождения живут в ветках `kIsWeb` и в файлах-заглушках `*_stub.dart` / `*_web.dart`. SEO-страницы (по темам/юристам) — отдельные статические страницы (#453, #454, #456, #459; `docs/runbooks/SEO_STATIC_PAGES.md`). Админка (`apps/admin`) — Next.js, но это не пользовательская веб-версия.

## 2. Метод и ограничения

- Поверхность «нужна», если её требует суть запроса: область строки + ключевые слова текста («в админке», «лимит», «сервер», «Cloudflare», «документ»…). Это эвристика по тексту, не чтение каждого запроса вручную; спорные ячейки лучше перепроверить перед работой.
- Статус поверхности берётся из колонки «Статус» чек-листа (он уже проверен по коду и PR): «в main» → **есть**; «в main, но иначе», «нет в main», «нужен владелец» → **нет правки**; «нужен телефон» → код в main, ждёт проверки на устройстве → **есть** (отдельно посчитано ниже); «правило/без кода» и `rules-docs` → **н/п**.
- Для веба поверх этого проверены ветки `kIsWeb` и заглушки (ссылки file:line в колонке «Доказательство»). Запросы, мобильные по природе (iPhone/Android/Samsung, CallKit, заблокированный экран, системная «назад», свайп, камера, SMS-приложение, haptics) → веб **н/п**.
- Для admin/api/db/infra отдельно построчно код не открывался: статус наследует состояние строки (кроме явных переопределений). Это честная оценка «по чек-листу», не независимая проверка.
- Значения: **есть** — сделано (file:line / PR в колонке «Доказательство»); **нет правки** — поверхность нужна, но правки нет или она «иначе»; **нет экрана** — на поверхности нет самого экрана/функции; **н/п** — поверхность этому запросу не нужна.
- Расхождение найдено: R-146 (продолжить регистрацию на телефоне) в чек-листе «нет в main», но на вебе уже есть `phone_handoff_panel.dart:17`; серверную часть надо проверить.
