## Как это делает эталон и где мы расходимся

### 1. VoIP-пуш → CallKit (iOS)
- **Эталон (PUSHKIT.md, плагин):** в `didReceiveIncomingPushWith` сразу `showCallkitIncoming(data, fromPushKit: true)` и `completion()` после отчёта. Apple требует: на **каждый** VoIP-пуш — отчёт о звонке, иначе приложение убивают, а после повторов iOS перестаёт доставлять VoIP-пуши.
- **Мы (AppDelegate.swift):** так же, плюс «стоп-звонок» VoIP-пушем.
- **Расхождения:**
  - M1. Ветки `callkitPlugin() == nil` и «звонок уже показан» вызывают `completion()` **без** отчёта о звонке → риск, что iOS отключит VoIP-пуши приложению. Сам плагин делает так же при неверном UUID. *Не исправлено (без сборки iOS на Mac не трогаем Swift); нужен отчёт + немедленное завершение звонка.*
  - M2. Длительность звонка: iOS 45 с (AppDelegate), Dart/Android 60 с, сервер 65 с, по умолчанию плагина 30 с. *Не меняли; лучше одна константа = таймаут сервера.*
  - M3. **VoIP-токен после смены аккаунта не отправлялся** (сервер привязывает токен к сессии, приложение пропускало «тот же токен») → `devices: 0`, iPhone не звонил, только «пропущенный». *Исправлено в этом PR.*

### 2. Полноэкранный звонок / ConnectionService (Android)
- **Эталон:** `showCallkitIncoming` → широковещательное INCOMING → Telecom self-managed звонок + уведомление CallStyle с full-screen intent на `CallkitIncomingActivity`; конец — `endCall(id)` → DECLINE/ENDED → снять уведомление, остановить звук, закрыть экран, `setDisconnected` + `destroy`.
- **Расхождения:**
  - M4. **Ошибка в эталоне 3.1.6:** экран закрывается сообщением, адресованным классу Activity (`getIntentEnded` → `setClassName`) — оно никогда не доходит до приёмника экрана → на заблокированном телефоне экран звонка остаётся. *Обход в этом PR (CallRinging.closeRingingScreen — сообщение без адреса класса); стоит отправить issue/PR в апстрим.*
  - M5. Остановка звонка по пушу шла только через фоновый Flutter (секунды на холодном старте). Эталон тоже полагается на Dart. *Добавлен нативный путь (CallPushReceiver).*
  - M6. `endAllCalls` эталона проходит только по своему списку в prefs: Telecom-звонки вне списка и `CallkitNotificationService` (запускается при «Принять») остаются → «идёт звонок» после конца. *Исправлено: нативный endAll на каждом конце звонка.*
  - M7. Видео на Android звонит как аудио (нет типа camera у службы) — осознанно, флаг видео выключен для Play.

### 3. Отмена звонящим до ответа на заблокированном телефоне
- **Эталон:** сервер шлёт «звонок окончен» → приложение `endCall(id)`.
- **Мы:** сервер шлёт (FCM data high + VoIP на iPhone) — проверено тестами. Расхождения M4, M5; плюс:
  - M8. Нет страховки, если пуш опоздал (Android понижает «high» у пушей без видимого уведомления). *Добавлено: опрос `/calls/:id/status?t=` по билету из пуша + будильник на таймаут сервера.*
  - M9. Холодный старт спрашивал звонок без сессии → 401. *Исправлено: ждём сессию.*

### 4. Порядок завершения
- **Требование / эталонный порядок:** остановить треки → закрыть peer connection → завершить CallKit/Telecom → убрать экран.
- **Мы:** `_finish` → `_reset` (медиа закрывается сразу) → `dismiss(id)` + `endAll` + остановка службы → экран уходит через 1,5 с. Порядок совпадает.
  - M10. Посреди анимации ухода экрана контроллер становился пустым (1,6 с) и шла вторая нативная уборка (2 с) → экран «исчезал на полпути». *Исправлено: экран держит завершённый звонок до конца анимации; поздняя уборка — через 3 с.*

### 5. Одна машина состояний
- **Мы:** один `CallController` (idle → outgoing/incoming → connecting → active → ended → idle), одна подписка на события плагина (`callkitEvents()`, тест `callkit_single_subscription_test`). Совпадает с эталоном по смыслу.
  - M11. Наш собственный `endCall` неотвеченного звонка возвращается событием DECLINE; при «звонящий сбросил» основной isolate может отправить серверу лишний decline (безвредно, звонок уже окончен). *Нативный stop этого события не порождает.*

### 6. Пропущенный звонок
- Эталон: уведомление плагина по таймауту. Мы: уведомление плагина выключено, сервер шлёт `missed_call` (с фото звонящего). Расхождение осознанное.

### 7. Роли и аудио/видео
- Сервер: один путь `CallsService.start` → `enqueueCall` → `dispatchCall` для адвокат→клиент и клиент→адвокат, аудио и видео (видео — только флаг `video` в пуше). Проверено чтением кода и юнит-тестами пуша. Все 4 варианта — в шагах проверки на телефонах в PR.
