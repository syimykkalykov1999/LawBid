# Аудит нагрузки на базу и поиск (R-395, 2026-11-04)

Владелец 04.11 08:30: «чтобы не грузили целые страницы, как сейчас, нагружая наш сервер; если с базой тоже такие вещи — сделайте с серверами, базой и поисковиками как надо».

Первый круг (R-385, `docs/dev/SERVER_REQUESTS_AUDIT_2026-11-04.md`, PR #732 админка, #735 API ETag/304, #738 приложение) убрал лишние запросы к серверу. Этот круг — слой данных: что сервер делает в базе, Redis и OpenSearch на каждый запрос. Прод: RDS Postgres, Redis, OpenSearch.

Правило №1: только готовые приёмы. Prisma — `take` + keyset-курсор, выборка нужных полей, пакетные запросы `in: ids` вместо запроса на строку; индексы под реальные `where`/`orderBy`, строятся `CREATE INDEX CONCURRENTLY` (у нас `prisma/concurrent`, как `disable_ddl_transaction!` в GitLab). Агрегаты админки — уже существующий `AdminSummaryService` (stale-while-revalidate + блокировка в Redis, как дашборды Stripe/Shopify). Кэш — уже существующий `cached()` (cache-aside + lease против лавины, приём memcache-lease Facebook).

Два PR, каждый самостоятельный:
- **PR «perf(база)»**, ветка `claude/db-search-load` — потолки списков, пакетный запрос аватарок, агрегаты админки в сводку, индексы; этот документ.
- **PR «perf(поиск)»**, ветка `claude/db-search-load-search` — общий кэш подсказки тем, статистика поиска в админке из сводки.

## Как считали

- **Списки без потолка.** Разбор TypeScript AST по `apps/api/src` (194 контроллера): каждый вызов `findMany` — есть ли `take`, есть ли выборка по списку id (`in:`), достижим ли он из контроллера (вызов метода из `*.controller.ts`, до трёх шагов `this.x()` внутри класса). Скрипт и полный список — в описании PR.
- **N+1.** Тот же разбор: запрос Prisma внутри `for`/`while` или `.map(async …)`; плюс вызовы помощников, которые сами ходят в базу (`files.mediaUrl`).
- **Индексы.** Для каждого `findMany/findFirst/count/updateMany` с литеральным `where`: есть ли индекс (`@@index`, `@@unique`, `@id`, `@unique` в `schema.prisma` и `CREATE INDEX` в `prisma/concurrent`), который начинается с одного из полей фильтра.
- **Запросы на открытие.** Юнит-тесты со счётчиком запросов (`src/prisma/query-counter.test-support.ts`: каждый вызов делегата Prisma — один запрос, ровно то, что печатает событие `query`). Docker на этом Маке не запущен, поэтому e2e на живой базе не гонялись; цифры «строк» — по коду (потолок `take`), байты — оценка по размеру DTO.

## Что уже было сделано и проверено (ok as is)

- **Ленты и пагинация.** Лента постов, кейсов, рилсы, чаты, уведомления, комментарии, подписчики, поиск, все таблицы админки — keyset-курсор с `take` (страница 20–50, админка ≤ 100); первая страница ленты — в Redis (`feed-version`); рилсы — частичный индекс `posts_reels_created_idx` (< 1 мс) + окно свежести 2 мин в приложении (R-385).
- **Пакетная загрузка.** Посты, комментарии, люди, файлы — через презентеры с `in: ids` (`PostPresenter`, `files.avatarUrlsMany`, `postImageUrls` и т. д.); N+1 в путях запросов не найдено, кроме исправленного (№7).
- **Сводка админки.** `dashboard`, `overview`, `billing/overview`, `trust/stats`, `support/stats`, счётчики меню — `AdminSummaryService` (cron + stale-while-revalidate); проверено нагрузочным тестом `test/perf-admin.e2e-spec.ts`.
- **Кэш Redis на горячих чтениях.** Список блокировок, права и подписка, профиль адвоката, дерево тем, ранжированные результаты поиска (60 с, общий ключ), подсказки (60 с), теги (60 с), топ тега (45 с). Карточка кейса, бейджи, профили — дешёвые ETag/окна свежести из R-385.
- **OpenSearch.** `track_total_hits: false`, `_source` только нужные поля, потолок кандидатов (`CANDIDATES`), тайм-аут `search.engine_timeout_ms` (800 мс) и автомат-предохранитель с переходом на Postgres (`search-switch.provider.ts`); у Postgres-поиска свой бюджет 700 мс и `statement_timeout`. `request_cache` OpenSearch не нужен: перед ним стоит общий кэш результатов в Redis.
- **Приложение.** Поиск — пауза 300 мс; подсказки — 150 мс (решение владельца 15.10, ответ сервера в общем кэше 60 с) — не меняли; темы ищутся на телефоне по уже загруженному дереву, без сервера.

## Что осталось

- Участники группы: постраничная ручка `GET /groups/:id/members` + экран (нужен владелец: экран группы).
- Голоса опроса (`/groups/:id/polls/:id/voters`) — ограничены размером группы; тот же приём, что и для участников.
- Вкладка «Файлы» кейса и вложенные события задачи — читаются целиком (объём ограничен лимитами загрузок); при росте — курсор.
- «Ничего не нашли» в админке поиска оставлена живой: администратор исправляет запрос фразой и ждёт, что список сразу изменится (e2e `owner-search-synonyms`).
- e2e со счётчиком запросов на живой базе и замер байтов — когда на Маке будет Docker (или в CI).
