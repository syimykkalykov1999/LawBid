## FAIL
### F1. Profile counter `posts` is not decremented by DELETE /posts/:id (owner's bug, still on main)
- apps/api/src/modules/posts/posts.service.ts:609 (`remove`): after the soft delete (`updateMany` sets deleted_at), `findFirst({ where: { id } })` runs through the soft-delete extension (src/prisma/soft-delete.extension.ts adds `deleted_at: null`), returns null, so `post?.status === 'published'` is never true and `counters.bump(..., 'posts_count', -1)` (line ~625) is skipped. Fix idea: read status/archived_at BEFORE the updateMany, or pass `deleted_at: { not: null }` in the where (opt-out).
- Repro (attorney marcus.reed, DB posts_count 3 = 3 real posts):
  - 3x `POST /posts` (+Idempotency-Key) -> `GET /attorneys/marcus.reed` counters.posts 3 -> 6 (OK, +1 each)
  - `DELETE /posts/{id}` -> 200 `{deleted:true}`; counters.posts stays 6, real published posts = 5, DB attorney_profiles.posts_count 6 after flush (waited 15 s, twice, also with 14 s gap between create and delete: same).
  - `POST /posts` with `mediaFileIds:[<clean image file>]` -> counters.posts +1 (correct). So "add a photo" is fine; only delete is wrong. Net drift after my run: counter 8, real 6.
  - Archive (`posts.service.ts:~728`) and unarchive paths do decrement/increment correctly (read code; not run).
