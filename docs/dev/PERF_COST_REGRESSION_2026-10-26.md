## Caching verified OK (evidence)
- **#368 per-user cache split is consistent.** Every writer and reader of feed, block-set and feed-version keys uses the same `REDIS_CACHE_CLIENT`: follows.service.ts:19,72,110; blocks.service.ts:12,42,89,151; posts.service.ts (cache client), :358,:613,:947; feed.service.ts:235 (reads `this.cache`). redis.module.ts:33-56 falls back to the main Redis when REDIS_CACHE_URL is unset, and `cache.redis_mode=off` swaps it through `switchableRedis` (cache-redis-mode.ts). An invalidation is therefore never written to one Redis and read from another.
- **#368 `cached()` helper** (common/cache/cached.ts): a hit costs 1 GET. A miss has in-process singleFlight, a cross-pod 5 s NX lease, a bounded wait (60 ms) and a jittered TTL (±20 %). A dead Redis counts as a miss, never an error. The global ceiling `cache.max_ttl_sec`=0 (none) is refreshed every 30 s, not per request. The L1 in-process cache (l1-cache.ts) is bounded (200 entries, ≤60 s, default 5 s) and has singleFlight.
- **#368 cheap ETags** (common/sync/cheap-etag.ts, version-etag.service.ts): the tag is built before the handler. A match returns 304 after only the access `verify()`. The tag includes the AVIF flag and a 60 s bucket (`cache.cheap_etag_sec`=60, 0 = off). Processing videos opt out, so author polling still runs. Express's body ETag is skipped because the header is pre-set. Cost is R-5 only.
- **#368 attorney profile cache**: a viewer-independent core keyed `attorney:public:<username>:<a|w>` (attorney-profiles.service.ts:490). The key includes the AVIF flag. TTL is `cache.attorney_profile_sec`=60, and an own-profile edit drops it.
- **#368 media (public) CDN** stays `immutable` (cacheControlFor returns IMMUTABLE for the media bucket, s3-storage.service.ts:360-363). Invalidation paths collapse all size variants and AVIF twins into one wildcard per file (cdn-invalidation spec, `baseKeyOf`). HTTP/3 is added at no cost.
- **#368 mobile stale-if-error** (http_cache_interceptor.dart): it serves the cached copy only on real outages (connection errors, timeouts, 502/503/504, SocketException), never on 404/500, and only for copies up to 8 h old. This cuts retry traffic during brown-outs.
- **#350 AVIF** is OFF (`images.avif_enabled` false, `avif_since` ''). The twins are separate keys (`<key>.avif`), so CDN cache keys stay plain URL keys with no `Vary: Accept` split. They are served only when the client sends `X-Image-Formats: avif` AND the file is newer than `avif_since`.
- **#325 cache safety middleware** (common/cache/http-cache.ts): 304 passes untouched (the ETag flow is intact). Errors and non-GET get no-store. Set-Cookie gets private, no-store. Untagged answers get `private, no-cache`, which revalidates via ETag rather than refetching. `public` plus credentials is downgraded to private. Anonymous public routes keep 30-60 s (`@AnonymousCache`: posts.controller.ts:264, attorneys.controller.ts:164, search.controller.ts:69,85,98).
