- **FA2. Теперь у кода свой текст на всех 86 языках (`error.api.REFUND_PROVIDER_FAILED`, `scripts/i18n-add.mjs`), ассеты строк сайта пересобраны. Тест `api_error_text_test.dart`.
- **FA3. Адвокат с двумя делами одного клиента не мог оценить клиента во втором деле, и отказ возвращался при каждом запуске.** #1251 сделал второй отзыв той же пары `409 REVIEW_ALREADY_EXISTS` («редактируйте тот, что есть»). Но на деле у адвоката нет id клиента, `GET /cases/:id/client-review` второго дела отвечал «нет отзыва» (пустая форма), а очередь отзывов (`review_outbox`) показывала «Вы уже оставили отзыв по этому кейсу» с «Повторить», которое не может помочь, и так при каждом старте. - **FA4. Картинка во время «Изменить» уходила с текстом редактируемого сообщения как подписью.** GIF с клавиатуры и вставка (#1253), перетаскивание и скрепка во время правки старого сообщения брали поле ввода (а там текст правки) как подпись: в личном чате он вставал подписью в просмотр, в группе файл сразу уходил с этим текстом и поле очищалось. ## ✅ Проверено, исправлять нечего (почему)

- **SYNC_TOO_OLD 409 у уведомлений (#1250).** Список колокольчика — `SyncedListNotifier`, он на этот код забывает метку и перечитывает первую страницу. Другие «дельты» уведомлений (`task_reminders`) читают задачи, не уведомления.
- **AUTH_OTP_EXPIRED 401 на «продолжить на этом телефоне» (#1245, AU3).** Тот же код уже приходил при истечении 5 минут; `AuthInterceptor` трогает только `TOKEN_EXPIRED`, `AUTH_SIGNED_IN_ELSEWHERE`, `AUTH_SESSION_REVOKED`, текст «код истёк, войдите снова» есть.
- **`registered: true, hasPassword: false` в `/auth/phone/status` (AU1).** `phone_screen.dart` в том же PR открывает «Забыл пароль».
- **ACCOUNT_SUSPENDED / ACCOUNT_DELETED на «Забыл пароль» (AU2) и на входе во время удаления (#1258).** Тексты есть; вход в срок удаления снова отменяет удаление по умолчанию — это совпадает с текстом приложения «отменить удаление, просто войдя снова».
- **404 на перевод скрытого «О себе» (#1252).** Профиль присылает скрытое «О себе» как null, кнопки «Перевести» тогда нет; 404 возможен только в гонке и показывается обычной плашкой (`showErrorOrPlans`).
- **USER_BLOCKED у подписки и новые проверки блокировок (#1245).** Подписка откатывает кнопку и показывает текст кода.
- **FIRM_FULL / FIRM_ALREADY_MEMBER / FIRM_OWNER_MUST_TRANSFER / ASSISTANT_SEATS_IN_USE / PAYMENT_INVALID_STATE / REVIEW_APPEAL_EXISTS / REVIEW_NOT_EDITABLE.** У всех кодов есть тексты (`api_error_text.dart`), экраны показывают их плашкой.
- **`queued` у «Пересчитать всех» (доверие, #1259).** Только админка, приложение этот адрес не вызывает.
- **Отказ войти в комнату чата для бывшего члена команды бида (#1259).** Приложение и раньше получало `{ok:false}` для чужого чата.
- **Токен в пачке событий (#1255, AN2).** Адрес публичный, просроченный токен сервер молча считает гостем (событие не теряется, ответ «нет» на телефоне всё равно не пускает события).
- **Кэш списка поддержки (#1255, SU3).** `mustAskAgain` спрашивает сервер (`If-None-Match`) после своего изменения и при «потянуть вниз».
- **`#1253` прочее.** Вставка на сайте не перехватывает текст вместе с картинкой, слушает только верхний экран (`ModalRoute.isCurrentOf`) и снимается в `dispose`; GIF с клавиатуры идёт из памяти (`readAsBytes`, без пути к файлу); GIF разрешён ровно там, где скрепка (контакты открыты, у помощника право «файлы»); клавиатура за пальцем — только iPhone, Android и сайт как были.
- **`#1254` прочее.** Колёсико ловится только над рилсами, во время доезда страница не берёт пиксели колеса, на телефонах пейджер прежний.
- **Строки сайта.** `dart run tool/gen_static_strings.dart` после правки — ассеты совпадают с кодом (`static_strings_asset_test`).

## Две ошибки в консоли живого lawbid.dev (84c364638, Flutter 3.50)

Проверено во встроенном браузере на `https://lawbid.dev/feed` (гость), консоль и `document.scripts`.

- **FA6. CSP блокирует встроенный скрипт (`sha256-k9B74s4HHrP7qsWLxbghlSaym+z4iZhIgo+kxF4g9d4=`).** Это не наш `index.html` (в нём два `application/ld+json`, они не исполняются, их хэши другие) и не Flutter 3.50. Скрипт вставляет пакет `firebase_core_web` (`injectSrcScript`, лицензия BSD-3) при `Firebase.initializeApp` на сайте:
  `window.ff_trigger_firebase_core = async (callback) => { … import("https://www.gstatic.com/firebasejs/13.3.0/firebase-app.js") … }`.
  Хэш ровно этого текста — `k9B74s…` (посчитал в странице). До #1261 было то же самое: `firebase_core_web` 4.1.0 вставлял тот же скрипт с версией 13.1.0 (другой хэш), в CSP хэша не было никогда. Следствие важнее ошибки: на сайте Firebase не стартует вовсе — в консоли сразу `app check: off (TypeError: … 'apply')`, то есть App Check на вебе не работает с первого дня, и веб-пуш тоже не смог бы стартовать.
  Почему не исправлено в этом PR: (1) хэш в CSP — это `infra/modules/web/main.tf` (Terraform — только владелец), хэш меняется с каждой версией Firebase JS, и таких скриптов три (core, messaging, app-check); (2) правильный путь без встроенного скрипта — заранее загрузить модули Firebase из своего кода и положить их в `window.firebase_core` (пакет сам так пропускает вставку), но тогда App Check на вебе впервые оживёт и пойдёт за reCAPTCHA Enterprise (`www.google.com/recaptcha`, `content-firebaseappcheck.googleapis.com`), которых нет в CSP: каждый запрос сайта ждал бы токен до 5 с (`AppCheckSetup.tokenTimeout`). Без правки CSP владельцем это хуже, чем сейчас. Готовый план: правка CSP (script-src/frame-src `https://www.google.com`, connect-src `https://content-firebaseappcheck.googleapis.com`) → `terraform apply` владельцем → затем предзагрузка модулей в приложении, и обе ошибки уходят. Сайт и вход сейчас работают (запросы идут без заголовка App Check, как и раньше).
- **FA7. `Failed to load resource: 503`.** Не адрес страницы и не API страницы: `drift_worker.js`, `sqlite3.wasm`, `flutter_bootstrap.js`, `boot_*.js`, `version.json`, `manifest.json`, `config/bootstrap`, `i18n/bundle`, `feed`, `app-events`, `socket.io` — все 200/204/304 (curl и Resource Timing), перехват `XMLHttpRequest`/`fetch` на странице 30+ с — ни одного ответа ≥ 400. 503 приходит один раз за загрузку, сразу после строк drift «Using WasmStorageImplementation.sharedIndexedDb» и не виден в Resource Timing страницы — значит, запрос идёт из воркера (drift SharedWorker), которого не видно из страницы. 6 запросов `drift_worker.js` — это норма drift: три базы × (SharedWorker + проверка выделенного воркера), все 200. Точный адрес 503 из воркера установить не удалось (нужен DevTools воркера); на работу сайта не влияет (базы открываются, лента грузится). Записано как открытый вопрос, не как исправление.
