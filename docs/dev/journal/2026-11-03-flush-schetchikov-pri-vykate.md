# 2026-11-03 — не терять счётчики при выкате

PR: (номер после открытия). SHA слияния: допишется после слияния.

**Находка Mac-треда (04:44 UTC):** при каждом выкате в момент остановки старых задач API — «case view flush failed» ×2 и «counter flush failed» ×2 с пустым `err.message`.

**Причина.** Prisma закрывается в своём `onModuleDestroy`, а финальный сброс `CounterAggregator` и `CaseViewTrackingService` стоял в `onApplicationShutdown` (позже; к тому же счётчики сбрасывались только из памяти в Redis, а не в БД). Таймерный сброс, идущий в момент остановки, попадал в закрытое соединение. Пустой `message` скрывал причину, потому что логировалось только `error.message`.

**Что сделано (apps/api):**
- `common/errors/error-log-fields.ts`: `errorLogFields` (message, иначе code/имя/вложенные ошибки; плюс name, code, stack) и `settleWithin` (ожидание с таймаутом, не бросает).
- Оба сервиса: финальный сброс в `onModuleDestroy` (пока БД и Redis открыты), таймаут 5 с; при сбое дельты остаются в Redis и их заберёт следующий под.
- Оба сообщения об ошибке теперь пишут реальную причину и stack.
- Тесты: финальный сброс доходит до БД, сбой логируется с причиной и не падает, порядок Nest-shutdown (потребитель уничтожается до модуля БД).

**Что искали и где:** `grep onApplicationShutdown/onModuleDestroy` по apps/api; общей функции формата ошибки для логов и общего «сброс при остановке» нет.

**Осталось (проверить после выката):** на следующем деплое в логах нет «flush failed» при остановке старых задач.
