# 2026-11-02 · отвал Postgres/Redis под нагрузкой, soak 2 ч, подготовка 10M (ноутбук)

Тред «Нагрузочные тесты до живых пользователей», продолжение PR #578. PR #606: https://github.com/syimykkalykov1999/LawBid/pull/606. Прод не трогали, облако не использовалось.

Сделано на том же стенде (Docker Desktop, база 1M, Postgres 8 CPU, задачи API по квоте 2 CPU): новая обвязка `loadtest/local-docker/resilience.sh` (отвал сервиса по расписанию + сэмплер каждые 5 с), `k6-series.py` (ряд по 10 с из `k6 --out json`), `soak-report.py`. Отвал Postgres 40 с при 1 000 человек: 30 009 × 500 (сначала висят 10 с, потом мгновенно), `/health/ready` через 14 с после старта, чисто через 24 с, p95 после = до; API, worker, сокеты восстановились сами. Отвал Redis 40 с: 7 223 × 500, каждый запрос висел 4 с (ioredis 2 с × 2), ready через 2 с, чисто через 6 с; восстановились сами; 83 из 200 переподключений сокетов через 1 м 45 с не удались без логов. Soak 1 500 человек × 2 ч: утечек в API/worker/Postgres нет; Redis растёт за счёт `feed:seen` (35 КБ на активного пользователя, кэп 500, TTL 3 суток) и очереди push, которую воркер 0,5 CPU не успевает разбирать (~26 заданий/с); два застоя — транзакция отправки сообщения держит `FOR UPDATE` чата через 5 round-trip'ов → пул соединений забит → `P2028`/503 health. 10M: база создана и мигрирована, засев ×100 стартовал 23:43 после soak (итог допишется).
