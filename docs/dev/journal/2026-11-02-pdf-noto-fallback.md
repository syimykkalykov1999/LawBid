# 2026-11-02 — шрифты по письменности в серверных PDF

Ветка claude/pdf-noto-fallback (от #583 с Noto). `apps/api/src/common/pdf-fonts/pdf-fonts.ts`: строка делится на куски по письменности, каждый рисуется Inter или Noto (арабский/иврит — с разворотом порядка, настоящий Unicode BiDi (UAX#9, bidi-js): уровни, перестановка кусков, зеркальные скобки, цифры и латиница остаются слева направо, абзац арабского/иврита прижат к правому краю; индийские, тайский, кхмерский, лаосский, бирманский, грузинский, армянский, эфиопский). Все 5 генераторов PDF (pdf-common, история дел, юр. выгрузка, квитанция, пакет спора) идут через `applyPdfFonts`. CJK (SC/JP/KR) качается с CDN при старте API и воркера (sha256, диск-кэш), только когда в manifest.json `uploaded: true` (SC/JP/KR залиты, uploaded:true); иероглифы Han берут шрифт по языку документа (ja→JP, ko→KR, иначе SC; кана → JP); реальная загрузка с CDN из облака не проверена (прокси 403), проверено моками. Пробелы рисует Inter (pdfkit терял пробел в шрифтах Noto). Ограничение: выравнивание center/right/justify для RTL не переписано, только left→справа; язык в applyPdfFonts пока не передают генераторы. Тест `pdf-fonts.spec.ts` проверяет все 85 языков из xlsx: у каждого знака (кроме CJK и значков-символов) есть глиф в выбранном шрифте. На устройстве/в Acrobat не проверялось, только pdftoppm. SHA: допишу после слияния.
