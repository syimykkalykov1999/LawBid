# 2026-11-02 — шрифты по письменности в серверных PDF

Ветка claude/pdf-noto-fallback (от #583 с Noto). `apps/api/src/common/pdf-fonts/pdf-fonts.ts`: строка делится на куски по письменности, каждый рисуется Inter или Noto (арабский/иврит — с разворотом порядка, настоящий Unicode BiDi (UAX#9, bidi-js): уровни, перестановка кусков, зеркальные скобки, цифры и латиница остаются слева направо, абзац арабского/иврита прижат к правому краю; индийские, тайский, кхмерский, лаосский, бирманский, грузинский, армянский, эфиопский). Все 5 генераторов PDF (pdf-common, история дел, юр. выгрузка, квитанция, пакет спора) идут через `applyPdfFonts`. CJK (SC/JP/KR) качается с CDN при старте API и воркера (sha256, диск-кэш), только когда в manifest.json `uploaded: true` (SC/JP/KR залиты, uploaded:true); иероглифы Han берут шрифт по языку документа (ja→JP, ko→KR, иначе SC; кана → JP); реальная загрузка с CDN из облака не проверена (прокси 403), проверено моками. Пробелы рисует Inter (pdfkit терял пробел в шрифтах Noto). Выравнивание left/center/right для RTL и смешанных строк считается по измеренной ширине; длинные абзацы переносятся по словам с BiDi на каждую строку (направление абзаца общее), высота строки — по самой высокой гарнитуре. Язык документа (ui_language) передают история дел, квитанция, пакет спора, юр. выгрузка, документы из шаблонов (язык шаблона), счета, листы подписей; договор-запись сделки (deal record) язык не получает (общий документ двух сторон, воспроизводимый хэш). CDN: с Мака проверено, что три CJK-файла отдаются 200, font/otf, ~15,7 МБ, immutable (по сообщению Mac-треда). Тест `pdf-fonts.spec.ts` проверяет все 85 языков из xlsx: у каждого знака (кроме CJK и значков-символов) есть глиф в выбранном шрифте. На устройстве/в Acrobat не проверялось, только pdftoppm. SHA: допишу после слияния.
