# 2026-11-02: списки «Мои кейсы», каналы, уведомления, консультации открываются из копии телефона

**Что искали и где.** Копия первой страницы на диске уже есть у всех GET: `HttpCacheInterceptor` (ключ = пользователь|язык|URL, ETag, лимиты, очистка в «Данных и памяти»). Но она использовалась только для 304 — первый экран ждал сеть. У чатов, групп и ленты есть `cachedFirstPage` на своих копиях (`SavedJson`), у этих четырёх списков не было ничего.

**Что сделано.** `readFromPhoneOnly(() => repo.method())` (`core/cache/http_cache_interceptor.dart`): внутри все GET отвечаются из копии телефона без запроса, любого возраста; нет копии → ошибка, в сеть не идёт (значение зоны, сигнатуры репозиториев не менялись). Четыре списка подключены через существующий `PagedNotifier.cachedFirstPage`; живая первая страница заменяет копию (`phoneCopy` в `SyncedListNotifier`: холодный старт читает первую страницу, обычно 304, а не дельту от времени, которое старше копии). Нового хранилища нет.

**Не затронуто.** Поиск и discover каналов (ранжирует сервер). Другие списки «Мои работы/ставки» и т.д. — тем же двумя строками, отдельно.

**Осталось / не проверено.**
- На устройстве не проверено: холодный старт, офлайн, 304.
- Копия берётся только при первом построении списка; после `invalidate` (правка, повтор после ошибки) читается живая страница.
- Окно чтения копии с диска (`diskReadWait` 1,5 с) длиннее лимита списка (1 с): на очень медленном диске копия может не успеть, тогда список ждёт сеть как раньше.
- Другие списки («Мои работы», ставки, сохранённые) подключаются тем же `phoneCopy(...)`, отдельно.
