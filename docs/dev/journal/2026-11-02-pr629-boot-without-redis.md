# 2026-11-02 · старт и остановка API без Redis не висят

Из проверки влитого #615 на стенде (PR #606, «проверка Redis»): без Redis API не открывал порт 90+ с (на ECS — цикл перезапусков). Трассировка хуков Nest нашла два класса ожиданий: `await subscribe()` на pub/sub-дубликатах (`SecretsService`, `ShardMapSync`) и `await setGlobalConcurrency()` BullMQ (`GroupFanoutQueue`); на остановке симметрично висят `quit()` и `Queue.close()`. PR #629: https://github.com/syimykkalykov1999/LawBid/pull/629.

Сделано: `backgroundSubscriber()` (сам создаёт pub/sub-дубликат, подписка без ожидания, повтор на `ready`, `close()` без зависания) в `SecretsService`, `ShardMapSync` и на остановке `RealtimeGateway`; настройка concurrency группового fan-out в фоне. `Queue.close()` BullMQ на общем соединении не виснет (пробник при `/simplify`), поэтому границ на него нет. Проверено на стенде: порт открывается через 30 с без Redis (`ready` 503), остановка без Redis 24 с с кодом 0 (было 65 с и SIGKILL), после появления Redis `ready` 200 за <1 с, подписки и concurrency применились.
