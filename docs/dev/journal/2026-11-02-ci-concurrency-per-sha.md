# 2026-11-02 · CI: проверки пуша в main не вытесняют друг друга

02.11 в 11:05 шесть слияний подряд дали шесть пушей в main. У workflow с `concurrency: group: <имя>-${{ github.ref }}` одна ждущая очередь на группу: новый ждущий запуск отменяет прежний ждущий, даже при `cancel-in-progress: false`. Так API CI, Admin CI и Secret scan на 13a03df24 (#598) стали cancelled, а гейт Deploy («Wait for green CI») на этом коммите стал красным (Deploy #342).

Правка: для не-PR событий группа включает `github.sha` (api-ci, admin-ci, mobile-ci, secret-scan, codeql, repo-guards). У PR группа прежняя (`github.ref`), старый прогон PR по-прежнему отменяется новым. Пуш каждого коммита в main теперь идёт в своей группе и доезжает до конца.
Deploy не менялся: он и должен собирать только последний коммит, его гейт теперь не краснеет от вытеснения.
SHA: см. слияние в main.
