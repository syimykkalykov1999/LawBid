# 03.11 Звонки iPhone: «Отклонить» доходит до звонящего; нет «Входящий звонок» рядом с CallKit

Ветка `claude/calls-ios-decline`. Только путь входящего / отклонения.

1. «Отклонить» на iPhone (Android → iPhone), Samsung оставался в звонке:
   - приложение живо: плагин flutter_callkit_incoming 3.1.6 шлёт событие decline с данными ПОСЛЕДНЕГО звонка из VoIP-пуша; повторный VoIP-пуш того же звонка (сокет успел первым) показывается и сразу закрывается как «пустышка» (AppDelegate.reportThrowaway) — и отклонение уходило на сервер со случайным id пустышки (404). Исправление: `systemDeclineTarget` в callkit_bridge.dart (iOS: звонящий здесь звонок, которого больше нет на системном экране, — тот, что отклонили).
   - приложение закрыто: VoIP-пуш будит только запасной движок (`callkitPushEntry`, пустой, без сессии) — отказ никуда не уходил. Исправление по README плагина (`onDecline`): AppDelegate сам шлёт `POST /calls/:id/status/decline {t}` с билетом звонка из VoIP-пуша, один повтор, потом `action.fulfill()`.
   - сервер: новый маршрут без сессии (по билету `pollToken`, как `GET /calls/:id/status`), идемпотентный; VoIP-пуш несёт `pollToken`. Страховка (таймаут звонка 65 с + `calls.sweep` раз в минуту) уже была, покрыта тестом.
2. «НЕОТЛОЖНЫЕ · Входящий звонок» на iPhone: FCM-пуш звонка пропускает iPhone, позвонивший по VoIP, сравнивая session_id токенов; FCM- и VoIP-токен привязаны к разным строкам сессии одной цепочки (обновление токена добавляет строку) — алерт приходил вместе с CallKit. Исправление: сравнение по цепочке входа (`fcmTokensCoveredBy`).

Проверено: API jest calls + push (37 наборов, 336 тестов), flutter analyze 0, flutter test test/features/calls (288). Не проверено: живой iPhone (закрытое приложение, экран блокировки, баннер, открытое приложение), Swift не компилировался локально.

Правки по ревью #693: отказ пишет «declined» только из состояния «звонит» (ответ между чтением и записью остаётся ответом); нативный отказ не шлётся, если прошло ≥ длины звонка (это таймаут, «нет ответа»); лимит маршрута 30/мин на IP; `req.body.t` скрыт в логах; e2e на отказ по билету рядом с owner-call-cancel-status.

iPhone → Samsung (ретест 03.11 18:05, у Samsung заработал FCM): при открытом приложении FCM-пуш звонка приходит в `onMessage`, тот вызывал `ringFromPush` без системного экрана звонка, а `call:incoming` из сокета для того же звонка отбрасывался как дубль (контроллер уже «звонит») — на экране ничего, звонящий звонит до конца, потом «пропущенный». Исправление: `ringFromPush(showSystemUi: true)` из `onMessage`; повторный показ гасит общий «claim» звонка. Тесты на оба порядка и на гонку.
