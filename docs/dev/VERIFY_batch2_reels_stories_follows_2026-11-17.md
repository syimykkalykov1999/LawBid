## ✅ Работает (проверено)

- Путь видео: сжатие на телефоне → TUS прямо в Bunny → в базе только guid и id библиотеки → просмотр через подписанный CDN (HLS) с проверенным MP4 на запас; байты видео через API не идут.
- Вебхук Bunny: HMAC по сырому телу (запасной токен), сравнение за постоянное время, данным вебхука не верим (перечитываем Bunny), переход статуса один раз (условный `updateMany`).
- Зависшее кодирование: опрос через 60 с, `encoding_timeout` через 3 ч, `upload_expired` по сроку; «готов, но processing» лечится.
- Истории: просмотр один раз на зрителя (`skipDuplicates` по PK), счётчик только при новой строке; срок 24 ч, удаление, модерация, аудитория, «скрыть от», блоки — во всех выдачах.
- Курсоры рилсов/историй/зрителей — время пишет Prisma (мс), пропусков нет; индексы `stories_author_created_idx`, `stories_expires_idx`, `story_views_*`, `posts_reels_created_idx` покрывают запросы.
- Подписки: двойное нажатие не двигает счётчики (`skipDuplicates` + число удалённых), блок снимает подписки в обе стороны в транзакции, подписка через блок запрещена; списки по `(created_at desc, id desc)` с индексами; закрытых аккаунтов и запросов на подписку в продукте нет.
- Рекомендации: запросы ограничены (600 + пул 300), тяжёлый расчёт только при пустом кэше (10 мин), после подписки/блока выдача снова фильтруется — устаревания нет.
- **Вторая сторона:** F1 — у адвоката одна строка уведомления и одна строка подписки; V1/V2 — после удаления видео его нет и в Bunny.

## Не исправлял — решить отдельно

- Лента историй у зрителя не обновляется до перезапуска (`stories_providers.dart:50`, не autoDispose). Сейчас истории выключены (`storiesEnabled = false`), поэтому не видно; перед включением — обновлять при возврате в приложение.
- Поиск внутри списка подписчиков (`follows.service.ts:663`) берёт все id списка и ищет по ним (до 5000 без порядка) — на 200 тыс. подписчиков тяжело и может терять совпадения. Нужен JOIN с лимитом; правка затрагивает поиск — в пачку 6 (поиск).
- ETag списка подписчиков (`follows.service.ts:383`) считает `count(*)` на каждое открытие — для популярного адвоката миллион строк индекса. Лучше брать сохранённые счётчики; вместе с пунктом выше.
- Блок снимает подписки без «надгробий» (`blocks.service.ts:73`) — `?updatedSince` не вернёт удалённую подпись. Приложение этот путь не использует (только нагрузочные тесты) — низкий приоритет.
