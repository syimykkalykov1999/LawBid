**Глобальный ключ повтора — границы (вопрос координатора 17.11):**
- *Вебхуки и анонимные запросы* (Stripe, Bunny, SES/SNS, Twilio, вход): глобальная копия их не трогает вовсе — работает только для вошедшего пользователя. Маршрут, который сам подключал перехватчик (вход, SMS), ведёт себя как раньше. Тест: «an anonymous request (a webhook) passes untouched, even with a key».
- *Тот же ключ с другим телом*: у маршрутов, где перехватчик стоял сам, — как раньше, 409 `payload_mismatch`. Глобальная копия на таких маршрутах отходит в сторону (тест «steps aside…»). На остальных другое тело под старым ключом выполняется как новый запрос (например, отправка файлов дела из очереди с постоянным ключом задачи и новыми id файлов), а не 409 навсегда (тест «a new body under the key runs as new»).
- *Границы ключа*: `idempotency:<пользователь>:<метод>:<адрес>:<ключ>` + отпечаток тела. Один и тот же ключ у двух людей — два разных ответа, чужой ответ не отдаётся (тест «two people with the same key…»). У анонимных маршрутов прежняя общая часть `anon` — там повтор отдаётся только при совпадении адреса, ключа и тела, как было до этого PR.

## ✅ Работает (проверено)

- Комментарий: создание, ответ, ответ на ответ (в ветке), лайк комментария (одна строка `comment_likes`, `ON CONFLICT DO NOTHING`), удаление автором или автором поста, с ответами; счётчики через агрегатор. **Вторая сторона:** B5 — у другого человека счётчик `1 → 0`, список пуст после удаления.
- Новые комментарии приходят в открытый лист сразу (`comment:new` в комнате поста), удаление видно при следующем открытии (как у Instagram).
- Выключенные комментарии скрыты, не удалены; модерация «hold» в очередь; блок в обе стороны.
- Индексы комментариев: `(post_id, created_at DESC, id DESC)`, `(parent_comment_id, created_at)`, `(author_id)`; N+1 нет (авторы, лайки, аватары — по одному запросу на страницу).
- Комментарии в деле (`case-comments`): та же схема, правка в окне `case_comments.edit_window_minutes`, ответ на ответ теперь тоже доходит до нужного человека (п. 2).
- Упоминания: одно уведомление на человека, блоки, не себе (#1213 P6).
- Звёзды: баланс не уходит в минус (условный UPDATE + `CHECK balance >= 0`), книга и баланс в одной транзакции с `ON CONFLICT (idem_key)`, оплата пакета зачисляется один раз, возврат и обмен подарка — один раз, получатель подарка получает уведомление `gift_received`.
- Пост: создание с обязательным ключом, одна строка на черновик, счётчик постов автора двигается ровно один раз на каждое действие; лента не показывает удалённые, архивные, задержанные, заблокированных; курсор ленты без дублей и пропусков; запросы ленты попадают в индексы `posts_author_visible_idx`, `posts_visible_created_idx`.
- Путь медиа (сжатие на телефоне → прямая загрузка → в базе только ключи → CDN) — #1213 P11–P16.
- Версии: пакеты этой пачки на последних стабильных (сверка #1213 `versions.sh`); исключение — TypeScript 6.0.3 при 7.0.2, им занимается PR №6 соседа (#1213 → cmv-fixes).

## Не исправлял (мелко или чужая зона) — решить отдельно

- Повторный «Поделиться» за сутки: приложение рисует +1, сервер считает один раз в сутки (`social_providers.dart:1168`). Мелочь, расхождение до следующего обновления поста.
- Дневной тормоз подарков (`stars.service.ts:722`) считается вне транзакции: параллельные отправки могут превысить лимит. Каждый подарок при этом оплачен, деньги не теряются.
- Подарок в чате при двух базах (`readsAreSplit`) списывается своей транзакцией до записи сообщения: если запись сообщения упадёт, списание останется. Это путь чата — передано помощнику чатов (пачка 4). Повторы HTTP теперь закрыты п. 1.
- Уведомление о комментарии остаётся после удаления комментария (Instagram убирает). Открывается «пост недоступен/комментария нет», не ломается.
- Такие же «микросекунды против курсора» есть у `notifications` (сырой INSERT) — пачка 8.

## Что взято у больших и откуда (законно)

- **Idempotency-Key на каждом POST** — как у Stripe (ключ на любом POST-запросе, повтор отдаёт сохранённый ответ, 24 ч; docs.stripe.com/api/idempotent_requests). Код свой, уже был в проекте; поменялось только подключение (глобально вместо отдельных маршрутов). Стороннего кода нет.
- **«@ник» перед ответом на ответ только настоящим ником** — как Instagram и Threads (ответ в ветке начинается с @username того, кому отвечают). Идея, не код.
- **Один файл — один пост, уникальный индекс** и **индекс под порядок списка** — обычная практика PostgreSQL (`CREATE UNIQUE INDEX CONCURRENTLY`, документация PostgreSQL 18). Стороннего кода нет.
- Лицензии: новых библиотек нет; брендов, иконок, текстов чужих приложений не брал.
