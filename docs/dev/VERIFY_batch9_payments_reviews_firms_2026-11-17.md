## ✅ Работает (проверено)
- Вебхуки Stripe: `stripe_event_id` — первичный ключ, повтор не обрабатывается дважды; `jobId = event.id`; потерянные задачи досылаются по индексу.
- Обработчики подписок, счетов и зарядов перечитывают объект из Stripe, а не верят снимку события.
- Книга: проверка баланса и положительных сумм, уникальный ключ записи, запись в той же транзакции, что и денежная строка (счёт, возврат по делу, спор, отмена возврата).
- Возврат по делу: резерв под `FOR UPDATE`, сверка с Stripe считает и зарезервированное; ключевой (админский) путь повторяет тот же ключ.
- Возврат платформы и автовозврат по спору: serializable, уникальный ключ спора, условный захват.
- Покупка мест, переход на год, «Горячая линия», создание подписки, клиента Stripe и Connect — ключи идемпотентности.
- Деньги только в целых центах; округление вверх при надбавке; настройки комиссий ограничены.
- Списки платежей — курсор, без N+1; выгрузка CSV ограничена. ETag у `GET /plans` меняется при смене цены.
- P8 (индексы `payments.stripe_payment_intent_id`, `case_payments.stripe_charge_id`): **ложная находка** — индексы уже есть (`prisma/concurrent/20261115090000_data_layer_lookup_indexes.sql`).
- Рейтинг адвоката: один UPDATE…SELECT в той же транзакции + ночная сверка; модерация пересчитывает; кэш профиля по `updated_at`.
- Двойной отзыв по одному делу — уникальный `case_id`; самоотзыв запрещён; голоса «полезно» у отзывов об адвокатах — serializable.
- Доступ команды фирмы читается живьём на каждой проверке (без кэша членства); чужая фирма не видна; передача владения — условная запись.

- Жалоба на отзыв о клиенте: двойное нажатие может дать две открытые жалобы (так же устроено во всех модулях жалоб — править вместе с пачкой 10).
- Рабочий стол админки: очереди зарплат и денег без фильтра страны (их видит только владелец).

## Что взято у больших и откуда (законно)
