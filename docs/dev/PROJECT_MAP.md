# LawBid — карта проекта (читать вместо старых переписок)

Любая новая сессия или помощник работает ПО ЭТОЙ КАРТЕ. Старые переписки читать не нужно.
Порядок чтения: этот файл → [`AGENTS.md`](../../AGENTS.md) (правила) → [`KNOWN_ERRORS.md`](KNOWN_ERRORS.md) (грабли).

## 1. Самые главные правила (подробно — AGENTS.md)
0. Берём готовое ЦЕЛИКОМ и не смешиваем со своим: ломается именно из‑за смеси нашего нерабочего кода с кусками чужого. Наш заменённый код удаляем, подключаем только по краям (наши экраны, вход, уведомления). Чужой код своими заплатками не «чиним».
1. Только копируем проверенный открытый код (MIT/Apache/BSD). Свой код — только если готового нигде нет И владелец прямо разрешил.
2. GPL/AGPL и код, требующий открыть наш, — не копировать; изучить и построить так же, без придумывания.
3. Каждый чужой файл — проверка на вирусы и опасные строки (отправка данных на чужие серверы, скрытый код, установочные скрипты).
4. Правила одинаковы для iPhone, Android, сайта, админки, сервера.
5. Внешний вид приложения не меняем без прямой просьбы владельца.
6. Лёгкость: телефон не греется, сервер не пропускает файлы через себя, кэш везде, качество как Instagram.
7. Экономия токенов: одна задача за раз, не больше 3–4 помощников, проверки — программами.
8. Честный отчёт: проверено / не проверено / сломано. Никаких «всё работает» без проверки.

## 2. Владелец
- Не программист. Отвечать по‑русски, коротко, простыми словами. Команды для него — блоками Run.
- Пароли и коды за него не вводить. Продакшн‑изменения (terraform apply, IAM, SSM, деплой Approve) нажимает он.
- Ждать, пока владелец договорит, и только потом начинать.

## 3. План работы (по пунктам, строго по порядку)
Для каждого пункта: найти готовый источник → проверить на безопасность → скопировать, поменять только названия → проверить на ноуте → телефоны.

**Волна A — основа:**
1. Звонки, полностью (аудио и видео; заблокированный экран на iPhone и Android; ответить, отклонить, сброс, завершить, пропущенный; аватарка и имя ЗВОНЯЩЕГО на системном экране и в уведомлении; значок идущего звонка; переподключение; микрофон, камера, динамик, смена камеры; маленькое окно; завершение без зависшего кадра). Источники: LiveKit (Apache‑2.0), flutter_callkit_incoming (MIT; НЕ копировать отправку логов на events.hiennv.com из его примера), flutter-webrtc (MIT).
2. Кэширование: телефон → CDN → Redis.
3. Передача кусками и загрузки всех файлов напрямую в хранилище, сжатие на телефоне без потери качества.
4. Серверы, база, Redis, балансировщик, автодобавление и автоуменьшение серверов — сверка с AWS Well‑Architected.

**Волна B — функции:** поиск, чаты, ленты, сетки, показы, вход, комментарии, уведомления, профиль, шторки, рилсы и плееры.

**Волна C:** то же самое для сайта и админки.
