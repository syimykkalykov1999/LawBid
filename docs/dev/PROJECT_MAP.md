## ОБЯЗАТЕЛЬНО перед любым PR/пушем/слиянием (CI-протокол, аудит 01.11)
Подробно: [`CI_CHECKLIST.md`](CI_CHECKLIST.md) (причины красного) и [`CI_FAILURES_AUDIT_2026-11-01.md`](CI_FAILURES_AUDIT_2026-11-01.md) (корни и что починено).
1. **До первого пуша:** `git fetch origin main && git merge origin/main` → `npm run precheck` → перед ПОСЛЕДНИМ пушем `npm run precheck:full`. Один пуш = один полный прогон CI (~40 мин), не «пушу и смотрю».
2. **Генераторы — ПОСЛЕ мерджа main:** схема Prisma → `npm run db:erd --workspace apps/api`; контроллеры/DTO → `sh packages/api-contract/generate.sh`; новые строки UI → `node scripts/i18n-add.mjs …` + `node scripts/i18n-audit.mjs --ci`; новый кросс-модульный импорт → `UPDATE_BOUNDARIES=1 npx jest architecture/module-boundaries`; путь в `AndroidManifest.xml` → тот же в `scripts/seo/well-known.mjs` APP_PATHS. Закоммитить результат.
3. **Красный шаг:** открыть лог (`gh api repos/…/actions/jobs/<id>/logs`), найти `FAIL … ›` / `##[error]`, чинить причину. Перезапуск — один раз и только при сетевом сбое (cocoapods/DNS/Trivy-зеркало). «Флак» не причина.
4. **Тесты:** даты только относительные (от `Date.now()`); проверка `TIME_SHIFT_DAYS=45 npx jest --setupFiles '<rootDir>/../test/time-shift.setup.js' <spec>`. Тест не ходит в интернет. e2e-флак → в `apps/api/test/quarantine.json` с датой и причиной (максимум 3 дня), чинить; тест не отключать и не удалять ради зелёного.
5. **Защита main:** единственный required check — **«CI gate»** (включает владелец: Settings → Rules). Новые проверки без path-фильтра класть в `.github/workflows/repo-guards.yml`.
6. **Стек PR:** после слития A сразу `base` B → `main`. Ветка живёт ≤ суток без мерджа main. Своя ветка: новый коммит поверх, не force-push.
7. **Никогда:** пустой коммит или закрыть/открыть PR ради CI; `--no-verify`; чужой/Dependabot PR не чинить без команды владельца; секрет-подобные фейки в файлах (`test-…-token`, иначе gitleaks); `graphify-out/` в коммит; слияние красного PR; сборки на телефон не по делу.
8. Нашёл новую причину красного — строка в `KNOWN_ERRORS.md` в тот же час.

## 1. Самые главные правила (подробно — AGENTS.md)
0. Берём готовое ЦЕЛИКОМ и не смешиваем со своим: ломается именно из‑за смеси нашего нерабочего кода с кусками чужого. Наш заменённый код удаляем, подключаем только по краям (наши экраны, вход, уведомления). Чужой код своими заплатками не «чиним».
1. Только копируем проверенный открытый код (MIT/Apache/BSD). Свой код — только если готового нигде нет И владелец прямо разрешил.
2. GPL/AGPL и код, требующий открыть наш, — не копировать; изучить и построить так же, без придумывания.
3. Каждый чужой файл — проверка на вирусы и опасные строки (отправка данных на чужие серверы, скрытый код, установочные скрипты).
4. Правила одинаковы для iPhone, Android, сайта, админки, сервера.
5. Внешний вид приложения не меняем без прямой просьбы владельца.
6. Лёгкость: телефон не греется, сервер не пропускает файлы через себя, кэш везде, качество как Instagram.
7. Экономия токенов: одна задача за раз, не больше 3–4 помощников, проверки — программами.
8. Честный отчёт: проверено / не проверено / сломано. Никаких «всё работает» без проверки.
