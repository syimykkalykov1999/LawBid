## Решения по образцу больших платформ
- **B3.** Значки раздела видят только те, кто может открыть раздел (как бейджи в Stripe Dashboard и Zendesk: счётчик очереди показывается только агентам с доступом к ней).
- **B6.** При смене роли права обрезаются, а не отклоняются. Так делают Google Workspace и Stripe: права идут вместе с ролью. Обрезка записывается в журнал.
- **B7, A5, C1.** Перед действием, которое расширяет доступ или его не отменить, просим свежий код 2FA (re-auth в Stripe, sudo mode в GitHub). Отключить человека по-прежнему можно сразу. Владельца ничто не ограничивает, кроме кода 2FA.
- **D2.** День оплачивается по тарифу, который действовал в конце этого дня. Изменение «с завтрашнего дня» к прошедшему дню не применяется.

## Проверено, ошибок нет
- Охрана админки: без `@Roles` маршрута нет. Роль и права читаются из базы при каждом запросе. Путь с другим регистром букв или с неизвестным разделом закрыт (404). Раздел, куда нет прав, отвечает 404 и пишется в журнал. Просмотр денег пишется в журнал до выдачи данных (если записать нельзя, ответ 503).
- TOTP по RFC 6238: окно ±1 шаг, повтор того же кода запрещён на 95 с, сравнение за постоянное время. Пароли: scrypt с параметрами OWASP; для несуществующего логина используется пустой хеш, поэтому ответ приходит за то же время.
- Сессии: Postgres + Redis, 8 часов максимум, 30 минут простоя (фоновый опрос сессию не продлевает). Сессии завершаются при смене роли, отключении, удалении, сбросе 2FA и смене пароля.
- Последний суперадмин защищён транзакцией serializable. Нельзя действовать на себя. Заместитель и глава выдают только то, что есть у них самих и в пределах потолка.
- Журнал: страницы по ключу `(created_at, id)`, индексы есть, ETag учитывает, чьи строки показаны. Выгрузка в S3 идёт в NDJSON, поэтому подстановка формул (как в CSV) невозможна.
- Дашборд: снимок от воркера раз в 2 минуты, итоги раз в день. Отчёт о доступах — сохранённый снимок. Тяжёлых живых запросов нет.
- Настройки: проверка версии внутри serializable с повтором, 409 возвращает свежую строку. Платные выключатели не включаются без ключей. Журнал пишет «до» и «после» в той же транзакции.
- Сдельная оплата: целые центы, одна строка — одно начисление, повторы идемпотентны. Спорный день не пересчитывается.
- Проверка решений: завершает только `updateMany WHERE status='pending'`. Свои решения проверять нельзя.

## Ложные или не ошибки (не менял)
- **B4.** Говорилось, что ETag списка людей перебирает всю таблицу. Ложно: индекс `users_live_updated_at_idx` уже есть в `prisma/concurrent/20261122090000_admin_list_etag_indexes.sql` (помощник смотрел только `migrations/`).
- **A4.** Неверные попытки входа по логину владельца ограничены 10 в час, поэтому чужие попытки могут временно не пускать владельца. Это защита от подбора пароля, ослаблять её нельзя (правило «не ослаблять защиты»). Пароль восстанавливается через секретный вопрос (5 в час) или консоль.
- **B9 (b).** Списки админов и сессий ограничены 500 строками. Это объём, а не ошибка: админов единицы.
- **B9 (c).** Почта в общем списке людей показывается так задумано. Для сотрудника без персональных данных она маскируется (A3).
- **C7.** Публичный bootstrap отдаёт технические выключатели (`files.*`, `cache.*`, `stickers.*`, `media.*`). Секретов в них нет, а приложение их читает. Если их убрать, приложение сломается.
- **D10.** Одно решение по заявке учитывается только один раз за 3 дня. Так задумано: повторные отчёты одного и того же решения не должны считаться дважды.

## Осталось (не исправлял, причина)
- **«Авто» — не трогаю:** ключи `budget.*` и `cost.*` в общем редакторе настроек (C1, C5, null = «авто») читает автоматика расходов. Ограничение «только владелец» на них и возврат к пустому значению лучше решить вместе с владельцем «Авто».
- **B5.** Дашборд один на всю платформу. Партнёр страны видит общие числа: новых людей, подписки, открытые дела. Ограничить их страной можно только новым снимком по странам, а это новое: пропущено.
- **B8.** «Восстановить» не отменяет повторную оценку связанных аккаунтов после блокировки. Нужно проверить `client-fraud` (пачка 10).
- **B9 (a, d).** Счёт мест в команде включает отключённых. Двойной клик при создании шаблона даёт P2002. Мелочи, тесты не писал.
- **C3.** Bootstrap может сохранить под новым тегом старый набор настроек, если чтение таблицы на другом экземпляре началось до сохранения. Тег сам сменится через 5 минут (окно тега). Правка затрагивает общий кэш, поэтому её стоит делать отдельно.
- **C8.** Карточки настроек, которые сохраняют без версии (`AppSettingsWriter`, бюджеты), при одновременном сохранении теряют одно из изменений: побеждает последнее. Чтобы это исправить, нужно передавать версию из каждого экрана. Внешний вид при этом не меняется, но работа объёмная; оставлено на отдельный PR.
- **D3.** Кнопка «Готово» на столе засчитывает единицу, даже если решения по задаче не было. Для поддержки ответ без закрытия тоже законченная работа, поэтому правило «что считать оплачиваемой единицей» по очередям нужно задать отдельно. Сдельная оплата сейчас выключена (`staff.piecework_enabled`).
- **D13, D14, D15.** Разница за уже выплаченный день видна только в одном прогоне. Калибровочную копию может проверять сам автор решения. Лимит показа персональных данных считается по дню UTC. Глава видит общую сумму своей области. Всё это мелочи, оставлены на следующую пачку.
