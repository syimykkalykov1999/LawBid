## Не дыры (проверено, почему)
- **Внешние ключи без индекса** (около 50, например на `users`, `calls`, `assistant_memberships`). Строки этих таблиц на проде не удаляются: люди обезличиваются, жёстко удаляет только демо. Поэтому проверка ключа при удалении не запускается.
- **Уборка «живые звонки, участник молчит / не ответил»** (раз в минуту). EXPLAIN на 300 000 звонков и 900 000 участников: план идёт от горстки активных звонков, 11 мс и 0,4 мс. Индекс не нужен.
- **Прокси админки ставит `private, no-cache` при ETag** (вместо `private, max-age=30` у дашборда). Так сделано нарочно ради свежести после действий админа: цена — один ответ 304 за опрос. Ошибки API и так `no-store`, а повторная проверка ошибку из кэша не отдаёт.
- **Ответ 304 оставляет `public`** у bootstrap, юридических документов и переводов. Общего кэша перед API нет (CloudFront `/api/*` = CachingDisabled), а тело одинаково для всех. Утечки нет.
- **`GET /config/flags` с `no-store`.** Так задумано: меньше одного запроса за открытие, экономить нечего.
- **Нет обработчика `error` у части воркеров.** BullMQ сам ловит ошибку и пишет её в stderr, процесс не падает, журнал её видит.
- **Очередь мёртвых вебхуков без воркера.** Так задумано: админ переигрывает её по 200 за нажатие, число видно на странице здоровья.
- **SCAN по всем ключам при стирании человека.** Редкая операция, не горячий путь.
- **Клиенты Redis воркеров в режиме кластера не закрываются через QUIT** (P3). Кластер на проде выключен; процесс всё равно завершается после `app.close()`.
- **Сжатие:** `compression` (порог 1 КБ, brotli 4 + gzip), SSE пропускается, двойного сжатия нет. **ETag:** слабый, считается до сжатия, `If-None-Match` со списком и `*` обрабатывается. **Остановка:** `enableShutdownHooks` в API и воркере, keepAliveTimeout 310 с больше простоя ALB 300 с, stopTimeout воркера 120 с больше бюджета 95 с.

## Осталось (не код этого PR — почему)
- **W1. Размер задачи воркера, terraform — делает только владелец.** В `infra/modules/ecs` по умолчанию `worker_memory = 1024`, а у ClamAV `memoryReservation = 2560`. Работает только потому, что в tfvars прода стоит 4096 (`launch.tfvars.example`). Сверить настоящий tfvars прода и поднять умолчание или добавить проверку `worker_memory >= clamav_memory + 1024`.
- **C1 / D1. CloudFront, terraform — делает владелец.** `/api/*` стоит в CachingDisabled, поэтому `s-maxage` у гостевых ответов (поиск, профили) не работает. У CDN документов `Accept-Encoding` входит в ключ кэша при `compress = false`, и один файл может лежать до трёх раз. Ничего не ломается, это экономия.
- **T1 / T2.** В Dockerfile стоит `UV_THREADPOOL_SIZE=8`, а описание terraform считает умолчанием 4 (расхождение в описании). Воркер берёт ~64 задачи сразу при пуле базы 6–10: смотреть ожидание пула на странице здоровья под нагрузкой.
- **DB1, остаток.** Уборка файлов по-прежнему раз в час проходит все живые файлы, но теперь каждая проверка — поиск по индексу (1,9 с на 400 000 файлов). Чтобы не проходить всё, нужен сохраняемый курсор. Это уже новая логика, в эту проверку не входит.
- **X7. Уборка видео без поста** (раз в минуту) проходит все готовые видео, проверки по индексам. Ограничить окно нельзя, не потеряв видео, у которых пост удалили позже. Нужна пометка «проверено» — тоже новая логика.
- **X11. Пересчёт доверия по одному адвокату за раз** (ночью). Файл `attorney-trust.service.ts` сейчас правит открытый PR #1251 (проверка 9). Пакетное чтение — после его слияния.
- **X13.** Сверка платежей за окно идёт без индекса по `paid_at`. Раз в сутки, таблицы небольшие.
- **Индексы удаляемых строк** для юридической очистки (сообщения, посты и так далее) — LD2 проверки 10 (`20261219110000_legal_retention_deleted_indexes.sql`). Ещё не слит, здесь не повторял.
- **Группы (Q3, Q7) и подсказки сообществ (N2)** — следующее обновление:
  - очереди `group-fanout-<n>` не видны на странице здоровья;
  - новый воркер может стартовать во время остановки;
  - подсказка сообщества держится 30 минут после блокировки.
