# Журнал известных ошибок (сборка, PR, деплой, прод)

Читать **перед** любой работой в этом репозитории: каждая ошибка здесь уже стоила кругов CI, падения деплоя или простоя.
Правило (владелец, 2026-10-28): каждая НОВАЯ причина красного PR, упавшего деплоя или сбоя прода дописывается сюда в тот же час, до запуска исправления. Номера не переиспользуются.

> **ПРАВИЛО №1 (самое главное, владелец 2026-10-28): не изобретать азбуку, когда есть готовый язык.** Есть проверенное открытое решение — берём его как есть (MIT/Apache/BSD: копируем целиком + строка в THIRD_PARTY_NOTICES; GPL/закрытый код — только идея, код свой). Наш остаётся только внешний вид, его не меняем. Отныне ТОЛЬКО копируем; свой код — только если готового нигде нет И владелец прямо разрешил. Каждый чужой файл — проверка на вирусы и опасные строки. Касается iPhone, Android, сайта, админки, сервера. Подробно: [`AGENTS.md`](../../AGENTS.md).

## A. Перед единственным пушем (почему PR краснели)
Каждый пункт стоил отдельного круга CI (~40 мин). Перед ЕДИНСТВЕННЫМ пушем обязательно:
1. **Mobile analyzer как в CI, по ВСЕМУ приложению:** `cd apps/mobile && flutter analyze` (CI падает даже на `info`, например `require_trailing_commas`). Анализ только изменённых файлов — недостаточно. После правок — `dart format <изменённые файлы>`.
2. **Gitleaks на свой диф:** `gitleaks git --log-opts="origin/main..HEAD" .` (установлен через brew). Фейковые токены/ключи в тестах называть «test-…-token», не случайной строкой вроде `tok-1-abcdefghijklmnop` или `practice.family_law…` в поле `*_key`.
3. **ERD после изменения схемы:** `npm run db:erd --workspace apps/api && git diff --exit-code -- docs/db/ERD.md`.
4. **Новая миграция:** первой строкой `SET LOCAL lock_timeout = '5s';` (squawk require-lock-timeout); проверить `npx squawk-cli@2.70.0 -c .squawk.toml <file>`.
5. **После merge main:** заново `packages/api-contract/generate.sh` (не contract:fast), oasdiff против main, `python3 apps/mobile/tool/ci/hardcoded_check.py`.
6. **Новые e2e в режиме двух баз:** вызов сервиса вне HTTP оборачивать в `shardContext.runForCase(...)`; прогнать `E2E_TWO_DB=all` для своего набора.
7. **Стек PR (B на ветке A):** после слития A сразу `gh pr edit B --base main`, иначе B сольётся в ветку A, а не в main.
8. **Не трогать чужие файлы форматированием:** никогда `dart format` по всему дереву.
9. **Сборки на телефоны:** `flutter build ... --release --flavor prod -t lib/main_prod.dart` (без `-t` приложение смотрит в dev-сервер).
10. **Деплой-проверки читают ответ API в обёртке `{data:…}`:** `/health/ready` → `.data.version`.
11. **Деплой запускается сам только при изменениях в apps/api, apps/admin, packages, package*.json или deploy.yml.** Правка в scripts/deploy/ или infra/ НЕ создаёт новый деплой: после такой правки нужен ручной запуск `gh workflow run deploy.yml --ref main` (кнопка владельцу), а ждущий старый деплой со старыми скриптами — отменить.

- **e2e 500 «column `bids.…` does not exist» у всех помощников (09.11, app-leftovers).** `prisma generate` в worktree с симлинком `node_modules` переписывает ОБЩИЙ клиент Prisma (`admin-speed/node_modules/.prisma`): пробная правка схемы попала всем, хотя в БД колонки нет. Схему в таком worktree не генерировать, пока миграция не нужна по-настоящему; после отказа от правки сразу `prisma generate` из схемы origin/main. Для `nest build` / `openapi:export` в таком worktree нужен свой tsconfig с `"preserveSymlinks": true` (иначе ложный TS2883).
- **Admin CI: «window is not defined» после всех тестов (05.11).** В админке нет vitest globals, поэтому Testing Library сама не размонтирует: рендер из последнего теста доигрывал уже без DOM, тесты зелёные, а прогон красный. В таком файле нужен `afterEach(() => cleanup())`.

- **«a new migration sorts before an already-released one» (05.11, #745).** PR долго ждал очереди, а в main вышли миграции с более поздней датой. Лечение: переименовать свою, ещё не выпущенную миграцию на дату после последней в main (`git mv`), перед слиянием сверять хвост `prisma/migrations`.
- **`api_error_codes_test`: «ApiErrorCodes.all is exactly the generated ErrorCode enum» (05.11, #779).** Новый код ошибки на сервере надо добавить и в `apps/mobile/lib/core/network/api_error.dart`: константу и строку в `all`. Каждый код, если их несколько.

- **iOS-сборка: «failed downloading … WebRTC.xcframework» (05.11, main, #755, #779).** Файл качается с релиза GitHub и часто обрывается. В CI кэш Swift-пакетов и до 3 попыток только на этой ошибке.

- **`resumable_download_pieces_test`: «an expired link» иногда падает (05.11, #755).** Запрос, отменённый в первой попытке, доходил до тестового сервера уже после очистки списка. Порядок запросов при параллельной работе в тестах не проверять; проверять наличие.
- **`resumable_download_pieces_test`: «the cut of an earlier try is kept when the admin number changed» — длина 8 вместо 5 (09.11, #862, run 42554319308).** Та же причина, что выше: отменённые части первой попытки дошли до сервера после очистки списка (повторы тех же диапазонов). Проверяется число разных диапазонов (`toSet()`), а не длина списка.

- **`dart format` до `flutter pub get` (09.11, ветка cases-sort-pins).** Без `.dart_tool` форматтер не видит `formatter: trailing_commas: preserve` из analysis_options.yaml, снимает запятые и переписывает целые файлы (15 файлов, +3600 строк). В свежем worktree сначала `flutter pub get` и `dart run build_runner build`, потом `dart format` только своих файлов; `flutter analyze` без codegen показывает тысячи ложных ошибок.
- **swagger_parser нумерует безымянные enum по порядку (09.11).** Новый query-параметр `enum` без `enumName` сдвигает `Sort` → `Sort2` → `Sort3` во всём Dart-клиенте и ломает приложение. Каждому новому enum в `@ApiPropertyOptional` давать `enumName`.
- **precheck «✔ API contract up to date», а контракт не пересобран (08.11, ветка claude/reco-experiments-wiring).** В worktree с `node_modules` по ссылке на `storage-usage` команда `nest build` падает на TS2742 («cannot be named without a reference to …/storage-usage/node_modules/@types/qs»), `generate.sh` молча не пишет `openapi.json`, и шаг зелёный. Признак: в `/tmp/precheck-gen.log` есть TS2742. Лечение: собрать без деклараций (`nest build -p` с tsconfig, где `declaration: false`), выгрузить `node dist/src/openapi/export-openapi.js` и взять из выгрузки только свои схемы (общий `node_modules` старее main, остальные места выгрузки отличаются не из-за PR), затем `SKIP_OPENAPI_EXPORT=1 sh packages/api-contract/generate.sh`.

- **API static, Unit tests: «Redis Cluster guard › has a written cluster reason for every multi-key Redis call» (09.11, #858).** Новый `.multi()` / `mget` / `del(a, b)` / SCAN в `apps/api/src` без строки в `src/redis/redis-cluster-scan.allowlist.json`. Прогон только «своих» модулей это не ловит: тест лежит в `src/redis`. Лечение: запись `{file, kind, reason}` (почему это один слот: один ключ или общий `{тег}`), порядок по file. Перед пушем любого кода с Redis: `npx jest src/redis src/architecture`.

- **Поднял лимит в DTO, забыл CHECK в базе и старые e2e (09.11, #884).** `PinPostDto` 6→10, но `posts_pin_slot_range` в базе оставался 1..6, а e2e `owner-pin-six` и `owner-chat-actions` проверяли старые лимиты. Перед сменой лимита: `grep -rn "<поле>" apps/api/prisma/migrations apps/api/test` — CHECK расширять миграцией (NOT VALID + отдельный VALIDATE), e2e с числом лимита обновлять в том же PR.
- **Общий хук сортировки в базовом классе ломает чужие списки (09.11, #884).** `arrange` по `order` в `SyncedListNotifier` начал пересортировывать каналы/группы (channels_select/channels_sync тесты). Новое поведение класть в mixin своей фичи (`CaseListSync`), не в общий базовый класс.

- **Экономия на фоновой задаче остановила рилсы (09.11).** `videos.sweep` стоял в списке «реже при простое» (ops.cron_idle_backoff, 25.10): если вебхук Bunny не дошёл, новый рилс ждал до 5 минут. Задачи, от которых зависит то, что видит пользователь (публикация видео, доставка), в «реже при простое» не класть.

- **«migrate-from-previous FAILED: … a new migration sorts before an already-released one» (09.11, #880).** Ветка создана раньше, чем в main вышли миграции с более поздней датой. Перед пушем: имя папки новой миграции должно быть позже последней в `origin/main` (`git ls-tree --name-only origin/main apps/api/prisma/migrations | tail`); переименовать папку, содержимое не трогать.

- **Деплой встал на «Wait for green CI»: Admin Lighthouse /users медиана TBT 307–317 мс при пороге 300 (10.11, #886).** Тот же код на main даёт 197–841 мс за 5 прогонов: страница держится у порога, шумный прогон краснеет и блокирует выкатку. Лечение сейчас: перезапуск упавшей проверки, затем `gh run rerun <deploy run>`. Настоящее лечение — облегчить загрузку /users (основной кусок ~235 КБ, ~850 мс скрипта при CPU x4), порог не трогать. Найденная причина (10.11, `next analyze`): все 36 файлов брали `m` из общего входа `motion/react`, и каждая страница сразу тянула весь движок анимаций (проекция раскладки, перетаскивание) — 69 КБ gz, хотя `LazyMotion` уже грузит возможности потом. Лечение по документации Motion («Reduce bundle size»): `import * as m from 'motion/react-m'`, с ним 27 КБ. Правило: `m` брать только из `motion/react-m`; из `motion/react` — только `AnimatePresence`, `LazyMotion`, `MotionConfig`, хуки. Проверено потом (10.11, PR #896): одно это проверку не вылечило (медиана 352). Локальный стенд как в CI показал: на нормальном процессоре /users даёт TBT 4 мс, при CPU x40 соотношение /users к /cases то же, что в CI, а разброс одного кода 197–1016 мс. Причина красного — шум 5 замеров на 2-ядерной машине. Лечение: 9 замеров, медиана, порог 300 мс не менялся. Настоящая причина роста /users (10.11, отчёты Lighthouse шести коммитов main, TBT×benchmarkIndex/2400): /cases и /audit-log ровно 190–260, /users 272 → 327 (#879) → 366 (#886). С #886 (C-c14) каркас не рисовал закрытую страницу, пока нет `me`, и каждая страница просила свои данные на 60–120 мс ПОСЛЕ ответа /auth/me (до того — на 40–60 мс раньше): лишний круг до сервера на каждом открытии. Лечение: страница монтируется сразу, но невидима, пока нет `me` (мелькания нет, данные проверяет сервер). Проверка: в отчёте запрос данных страницы снова раньше конца /auth/me.

## B. Деплой и прод

25. **main/PR красный 01.11 — «бомбы времени» в unit-тестах:** `groups.sync.spec`, `notifications-api.sync.spec` брали `since = 2026-10-22`, а API отвергает `updatedSince` старше 7 дней; `staff-ai-qa.service.spec` смешивал `NOW=2026-10-27` и реальные часы, ключ бюджета меняется с месяцем. Правило: любой свой «прогон миграций» повторяет `prisma migrate deploy` — один файл = одна транзакция.

126. **Переход на ARM 13.11: фоновый сервер (worker) не запустился — `CannotPullContainerError: image Manifest does not contain descriptor matching platform 'linux/arm64 v8'`.** Доказано описанием задачи: сайдкар антивируса `lawbid-clamav:1.4` в ECR собран только под amd64. Перед переходом проверялись только образы api/admin/pgbouncer, а сайдкар — нет (в DEPLOY_PROD.md шаг 4b «сначала ClamAV» был). Починка: «Mirror ClamAV» → `lawbid-clamav:1.4-debian` (тот же ClamAV 1.4, amd64+arm64); `infra/envs/prod/main.tf` на ARM64 берёт `-debian`. Плюс в том же применении 2 ошибки 403: роль применения не имела `scheduler:UpdateSchedule` (ночные расписания «Авто» базы/Redis — это EventBridge Scheduler, не `events:*`) — добавлено в bootstrap. Правило: перед сменой архитектуры проверить КАЖДЫЙ контейнер КАЖДОЙ задачи (`describe-task-definition … containerDefinitions[].image` → манифест на нужную платформу), включая сайдкары. Полный аудит 13.11 (все Dockerfile, сборки, нативные модули, Lambda, EC2): остальное многоархитектурное; доделано — ClamAV `1.4-debian` на любом процессоре (старый `1.4` уходит по правилу хранения ECR), умолчания `clamav/clamav-debian:1.4` (staging/loadtest), задача миграции на том же процессоре, деплой/откат проверяют arm64-сборку образа ДО смены сервисов (`roll-services.sh` → `arm64-check.sh`).

128. **13.11: я поставил общий потолок загрузок «0», думая, что это «без потолка», — а у счётчиков вызовов 0 = СЕРВИС ВЫКЛЮЧЕН.** Доказано красным PR #985: `perf-user` и `attorney-brief` получили `503 PROVIDER_BUDGET_EXCEEDED` на presign; в `cost-guard.service.ts` `CONSUME_LUA` сравнивает `cur + units > cap` без «0 = нет» (так только у денег, `MONEY_LUA`: `if cap > 0`), а админка пишет «0 = off». На проде с ~08:45 до ~09:25 UTC загрузки были выключены; по журналам API за 90 мин отказов не было (никто не загружал). Починка: на проде и в умолчаниях — наибольшее допустимое значение 10 000 000 (AUTOSCALE_MAX_VALUE). Правило: перед записью «0» в любой лимит прочитать, что 0 значит именно в ЭТОМ счётчике.
127. **13.11: заявка «Дешёвые серверы» висела «Применяется» 3 часа и не давала нажать «Вкл» снова.** Доказано журналом запуска 43377778071: применение само пересоздало сервис API (переход на ARM, KE 119), а шаг «Report the result» попал ровно в это окно — `api.sh: HTTP 503 from status` (балансировщик без живых серверов); три быстрых повтора curl кончились за секунды, админка не узнала об ошибке, заявка осталась `applying` до 3-часовой чистки. Починка: `scripts/infra/api.sh` повторяет 5xx / нет ответа каждые 20 с со свежим токеном — до 15 минут для `status`, до 2 минут для остальных вызовов; 4xx — сразу конец. Проверено на поддельном сервере: 503 шесть раз → успех через 30 с; 404 → сразу выход 1. Правило: любой отчёт из применения облака, которое может перезапустить API, должен переживать перезапуск API.
