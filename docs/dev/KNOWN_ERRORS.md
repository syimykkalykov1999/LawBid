# Журнал известных ошибок (сборка, PR, деплой, прод)

Читать **перед** любой работой в этом репозитории: каждая ошибка здесь уже стоила кругов CI, падения деплоя или простоя.
Правило (владелец, 2026-10-28): каждая НОВАЯ причина красного PR, упавшего деплоя или сбоя прода дописывается сюда в тот же час, до запуска исправления. Номера не переиспользуются.

> **ПРАВИЛО №1 (самое главное, владелец 2026-10-28): не изобретать азбуку, когда есть готовый язык.** Есть проверенное открытое решение — берём его как есть (MIT/Apache/BSD: копируем целиком + строка в THIRD_PARTY_NOTICES; GPL/закрытый код — только идея, код свой). Наш остаётся только внешний вид, его не меняем. Отныне ТОЛЬКО копируем; свой код — только если готового нигде нет И владелец прямо разрешил. Каждый чужой файл — проверка на вирусы и опасные строки. Касается iPhone, Android, сайта, админки, сервера. Подробно: [`AGENTS.md`](../../AGENTS.md).

## A. Перед единственным пушем (почему PR краснели)
Каждый пункт стоил отдельного круга CI (~40 мин). Перед ЕДИНСТВЕННЫМ пушем обязательно:
1. **Mobile analyzer как в CI, по ВСЕМУ приложению:** `cd apps/mobile && flutter analyze` (CI падает даже на `info`, например `require_trailing_commas`). Анализ только изменённых файлов — недостаточно. После правок — `dart format <изменённые файлы>`.
2. **Gitleaks на свой диф:** `gitleaks git --log-opts="origin/main..HEAD" .` (установлен через brew). Фейковые токены/ключи в тестах называть «test-…-token», не случайной строкой вроде `tok-1-abcdefghijklmnop` или `practice.family_law…` в поле `*_key`.
3. **ERD после изменения схемы:** `npm run db:erd --workspace apps/api && git diff --exit-code -- docs/db/ERD.md`.
4. **Новая миграция:** первой строкой `SET LOCAL lock_timeout = '5s';` (squawk require-lock-timeout); проверить `npx squawk-cli@2.70.0 -c .squawk.toml <file>`.
5. **После merge main:** заново `packages/api-contract/generate.sh` (не contract:fast), oasdiff против main, `python3 apps/mobile/tool/ci/hardcoded_check.py`.
6. **Новые e2e в режиме двух баз:** вызов сервиса вне HTTP оборачивать в `shardContext.runForCase(...)`; прогнать `E2E_TWO_DB=all` для своего набора.
7. **Стек PR (B на ветке A):** после слития A сразу `gh pr edit B --base main`, иначе B сольётся в ветку A, а не в main.
8. **Не трогать чужие файлы форматированием:** никогда `dart format` по всему дереву.
9. **Сборки на телефоны:** `flutter build ... --release --flavor prod -t lib/main_prod.dart` (без `-t` приложение смотрит в dev-сервер).
10. **Деплой-проверки читают ответ API в обёртке `{data:…}`:** `/health/ready` → `.data.version`.
11. **Деплой запускается сам только при изменениях в apps/api, apps/admin, packages, package*.json или deploy.yml.** Правка в scripts/deploy/ или infra/ НЕ создаёт новый деплой: после такой правки нужен ручной запуск `gh workflow run deploy.yml --ref main` (кнопка владельцу), а ждущий старый деплой со старыми скриптами — отменить.

## B. Деплой и прод
12. **Сайт 503 с 24.10:** CloudFront function опубликована со старым кодом (`cf.kvs(имя)` вместо ID хранилища). После любого Terraform apply проверять `curl -s -o /dev/null -w "%{http_code}" https://lawbid.dev/` = 200 и `aws cloudfront test-function` на LIVE-стадии.
13. **Terraform apply оборвался на сохранении state:** короткий `aws login` истёк в конце apply → state ушёл в errored.tfstate. Перед apply обновлять вход; при обрыве — `terraform state push errored.tfstate`, а не повторный apply.
14. **SLO-дашборд не создавался:** `flatten()` расплющил строки метрик → CloudWatch 400. Для списков-строк использовать `concat([...]...)`.
15. **Деплой не стартовал:** старый деплой от 24.10 висел «ждёт одобрения» и держал очередь (concurrency). Обычный cancel его не берёт — нужен `gh api -X POST …/runs/<id>/force-cancel`.
16. **Сборка образов не уложилась в 60 мин:** arm64 под эмуляцией QEMU. Собирать каждую архитектуру на родной машине (ubuntu-24.04-arm), склеивать манифестом.
17. **Предпроверка упала: пустой секрет** `lawbid-prod/SEARCH_INDEX_KEY` (Terraform создал секрет без значения). Перед деплоем проверять, что у всех секретов из task definition есть AWSCURRENT; новые секреты из Terraform сразу заполнять.
18. **Smoke «версия none»:** скрипт читал `.version`, а API отвечает `{data:{version}}`.
19. **Пометки отката не было:** SSM `/lawbid-prod/deploy/last_good_tag` отсутствовал. Держать его актуальным после каждого удачного деплоя.
20. **Сборки на телефоны смотрели в dev-сервер:** без `-t lib/main_prod.dart`.
21. **Новое приложение + старый сервер = «Нет соединения»:** генерированные модели требовали новые поля. Приложение должно переживать сервер на версию старше (legacy-shape interceptor, таймауты, без бесконечных повторов).
22. **Mac: полный диск** во время iOS-сборки → всё встало. Перед сборками ≥15 ГБ свободно; кэши Gradle/DerivedData/.next чистить; тяжёлое — на ноуте.
23. **API lint OOM в CI (main красный с 10:09 UTC 28.10):** type-aware eslint по всему API превысил 6 ГБ кучи. Теперь lint идёт двумя процессами (src, затем test/apps/libs). Если снова растёт — делить дальше, а не только поднимать память.
24. **PDF записи о сделке не воспроизводился побайтно (тест красный на main 28.10):** PDFKit вставляет PNG с прозрачностью асинхронно, номера объектов «плавали». Подписи сначала выравниваются на белый фон через sharp. Любой PDF с хешем — без прозрачных PNG.
25. **main/PR красный 01.11 — «бомбы времени» в unit-тестах:** `groups.sync.spec`, `notifications-api.sync.spec` брали `since = 2026-10-22`, а API отвергает `updatedSince` старше 7 дней; `staff-ai-qa.service.spec` смешивал `NOW=2026-10-27` и реальные часы, ключ бюджета меняется с месяцем. Даты в тестах — от `Date.now()` или `jest.useFakeTimers({ now, doNotFake })`.
26. **162 красных прогона API CI за 10 дней:** ветки пушились по 5–9 раз, каждый круг — новая причина (e2e, OpenAPI, ERD, контракт, i18n, gitleaks). Перед пушем — `npm run precheck` / `precheck:full`, список причин — `docs/dev/CI_CHECKLIST.md`.
27. **Gitleaks `sentry-access-token` на `graphify-out/cache/stat-index.json` (#527):** локальный кэш с путями `sentry_*.dart` закоммичен. `graphify-out/` не коммитить.
28. **iOS build check: `Could not resolve host: cdn.cocoapods.org`:** сеть раннера, не код — перезапустить упавший job (`gh run rerun <id> --failed`).
29. **Android release (R8) не собирался: «Missing class ... mlkit.vision.text.chinese/japanese/korean»:** пакет google_mlkit_text_recognition ссылается на необязательные распознаватели. Лечится -dontwarn в android/app/proguard-rules.pro (совет из README пакета). Любой новый плагин с необязательными классами — проверять сборку release на ноутбуке до влива.
30. **«Архив» — серый экран (2026-10-28, Samsung, release):** один и тот же экран был подключён `deferred as` в двух файлах (app_router и chat_routes) с одинаковым id, а `DeferredScreen` помнил «загружено» по id. В Dart отложенная библиотека грузится отдельно для КАЖДОГО префикса → второй маршрут строил экран без своего `loadLibrary()` → `_checkLoaded`. Теперь экран всегда ждёт свой `load()`, а тест `deferred_screen_test.dart` запрещает общий id у разных префиксов.
31. **Экран «сжат» после клавиатуры (2026-10-28, Samsung):** после закрытия поиска телефон продолжал сообщать высоту клавиатуры — все экраны и вкладки оставались в верхней половине. `SystemNavBand` теперь игнорирует нижний отступ клавиатуры, когда ни одно поле не в фокусе (тест `system_nav_band_test.dart`).
32. **Белая вспышка при открытии экрана:** страница, которая в первом кадре ничего не рисует, показывала белое окно Android под приложением. Каждая страница теперь лежит на цвете фона темы (`PageBackground` в переходах).
33. **CI: «Bind for 0.0.0.0:5432 failed: port is already allocated» (2026-11-02):** фиксированные host-порты сервисов (postgres 5432, redis 6379, mailhog 1025/8025, MinIO 9000) в api-ci.yml сталкивались, когда два job шли на одном Docker-хосте (раннеры laptop-N). Лечение (#593): сервисы на случайных портах, `scripts/ci/service-env.sh` и `start-minio.sh` экспортируют DATABASE_URL/REDIS_URL/SMTP_PORT/S3_ENDPOINT. Новый job или workflow НЕ публикует фиксированные порты. Несколько systemd-раннеров на одном хосте тоже нельзя (runbook self-hosted-runner.md).
34. **Job «cancelled» после зелёных тестов (2026-11-02, PR #593 e2e 1/3):** сами тесты прошли, но job убит таймаутом `timeout-minutes: 45`: тесты шли 33 мин (ноут делил ядра с soak), потом «Post setup-node» выгружал кэш npm в GitHub ещё минуты. Признак: отмена ровно через 45 мин после старта, на шаге Post*. Лечение: на self-hosted кэш npm только читается (`.github/actions/npm-cache-restore`, плюс том `~/.npm` у каждого раннера), кэш MinIO остаётся обычным с сохранением при промахе (ключ с архитектурой), таймаут e2e, two-db и n1 — 60 мин (должен покрывать p99, а не медиану). Не OOM: `docker inspect` даёт `OOMKilled=false`.
35. **Deploy упал на «Wait for green CI» при зелёном main (2026-11-03, run 41661806332):** у шага `timeout-minutes: 50`, а полный API CI на push в main идёт дольше. Прогон деплоя гаснет по таймауту, хотя ни одна проверка не красная. Лечение: дождаться зелёного API CI на этом SHA и запустить деплой заново `gh workflow run deploy.yml --ref main` (это не «rerun красного»); системно — поднять таймаут гейта или ждать по статусу коммита, а не по часам.
