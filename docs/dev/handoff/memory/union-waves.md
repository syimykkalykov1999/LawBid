When several helpers work in parallel, land them as ONE union branch per wave (real merge commits, conflicts resolved once, full local audit, one CI, one merge). While a union is pending, new branches start from the union head, not main. Shared registry files (module-boundaries baseline, job stub lists, SWITCH_INVENTORY, two-db suite list, redis allowlist, openapi/Dart) are regenerated by scripts as the last step before commit, never hand-edited; where no generator exists, add one (conflict-proof task). Before any push: merge main (+union), regenerate, audit, one push.

**Why:** 2026-10-27 the owner lost ~8 h to per-PR re-merge cycles (train v3) and then saw 5 staff PRs go DIRTY after one merge; he said «реши вопросы параллельности, потом сливай… в каждом шагу застреваешь».

**How to apply:** default to a union for any wave ≥3 PRs; brief every helper with the union head as base; schedule the conflict-proof generator task early. Related: [[full-local-audit-before-push]], [[stall-watchdog]], [[owner-working-rules]].
