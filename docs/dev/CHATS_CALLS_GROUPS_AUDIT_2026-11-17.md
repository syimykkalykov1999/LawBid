# Проверка чатов, файлов, звонков 1:1 и групп — 17.11

Что проверял: `main` на 552578d97. Код продукта не менял, только читал его и запускал тесты.

Чем доказывал:
- **Проверки по коду.** `docs/dev/verify/chats-calls-groups/code-checks.sh` проверяет каждую находку по строке кода. Запуск: `docs/dev/verify/chats-calls-groups/run.sh code`. Ожидаемый вывод на 552578d97: `итого: ДА=34 НЕТ=0`. «НЕТ» значит, что код уже другой и находку надо проверить заново.
- **Существующие тесты.** Запуск: `run.sh specs`, четыре группы по очереди через `heavy.sh`, по одному процессу. Итоги в разделе «Прогоны».
- **Проба П1** на настоящей PostgreSQL: `docs/dev/verify/chats-calls-groups/order.e2e-spec.ts`. Запуск: `run.sh order`, потом уборка `run.sh cleanup`.
- **Сверка вручную.** Четыре помощника читали код и прислали отчёты. Каждую находку из списка проблем я открыл в коде сам. В двух местах помощники ошиблись, это поправлено ниже: приём файлов через сервер есть, но только в двух админских импортах; индекс `(conversation_id, seq)` есть.
- **Что не сделано.** Живые проверки двумя тестовыми аккаунтами через запущенный API (с сокетами и MinIO) я **не делал**. Их список с точными шагами дан в разделах «Живые проверки на Маке» и «Живые проверки на проде». Где в таблице написано «по коду», это доказано чтением кода и проверкой `code-checks.sh`, а не живым прогоном.

Главное одной строкой:
- Путь данных устроен как у WhatsApp и Instagram: файлы идут с телефона прямо в хранилище, отдаются через CDN, в базе только ключи, тяжёлая обработка идёт в отдельном worker.
- Исключений два: файлы меньше 8 МБ проходят через API при подтверждении загрузки, а превью ссылок жмёт картинку прямо в API.
- Серьёзных дыр нашлось 10:
  - удалённые файлы групп никогда не освобождаются;
  - на жалобы на группы нет кнопки в системе;
  - когда лежит Valkey, сообщения не отправляются;
  - при гонке телефон может потерять сообщение;
  - двойной звонок в состояние «занят»;
  - видео можно протолкнуть в аудиозвонок группы;
  - «печатает…» виден заблокированному;
  - веб-голосовое из Firefox может не играть на iPhone;
  - звонки по умолчанию не только через Cloudflare;
  - раздача сообщений групп ограничена 8 потоками на весь кластер.

## 1. Путь данных (первым, по указанию владельца)

Как делают лидеры (источники с датами):
- **WhatsApp.** Телефон шифрует файл и кладёт его в хранилище сам. Сервер файл не читает и не переделывает. В сообщении идут только ключ, SHA-256 и ссылка (WhatsApp Encryption Overview, версия 2020: https://webcf.waybackmachine.org/web/20201125232437/https://www.whatsapp.com/security/WhatsApp-Security-Whitepaper.pdf; текущая версия #10 от 30.10.2026 по тому же адресу). Одинаковые файлы хранятся одной копией по SHA-256 (arXiv 2411.09228, ноябрь 2024).
- **Размеры у WhatsApp.** Фото обычное 1600 px, HD 4096 px; видео обычное 480p, HD 720p (9to5mac, 24.08.2023 и 18.06.2024).
- **Instagram.** Телефон загружает один файл, а лестницу качеств делает сервер в фоне. Перепаковка без перекодирования сократила вычисления на 94 % (Meta Engineering, 04.11.2022). AV1 включается только для роликов, которые много смотрят (Meta Engineering, 21.02.2023). На iOS для HDR телефон сам сводит ролик в HEVC (Meta Engineering, 17.11.2025).
- **TikTok / Douyin.** Подготовка ролика на телефоне, лестница качеств на сервере. Отдельной статьи TikTok о кодеке на телефоне не нашёл.

## 4. Проблемы по важности

1. **Удалённые «для всех» файлы групп не освобождаются никогда** (F1, F1b). Хранилище течёт, а файл, который человек удалил, остаётся. Исправление: в `groups.remove` то же, что `releaseFile` в 1:1. В чистильщике `AND cgm.deleted_at IS NULL`, у 1:1 `AND m.revoked_at IS NULL`.
2. **Когда лежит Valkey, сообщения не отправляются** (G5). Исправление: `RateLimitService.consumeFixedWindow` при ошибке Valkey пропускает запрос и пишет предупреждение.
3. **На сообщения и группы нельзя пожаловаться, проверки содержимого в группах нет** (G2). Исправление: типы `group` и `group_message`, поиск по `chatGroupMessage`, тот же хук модерации в `send` и `edit`.
4. **Телефон может потерять сообщение.** Тут две причины. Первая: догонялка отдаёт не больше 100 сообщений и молчит, что есть ещё (C1). Вторая, если П1 красная: при гонке порядок по `created_at` расходится с `seq` (C1b). Исправление: догонялка по `seq` с признаком «есть ещё», цикл на телефоне.
5. **Видео можно протолкнуть в групповой аудиозвонок** (G3). Исправление: проверка `call.video` при публикации `cam`.
6. **Двойной звонок в «занят»** (K1). Исправление: замок `call:live:{user}` в Valkey или замок в базе.
7. **«Печатает…» виден тому, кто заблокировал** (C3). Исправление: бит блока при входе в чат.
8. **Звонки по умолчанию не только через Cloudflare** (K3). Исправление: если правило строгое, владелец ставит `calls.transport=cloudflare` и `calls.own_turn.mode=off`.
9. **Раздача сообщений групп: 8 потоков на весь кластер** (G1). Значки публикуются отдельно каждому участнику (G4), пуш читает базу по каждому получателю. Исправление: число частей в админку (64+); один публикационный вызов на сообщение; пачка `findMany` на 500 получателей.
10. **Веб-голосовое из Firefox или Linux может не играть на iPhone** (F3). Исправление: перевод WebM → AAC в worker.
11. **Файлы меньше 8 МБ проходят через API, их копия лежит в Valkey** (D1). Исправление: «лёгкий» путь для всех размеров.
12. **Предел размера голосовых, шаблонов и стикеров без верхней границы.** Файл больше 110 МБ загрузится, но не отправится. Исправление: верхняя граница = `clamav_max_file_mb`, проверить тестом.
13. **Сканер лежал 2 минуты, и все загрузки за это время пропали навсегда.** Исправление: метка «сканер лежал» и повторная проверка.
14. **Уборка звонков внутри ответа на звонок** (K2), нет индекса `(status, updated_at)`. Исправление: уборка только по расписанию, добавить индекс.
15. **Звонящий убил приложение, у собеседника звонит 60 с и пишется «пропущен».** Исправление: отмена после окна переподключения.
16. **Голосовые: ссылка 1 час и нет журнала доступа** (F2, F2b). Исправление: как у вложений.

## 5. Нагрузка (числа из кода)

Владелец просил не проверять сами серверы, они работают. Ниже только то, что упирается в устройство кода:
- **Сообщение группы на 5000 человек.** Одна задача раздачи. Значки — около 15 000 обращений к Valkey (на каждого `nextSeq` + запись в журнал + публикация, `badges.service.ts:244-256`, `realtime-publisher.service.ts:208-231`). Журнал событий — до 1000 записей Lua (`realtime-event-log.ts:126-153`). Пуш — пачки по 500, на каждого получателя 2 запроса к базе (`push-dispatcher.ts:920-946`). Раздача — не больше 8 одновременно на весь кластер (G1). При 30–100 мс на задачу это примерно 80–250 сообщений групп в секунду на всю платформу. Первым упрётся здесь, уже около 10 000 активных людей в группах.
- **Сокеты.** При входе человек попадает в одну комнату `user:{id}` и в комнату открытого чата, без комнаты на каждую группу. Пределы: 400 комнат, 50 открытых чатов и 10 сокетов на человека (`realtime.gateway.ts:95-99`). Адаптер `@socket.io/redis-adapter` 8.3 с разделением по частям.
- **«Печатает…»** идёт только тем, у кого чат открыт, не чаще 1 раза в секунду, без очереди.
- **Присутствие.** Каждое «в сети / не в сети» опрашивает все серверы (`fetchSockets`, `realtime.gateway.ts:870-897`) и пишет `last_active_at` в базу при последнем отключении. После выкатки или сбоя все переподключаются разом и получают такую же волну.
- **Звонки.** Каждый участник раз в 30 с обновляет `updated_at` строки звонка (`calls.service.ts:1153-1158`). 100 000 звонков дают около 6 700 записей в секунду в одну горячую таблицу. Исправление: держать сигнал жизни в Valkey.
- **Ключи Valkey без срока.** `rt:fx:pending` (C4) и `rt:epoch` (намеренно, один ключ). Остальные проверенные ключи со сроком.

## 6. Перемены последних недель: что проверено

- **ARM64 / Graviton** (`growth.auto.tfvars.json:12`). sharp ставит сборку под linux-arm64, ClamAV-образ мультиархитектурный (KE 126), своих родных модулей в чатах и звонках не нашёл. Сломанного по коду нет. Живьём на проде не проверял.
- **Fargate Spot для api, worker, admin и pgbouncer.** Сокеты при остановке задачи уходят мягко (`realtime.gateway.ts:465-473`, `stopTimeout` 60/120 с). Звонок идёт через TURN и обрыв сокета переживает. Загрузки идут в S3 мимо API. Риск — pgbouncer на Spot: прерывание рвёт соединения с базой всех задач сразу.
- **Valkey 9.1 вместо Redis.** Сокеты через разделённые публикации, Lua, BullMQ. Несовместимостей в коде не нашёл. Отдельная дыра не из-за Valkey, а из-за кода: отправка падает, когда Valkey лежит (G5).
- **R2 для публичного.** Личные файлы туда не попадают, это доказано тестом `files.policy.r2.spec.ts`.
- **Cloudflare TURN.** Когда он здоров, политика `relay`. По умолчанию разрешён запасной путь (K3).
- **Новое сжатие AVIF и WebM→AAC.** AVIF делается в worker. WebM→AAC идёт только в браузерах с AAC (F3).
- **NestJS 12, Prisma 7, Node 26, Postgres 18.** Тесты в разделе «Прогоны» идут на этих версиях. Пробу П1 (Prisma 7 и `@default(now())`) см. там же.
