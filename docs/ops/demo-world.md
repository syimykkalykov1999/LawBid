# Демо-мир («Продвижение»): как устроен и что делать, если что-то не так

Владелец, 2026-10-05. Демо-аккаунты нужны блогерам, чтобы записывать видео
о приложении, тыкать, создавать задачи и кейсы — и чтобы это никогда не
попадало к настоящим людям и не занимало место.

## Как это устроено (простыми словами)

* Все демо-данные живут в **отдельной базе** `lawbid_demo` рядом с основной.
  Там нет ни одного настоящего человека. Поэтому демо-кейс физически не
  может появиться в ленте, поиске или уведомлениях настоящих пользователей.
* Приложение, зайдя в демо-аккаунт, ставит метку на каждый запрос
  (`X-LawBid-Demo: 1`), и сервер отвечает из демо-базы. Токен демо-сессии
  тоже помечен; метка и токен должны совпадать, иначе 401.
* В демо-мире **запрещены**: оплаты (Stripe), загрузка видео (Bunny), SMS,
  письма, пуши, платные проверки. Файлы можно загружать в пределах квоты
  (по умолчанию 20 МБ на демо-аккаунт), они лежат в S3 под префиксом `demo/`.
* Демо-база **сама** создаётся при старте API (`CREATE DATABASE IF NOT EXISTS`),
  сама накатывает те же миграции, что и основная, сама копирует справочники
  (штаты, практики, страны, флаги, настройки, планы) и сама наполняется
  вымышленными адвокатами, клиентами, кейсами, чатами, постами.
* **Чистка**: раз в час удаляются демо-аккаунты, которыми не пользовались
  N дней (по умолчанию 7; админка → Деньги → Партнёры → Демо-доступ). Когда
  удалён последний, весь демо-мир очищается и пересоздаётся заново. Кнопка
  «Сбросить демо-мир» делает то же самое вручную.

## Где включать и настраивать

Админка → Деньги → Партнёры → вкладка **«Демо-доступ»**:
главный выключатель, срок жизни аккаунта, сколько аккаунтов у одного
партнёра, автоочистка, квота файлов, текст плашки. Там же список всех
демо-аккаунтов, создание аккаунта для блогера без приложения (выдаётся
8-значный код, показывается один раз) и кнопка сброса.

Право создавать демо-аккаунты из приложения даётся партнёру переключателем
«Демо-доступ» в карточке партнёра. Партнёр видит раздел «Демо-режим» в
Настройки → Партнёрская программа.

## Если во вкладке написано «Демо-база не готова»

1. Причина написана рядом. Чаще всего: у роли приложения в проде нет права
   создавать базы. Тогда один раз выполнить на кластере:
   ```sql
   CREATE DATABASE IF NOT EXISTS lawbid_demo;
   GRANT ALL ON DATABASE lawbid_demo TO lawbid_app;
   ```
   (имя роли — как в `DATABASE_URL`). После перезапуска API всё остальное
   сделает само.
2. Можно задать адрес явно: переменная `DEMO_DATABASE_URL`. Значение `off`
   полностью выключает демо-мир.
3. Локально (Mac) ничего делать не нужно: пользователь `root` из
   docker-compose может создавать базы, так что API создаёт её сама. `npx prisma migrate deploy` для демо-базы
   запускать не надо — API применяет миграции сама и записывает их в
   `_prisma_migrations` демо-базы.

## Для разработчика

* Код: `apps/api/src/common/demo/*` (контекст, middleware, запреты),
  `apps/api/src/prisma/prisma.service.ts` (один PrismaService → две базы),
  `apps/api/src/modules/demo/*` (сервис, сид, админка, крон `demo.sweep`).
* Реестр демо-аккаунтов (`demo_accounts`) лежит в ОСНОВНОЙ базе: кто создал,
  последняя активность, хеш кода входа. Сам демо-пользователь — в демо-базе.
* Публичные справочные маршруты (`/i18n`, `/countries`, `/legal`, `/health`)
  всегда отвечают из основной базы, даже с демо-меткой.
