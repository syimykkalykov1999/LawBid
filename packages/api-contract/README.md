# api-contract

The API contract between apps/api and apps/mobile (docs/01_FOUNDATION_AUTH.md
§6.3). Everything here is **generated — never hand-edit it**; change the API
and regenerate.

```sh
sh packages/api-contract/generate.sh           # needs the dev DB + Redis
SKIP_OPENAPI_EXPORT=1 sh packages/api-contract/generate.sh   # client only
```

- `openapi.json` — exported by `npm run openapi:export --workspace apps/api`
  (`nest build`, boots the app, writes this file). Request schemas come from
  the `@nestjs/swagger` CLI plugin (nest-cli.json); every response is
  documented explicitly:
  - 2xx JSON bodies are named envelopes `XxxEnvelope = {data: XxxDto,
    meta?: {nextCursor}}` (`ApiEnvelopeResponse`,
    apps/api/src/common/dto/api-docs.decorators.ts) — the shape the global
    ResponseInterceptor produces (docs/01 §7);
  - errors are `ErrorResponseDto = {error: {code: ErrorCode, message,
    details?, requestId}}` with the ErrorCode values each status can carry
    listed in the response description (`ApiErrors`);
  - paths are relative to the server URL `/api/v1`; the `/health/*` probes
    override it per operation (they live outside the prefix);
  - operationId = the controller method name (unique — the export fails on a
    duplicate), tag = one per controller.
- `dart/` — package `lawbid_api`: retrofit clients (one per tag, plus the
  `LawbidApi` root) and json_serializable models, generated by
  [swagger_parser](https://pub.dev/packages/swagger_parser) + build_runner
  from `openapi.json` (minus `/health/*`). The toolchain is pinned in
  `dart/pubspec.yaml` + `dart/pubspec.lock`, so regenerating twice yields no
  diff. Unset optional request fields are omitted (never sent as `null`,
  `dart/build.yaml`); enums fall back to `$unknown` for values added later.
  apps/mobile depends on it by path and passes its own configured `Dio`
  (base URL ending in `/api/v1`, interceptors) into the clients.

CI (`.github/workflows/api-ci.yml`, "API contract is up to date") runs
`generate.sh` and fails on any diff, then `dart analyze --fatal-warnings`.
The mobile `ApiErrorCodes` constants are checked against the generated
`ErrorCode` enum by apps/mobile/test/core/network/api_error_codes_test.dart.

Not a 2xx JSON body (documented as such): `GET /admin/i18n/export` returns
the xlsx file itself; `POST /cases` is a stub that only answers 403/501
until docs/04 §3.
